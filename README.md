# FORTIQ — Distributed Desktop (Qt rebuild)

**Fortiq — удалённый Linux-рабочий стол.** Нативное приложение показывает файлы, документы,
почту, браузер и системные инструменты выбранного Linux-сервера, а вся работа происходит на самом
сервере: клиент только рисует интерфейс и по **SSH** запускает существующие проверенные утилиты.
Серверу не нужен графический стол, а на сервер не устанавливается собственный агент Fortiq.

> **Статус на 21 октября 2026: инженерный прототип R0.1.** Прежний прототип на Flutter/Dart удалён
> (последнее состояние — git-тег `flutter-final`). В `main` начат клиент на **C++20 с Qt 6 / QML**:
> каркас CMake и ограниченный срез «Файлы» через SSH/SFTP (только чтение). Это не перенос всего
> прототипа, не опубликованная сборка для Windows/Android и не проверенный по безопасности выпуск.
> Остальные функции ниже — цели, а не готовые возможности. Подробности — [QT_MIGRATION](docs/QT_MIGRATION.md).

## Что есть в R0.1

- Одно приложение Qt Quick Controls (C++20) с общим QML-интерфейсом и SSH/SFTP-адаптером на libssh2
  для Windows и Android; боковая навигация на компьютере и нижняя — на узком экране.
- Поля адреса, порта, пользователя и пароля. Пароль хранится **только в памяти**; локально сохраняются
  лишь хост, порт, пользователь и закреплённые отпечатки ключа.
- Закрепление **SHA-256 отпечатка** ключа хоста: при первом подключении пользователь сверяет отпечаток
  по независимому доверенному каналу и явно закрепляет его до ввода пароля; смена ключа блокируется.
- Реальный листинг каталогов SFTP, переход в каталог и наверх, обновление. Изменений файлов, загрузок
  и локальной подмены нет.
- Работа в фоновом потоке; ответы привязаны к поколению запроса, поэтому поздний результат не
  «оживит» отключённую сессию.
- Тесты проверки удалённых путей (`tests/RemotePathTest.cpp`).

**Не реализовано:** постоянная SSH-сессия, вход по ключу, переподключение и отмена, открытие и
сохранение файлов, передачи, несколько серверов, почта, браузер, системные инструменты, подготовка
сервера, лицензирование, AI. Заявления прежнего README о Flutter-версии к Qt не относятся.

## Принципы (решения владельца)

- **Только SSH.** Единственный рабочий транспорт: SSH exec/PTY, SFTP внутри SSH, перенаправление
  портов и SOCKS. Никакого стриминга окон, собственного серверного агента, прямых SMTP/IMAP, REST и
  других клиентских подключений к рабочим системам. Единственное прямое внешнее подключение
  клиента — покупка и проверка лицензии (Lemon Squeezy).
- **Сервер — единственный источник рабочих данных и настроек.** Клиент хранит только то, что
  нужно для подключения, лицензию и несохранённый ввод в памяти.
- **Готовые Linux-утилиты вместо своих.** Fortiq пишет графический слой и адаптеры, а не новый
  почтовый клиент или файловый движок. Свои серверные CLI и демоны — только отдельным решением.
- **Debian и Ubuntu.** Другие дистрибутивы не поддерживаются.
- **Терминал один** (качественный, в tmux-сессии на сервере).
- **Цвет домена — только метка пользователя.** Он не навязывает политик и ограничений.
- **Без отключения JavaScript** в браузере; весь трафик браузера идёт через SSH SOCKS-прокси сервера.
- **Закрытый исходный код.** Платное приложение; покупатель получает готовую сборку.
- **Подготовка сервера при подключении — явная.** Проверка, обновления и защита (fail2ban, SSH,
  файрвол) идут в окне с живым логом; шаги, способные отрезать доступ, подтверждаются вторым входом
  и откатываются.
- **AI только по желанию** и только как совет по явно выбранному контексту (см. [AI_CLI](docs/AI_CLI.md)).

## Стек

C++20, Qt 6 (целевая 6.12, минимум в CMake — 6.8), CMake 3.21+, libssh2. Открытые вопросы — в
[ARCHITECTURE](docs/ARCHITECTURE.md#открытые-решения): подход к стилю «Windows 13», лицензия Qt
для закрытого продукта, терминальный движок, веб-движок браузера.

## Сборка

- Qt с модулями Quick, Quick Controls, Network, Concurrent (и Test при `BUILD_TESTING=ON`).
- **libssh2** для той же архитектуры и ABI вместе с криптобэкендом (например, OpenSSL).
  Windows: Qt MSVC 2022 x64 (или MinGW) и libssh2 из vcpkg для того же тулчейна.
  Android: Qt for Android, SDK/NDK/JDK и libssh2 для **arm64-v8a** (лучше статическая сборка);
  разрешение `android.permission.INTERNET` регистрируется CMake (Qt 6.9+), итоговый манифест
  проверить перед установкой.

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/kit -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Готовые APK или EXE в репозитории пока не собирались.

## Использование среза R0.1

1. Ввести хост, порт, пользователя и пароль (на сервере должны быть разрешены вход по паролю и SFTP).
2. На новом хосте сверить отпечаток `SHA256:` с известным, например на сервере:
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` (алгоритм ключа может отличаться).
3. Закрепить только после независимой проверки, подключиться и открыть **Файлы**.
4. Отключение стирает пароль из памяти контроллера.

Нативный SSH-клиент — значительная непроверенная поверхность атаки; закрепление при первом входе не
заменяет внешнюю проверку отпечатка.


подтвердить проверкой.
