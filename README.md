# Fortiq

Универсальный удалённый рабочий стол для повседневной работы, бизнеса и
администрирования Linux. Все существующие приложения сохраняются и развиваются
постепенно: рабочие приложения, файлы и хранение, управление системой.

Сейчас интерфейс и встроенные приложения работают локально на Flutter, а данные
Linux и системные операции доступны через SSH. Текст и изображения загружаются
на клиент для редактирования и просмотра; браузер использует SSH-прокси.
Стриминг удалённого экрана и запуск произвольных удалённых GUI-программ пока
не реализованы.

README описывает текущее устройство, запуск и ограничения. Подробный план с
состоянием каждого инструмента, зависимостями и критериями готовности находится
в [матрице развития](docs/DEVELOPMENT_MATRIX.md). Планируемые функции не входят
в список текущих возможностей ниже.

Окна принадлежат «домену»: серверу с цветом, который выбирает сам пользователь
(цвет ничего не значит для программы, это только ваша метка).

> **Статус: прототип.** Основной сценарий работает на Windows. Android, Linux и macOS
> пока не поддерживаются, подробности в разделе [Платформы](#платформы).

## Возможности

| Окно | Что делает | Как работает на сервере |
|---|---|---|
| **Terminal** | Терминал (xterm), восстановление сессии после обрыва при наличии tmux | `tmux`, либо обычный SSH PTY |
| **Files** | Обзор каталогов, создание, удаление, открытие файлов | `ls`, `mkdir`, `rm`, `cat` |
| **Editor** | Правка текста, Ctrl+S, dirty, подтверждение Reload и закрытия | Запись через stdin; атомарная замена, когда доступны файл и каталог |
| **Docs & Notes** | Редактор Markdown с предпросмотром | то же, что Editor |
| **Processes** | Список процессов, завершение | `ps`, `kill` |
| **Services** | Службы systemd: старт, стоп, перезапуск | `systemctl` |
| **System Logs** | Журналы, фильтры | `journalctl`, `/var/log` |
| **Firewall & Ports** | Открытые порты, правила UFW, интерфейсы | `ss`, `ufw`, `ip` |
| **Search Hub** | Поиск файлов по имени и содержимому | `find`, `grep` |
| **Browser** | Веб-браузер с настройками прокси через выбранный сервер | WebView2 и SOCKS5 поверх SSH |
| **Mailbox** | Локальная почта сервера | `/var/mail` |
| **Media Viewer** | Просмотр изображений с сервера | `base64` по SSH |

Дополнительно:

- **Проверка сервера при подключении.** Fortiq сам проверяет, что на сервере есть
  `tmux`, `procps` и `iproute2`, при необходимости устанавливает их и показывает
  состояние в верхней панели (обновления, перезагрузка, нехватка прав).
  Автоматическая установка и обновление этих зависимостей выполняются при наличии
  прав; настройка общесистемных автообновлений управляется отдельно.
- **Системные обновления.** Количество доступных обновлений (в том числе security)
  проверяется всегда. Установка по кнопке, либо автоматически, если включить опцию
  для конкретного сервера.
- **Автопереподключение.** При потере связи рабочий стол остаётся на экране,
  сверху появляется полоса с обратным отсчётом. Терминалы возвращаются к своим
  tmux-сессиям, браузерный туннель поднимается заново.

## Требования

### Клиент (ваш компьютер)

- Windows 10/11 x64.
- [Flutter SDK](https://docs.flutter.dev/get-started/install) с Dart `^3.13.5`.
- Visual Studio 2022 с компонентом «Разработка классических приложений на C++».
- [Microsoft WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)
  (нужен окну Browser; в Windows 11 уже установлен).

### Сервер

- **Debian или Ubuntu.** Другие дистрибутивы не поддерживаются.
- SSH-доступ по ключу или паролю.
- `root` либо пользователь с `sudo` **без пароля** (`sudo -n`). Это нужно для
  установки пакетов, управления службами, UFW и завершения чужих процессов.
  Без этих прав Fortiq работает, но показывает, чего не хватает, и подсказывает команду
  для администратора.
- Необходимые зависимости (`tmux`, `procps`, `iproute2`) Fortiq устанавливает
  при наличии административных прав; без них требуется помощь администратора.

Чтобы включить `sudo` без пароля для пользователя `debian`:

```bash
echo 'debian ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/debian
```

## Запуск

```bash
flutter pub get
flutter run -d windows
```

Сборка релиза:

```bash
flutter build windows
```

Готовый файл: `build\windows\x64\runner\Release\fortiq.exe`.

## Первое подключение

1. Введите адрес сервера, порт, пользователя и выберите цвет домена.
2. Укажите приватный ключ (на Windows Fortiq ищет `id_ed25519` или `id_rsa`
   в `%USERPROFILE%\.ssh`)
   либо пароль.
3. При первом подключении Fortiq покажет отпечаток ключа сервера. Сверьте его,
   если можете, и подтвердите. При ручном подключении изменившийся ключ вызывает
   красное предупреждение и требует явного доверия новому ключу. При автоматическом
   переподключении несовпадение ключа останавливает повторы.
4. Профиль можно сохранить. Пароль не сохраняется никогда.

Ключи с парольной фразой (passphrase) пока не поддерживаются.

## Безопасность

- **Проверка ключа сервера** по принципу «доверие при первом подключении».
  Отпечатки хранятся локально. При автопереподключении изменившийся ключ никогда
  не принимается автоматически.
- **Секреты:** пароль и содержимое приватного ключа не записываются на диск. Они
  держатся в памяти, пока открыта сессия (для автопереподключения); при отключении
  ссылки на параметры соединения освобождаются. Это не гарантирует физического
  обнуления строк в памяти. В профиле сохраняется только путь к ключу.
- **Команды на сервере** составляются с экранированием (`shQuote`), имена файлов
  и поисковые запросы передаются как буквальные аргументы. SSH-сервис проверяет код
  возврата и stderr; часть методов ещё скрывает ошибки чтения за пустыми результатами.
- **Запись файлов.** Для существующего доступного файла в доступном для записи
  каталоге используется временный файл с проверкой размера и атомарной заменой.
  Права копируются, восстановление владельца выполняется по возможности; ACL и
  дополнительные атрибуты не копируются. Новые файлы и файлы в недоступном для
  записи каталоге пишутся на месте. Для существующего файла интерфейс предупреждает
  о неатомарной записи; обрыв такой записи может оставить неполный файл.
- **Браузер.** WebView2 настроен на SOCKS5 поверх проверенного SSH-соединения,
  включая проксирование `localhost`; задан запрет WebRTC UDP вне прокси.
  Прямого соединения как запасного варианта в коде нет. Индикатор «VPS TUNNEL»
  отражает состояние SSH и SOCKS-listener. Проверка маршрута HTTP/DNS, отсутствия
  обхода туннеля и поведения WebRTC входит в интеграционные критерии матрицы;
  наличие настроек само по себе не подтверждает их выполнение во всех сценариях.

Какие данные сохраняются локально (через `shared_preferences`): профили серверов
(имя, адрес, порт, пользователь, путь к ключу, цвет), отпечатки ключей серверов и
настройка автоустановки обновлений.

## Устойчивость к обрывам

- Потеря связи обнаруживается за секунды: каждые 10 с проверяется ответ сервера.
- Повторы идут через 1, 2, 4, 8, 15 и затем каждые 30 с, пока вы не нажмёте
  «Disconnect». Остановка происходит при неверных учётных данных или изменившемся
  ключе сервера.
- Терминал называется `fortiq-N` и живёт в tmux на сервере: после обрыва он
  подключается к той же сессии. **Закрытие окна терминала завершает его сессию,
  а отключение или выход из Fortiq оставляет её работать.** Новый запуск приложения
  снова подключается к `fortiq-1`, `fortiq-2`…
- При закрытии окна с несохранёнными правками и при отключении Fortiq спрашивает
  подтверждение.

## Известные ограничения

- Файлы читаются и пишутся командами оболочки, SFTP пока нет. Большие файлы и
  изображения передаются медленно.
- Вывод `ls`, `ps`, `systemctl`, `ss` разбирается как текст. Необычные имена файлов
  (несколько пробелов подряд) и символические ссылки отображаются неточно, UDP-порты
  не показываются.
- Терминал один: повторное нажатие открывает то же окно.
- Несохранённые правки не переживают закрытие приложения (черновики на диск пока
  не пишутся).
- Раскладка окон не сохраняется между запусками.
- Нет ключей с passphrase и ssh-agent.
- Обычного IMAP/SMTP-клиента, приложения управления дисками, PDF-просмотра и
  медиаплеера пока нет. Они запланированы в матрице; системная почта и просмотр
  изображений сохраняются.
- Рабочий стол пока зависит от активной SSH-сессии. Локальная почта и черновики
  без SSH требуют отделения оболочки от соединения.
- Рекомендуется не открывать приложение дважды на одном компьютере одновременно:
  порт браузерного прокси выбирается один раз на запуск.

## Разработка

```bash
flutter analyze        # статический анализ
flutter test           # модульные тесты
```

Тесты пока покрывают экранирование команд, `sudo`-обёртку, команду tmux и разбор
списка обновлений. Живое SSH-подключение автоматически не проверяется.

При горячей перезагрузке (hot restart) браузер может перестать загружать страницы,
потому что порт туннеля меняется. Перезапустите приложение целиком.

## Развитие

Все текущие приложения остаются частью рабочего стола. Развитие идёт одновременно
по трём направлениям, с небольшими законченными сценариями в каждой поставке:

| Направление | Ближайшие возможности |
|---|---|
| Рабочие приложения | Полноценная IMAP/SMTP-почта с сохранением системного источника, черновики, развитие редактора и Markdown, затем PDF и медиа |
| Файлы и хранение | SFTP и передачи, обзор дисков и анализ занятого места, затем монтирование и операции с разделами |
| Управление системой | Развитие процессов, служб, логов, сети, нескольких терминалов и подготовки сервера |

Общая основа: независимая от SSH оболочка, явное расположение ресурсов, фоновые
задачи, безопасное хранение секретов, уведомления и рабочие пространства.

| Поставка | Основной результат |
|---|---|
| R0 | Общие контракты, черновики и проверка устойчивости существующих приложений |
| R1 | Один полноценный почтовый аккаунт, SFTP-передачи, обзор дисков и сценарий диагностики службы |
| R2 | Несколько аккаунтов/OAuth, PDF, анализ места, поиск с переходом к строке и связи порт → процесс → служба |
| R3 | Уведомления, очередь действий, избранное и корзина, конфликты файлов, монтирование и восстановление рабочего пространства |
| R4 | Экспорт документов, медиаплеер, операции с разделами и расширенная диагностика |

Windows остаётся основной платформой. Android, прежде всего планшеты, развивается
отдельным направлением: разрешение сети, замена Windows-only компонентов и проверка
сенсорных сценариев. Планируемая поддержка не меняет текущий статус платформ.

Полный перечень задач, зависимости и критерии приёмки — в
[матрице развития](docs/DEVELOPMENT_MATRIX.md). Она определяет состав поставок;
README обновляется по мере реализации и проверки. Это этапы готовности, не
календарные обещания.
