# Квалификация платформ

Статус на 24.10.2026 (пункт 6 бэклога [аудита](AUDIT_2026-10-23.md), R5 и R11): **частично**. Выполнен прогон на эмуляторе Android; **чистая Windows и физический Android не проверены** — это проверки владельца, виртуальные машины владельца не запускались и не трогались.

## Что сделано: эмулятор Android

Окружение: AVD `FortiqTablet` (Android 17 / API 37, x86_64 с трансляцией arm64, 2560×1600, GPU хоста), отладочный arm64 APK, собранный из текущего кода (`tool/build_android.py`). Сервер — одноразовый Debian в WSL (`fortiq-test`); эмулятор подключался к нему через `adb reverse tcp:2222 tcp:2222` как к `127.0.0.1:2222`, вход по одноразовому ключу, который лежал в каталоге приложения (`run-as`) и после прогона удалён с сервера и с диска.

| Проверка | Результат |
|---|---|
| Установка, запуск, форма сервера, ввод с экранной клавиатуры (`adb input`) | работает; первый запуск ≈ 30–45 с из-за трансляции arm64 |
| Первое подключение: проверка отпечатка хоста | диалог показан; отпечаток совпал с ECDSA-ключом хоста (сверено с `ssh-keygen -l`); после «Vérifiée» вход по ключу прошёл |
| Рабочий стол, док, панель приложений на реальном сервере | работает |
| **Réseau, Système, Bases, Courrier** (раньше на Android не запускались, R11) | запускаются и показывают данные сервера (интерфейсы, процессы; БД — «нет профилей»; Courrier — честное «notmuch не настроен», фикстура почты была очищена тестами) |
| Поворот планшета в портрет | окна занимают весь экран, появляется меню-«гамбургер», док получает подписи; сессия сохраняется |
| Уход в фон на 30 с и возврат | процесс жив, сессия и окно на месте |
| Обрыв сессии со стороны сервера (убиты все процессы пользователя) | ошибка показана, ручное «Обновить» открывает сессию заново и работает |

Сделано **только** на эмуляторе: касания идут от `adb input`, а не от пальца; IME — стандартная панель эмулятора; нет настоящей смены сети, блокировки экрана, нехватки памяти и SAF-провайдеров.

## Найдено и исправлено

1. **Шрифт `sans-serif` на Android** разрешается Qt в системный Carrois Gothic SC (шрифт с капителью): весь интерфейс выглядел как small caps, а отпечаток хоста при первом подключении нельзя было прочитать однозначно (в base64 регистр значим). Теперь `Theme.fontFamily` на Android — `Roboto`.
2. **Шрифт `"Consolas"`** (33 места: Logs, Terminal-подобные вывод, файлы, БД, Réseau, адреса, отпечаток) на Android не существует, подставлялся случайный шрифт. Введён `Theme.monoFamily` (`Consolas` / `Droid Sans Mono` / `monospace`), все места заменены.
3. **Пустые квадраты вместо иконок** (нет глифа в шрифтах Android): `✎` в «Modifier» и в БД, `☰` в иконке «Journaux», `▾` в чипе сервера. Теперь рисуются через `SymbolGlyph`.

Проверено снимками экрана эмулятора после каждой правки; Windows: CTest 19/19.

## Найдено и пока не исправлено

- **Обрыв связи не виден в интерфейсе:** после потери сессии индикатор сервера остаётся зелёным, старый список процессов остаётся без пометки «устарело», сообщение приходит по-английски (`SSH connection lost.`). Нужна общая модель состояния соединения (индикатор, пометка устаревших данных, повтор при автообновлении) — отдельный срез.
- Окна в стопке **просвечивают друг сквозь друга** (виден текст нижнего окна под верхним) — вопрос читаемости; стекло и прозрачность заданы эталоном владельца, решение за владельцем.
- Экранная клавиатура **не закрывается**, когда форма закрыта, и закрывает док, пока не нажать «назад»; форма «Nouveau serveur» **меняет масштаб** при появлении клавиатуры.
- Смесь языков в сообщениях ядра (английские тексты SSH-слоя в французском интерфейсе).
- Другие символы вне латиницы в QML (`☾ ✈ ⓘ ⋯ ◎ ◐ ✒ ≋ ▲ ✦`) на Android не проверены один за другим.
- На телефонном AVD `StanixPhoneX64` с `-gpu swiftshader_indirect` фон рисовался разорванными треугольниками, а с `-gpu host` экран оставался пустым; на планшетном AVD с GPU хоста всё рисуется. Причина не выяснена (похоже на ограничение графики эмулятора с трансляцией arm64), **не принимать за проверку телефона**.

## Что должен проверить владелец

### Чистая Windows (R5)

Только на машине без Qt, Visual Studio и vcpkg, без запущенных виртуалок владельца в этом сеансе; ничего из FORTIQ не должно быть установлено заранее.

1. Установить свежий установщик (`tool/` собирает по подтверждению владельца) и запустить; приложение стартует без «Qt6Quick.dll was not found» и без запроса стороннего ПО.
2. Первый запуск: окно, обои, док; Предупреждений SmartScreen/подписи записать как есть (сборка не подписана).
3. Сервер: добавить по паролю и по ключу; **сверить отпечаток вручную**; перезапустить приложение — пароль хранится только если выбран «запомнить» (Windows Credential Manager).
4. По одному действию в Fichiers (список, загрузка, скачивание, удаление в корзину), Journaux, Terminal, Réseau, Système, Courrier (если на сервере настроен notmuch), Bases.
5. Закрыть окно/выйти при идущей загрузке — должен появиться диалог.
6. Удаление программы: убедиться, что на диске не остались ключи и пароли.

Результат записывать по пунктам: «работает / не работает / не проверялось», с текстом ошибки.

### Физический Android (R5, R11)

1. Установить APK (отладочный; не из магазина), включить установку из неизвестных источников только на время.
2. Касания пальцем: перетаскивание окон, прокрутка длинных списков, долгое нажатие, жест «назад» с формой/редактором.
3. Ввод: IME на русском, французском, английском; автозамена и подсказки в полях адреса/пользователя/пароля; Ctrl-подобные сочетания с Bluetooth-клавиатурой.
4. Поворот, режим разделённого экрана, свёрнутое приложение на несколько минут и на час, возврат, блокировка экрана.
5. **Потеря сети:** выключить Wi-Fi/мобильные данные во время листинга, загрузки и Terminal; включить обратно; проверить, что ничего не помечено «готово», если оно оборвалось.
6. Файлы: выбор через системный диалог (SAF) из Загрузок и из облачного провайдера; загрузка с сервера в выбранную папку; отказ в доступе.
7. Ключ SSH: импорт через «Parcourir», ключ с парольной фразой, Android Keystore после переустановки.
8. Нагрузка: открыть Système с автообновлением 5 с на 10 минут (батарея, нагрев), закрыть, проверить, что обновление остановилось.

Результат — таблица «пункт / устройство и версия Android / итог / замечания».
