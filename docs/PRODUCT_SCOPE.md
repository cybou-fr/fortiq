# FORTIQ: назначение и границы продукта

Статус: продуктовая спецификация, 18 октября 2026. Прототип на Flutter удалён (тег `flutter-final`);
клиент заново разрабатывается на C++/Qt. На 21 октября есть только прототип R0.1 — просмотр файлов по
SFTP только для чтения (см. [QT_MIGRATION](QT_MIGRATION.md)). Всё ниже — цель, а не наличие.
Связанные документы: [README](../README.md), [SSH_FRONTEND_CONTRACT](SSH_FRONTEND_CONTRACT.md),
[ARCHITECTURE](ARCHITECTURE.md), [DEVELOPMENT_MATRIX](DEVELOPMENT_MATRIX.md),
[UI SPEC v1](UI_SPEC_V1.md), [Smart Files](SMART_FILES_SPEC.md), [Logs](LOGS_INTELLIGENCE_SPEC.md).

## 1. Идея

**FORTIQ — исключительно графический клиент к Linux-серверу.** Сервер — единственный вычислитель и
источник рабочих данных, настроек и конфигурации. Клиент рисует интерфейс и по **SSH** запускает
зрелые Linux-утилиты. Своих серверных программ по умолчанию нет.

Пользователь всегда видит, где находится файл, к какому серверу относится служба, через какой
аккаунт уходит письмо и продолжает ли выполняться задача. Один рабочий стол объединяет контексты, не
смешивая права и данные разных серверов.

Без SSH доступны только подключение, лицензия и несохранённый текст в памяти; локального backend и
постоянного локального хранилища рабочих данных не создаётся. Покупка и проверка лицензии (Lemon
Squeezy) — отдельный служебный канал, а не транспорт работы с серверами.

**В будущем (не обещание):** шифрование серверных данных и настроек в покое. SSH защищает передачу,
но не диск. Замена SSH другим транспортом не планируется.

## 2. Приоритет: универсальный удалённый рабочий стол

Аудитория широкая, не только DevOps и администраторы: человек работает с файлами, документами,
почтой и браузером своего Linux-компьютера через SSH; отсутствие графического стола на сервере —
преимущество архитектуры. Порядок развития:

1. **Desktop Shell строго по скетчу владельца:** все положения, материалы, прозрачность, светлое окно Files, rail, launcher, правый control center и dock по [UI SPEC v1](UI_SPEC_V1.md). Эскиз — **обязательный эталон**, не источник вдохновения.
2. **Smart Files — первый flagship:** поиск, умные коллекции, превью, версия и конфликты, безопасные передачи и операции. [Спецификация](SMART_FILES_SPEC.md).
3. **Logs — второй flagship:** journald, журналы приложений и служб, live tail, фильтры, группировка повторов, временные связи и доказательные сводки **без обязательного AI**. [Спецификация](LOGS_INTELLIGENCE_SPEC.md).
4. **Terminal / Services / System Overview:** поддерживающие интеграции Linux/SSH для повседневного desktop и Logs; не DevOps dashboard.
5. **Editor / Documents:** diff, редактор, Markdown/PDF и серверные документы.
6. **Mail:** аккаунты и отправка исключительно через серверные консольные программы.
7. **Browser / Media:** после доказанного SSH-only маршрута одновременно на Windows и Android.
8. **AI только по желанию:** советник на Linux позднее; Files/Logs работают без него.

Docker/Podman и расширенная DevOps-диагностика не приоритет.

## 3. Набор приложений

Все приложения входят в одну лицензию. Новое приложение появляется, только если сценарий нельзя
удобно реализовать расширением существующих и общих сервисов.

| Категория | Приложения | Назначение |
|---|---|---|
| Workspace | **Smart Files** (flagship), Editor, Docs (Markdown), Mail, Browser, Viewer | рабочие данные сервера через SSH, умная навигация и операции |
| System | **Logs** (flagship), Terminal, Processes, Services, Network, Disks | понятный анализ Linux-событий и управление системой |
| Tools | Search, Tasks (и передачи), Connections | общие функции |
| Platform | Sessions, Security, Notifications, App Registry | общая инфраструктура |

Правила:

- У каждого инструмента есть конкретный существующий Linux-исполнитель, проверка его версии и прав;
  при отсутствии пакета его установка возможна **только с отдельного согласия через SSH**. Новые `fortiq-*` команды и клиентский запасной путь
  запрещены без отдельного решения.
- **Терминал один**: высококачественный, в tmux-сессии на сервере.
- Search, Transfers и Tasks — общие функции, а не очереди внутри каждого приложения.
- Editor и Docs — разные интерфейсы с общими ресурсами, сохранением, проверкой конфликтов и
  черновиками.
- Почта — только существующий консольный клиент на сервере (аккаунты, IMAP/SMTP — на сервере);
  клиент Fortiq не реализует почтовых протоколов.
- Браузер рисуется локально, но весь трафик идёт через SSH SOCKS выбранного сервера; JavaScript не
  отключается.
- `serverId` обязателен для каждого рабочего ресурса; запущенная операция не переносится на другой
  сервер при смене активного.
- **Server Setup** — часть подключения, а не приложение: проверка, обновления, защита сервера на
  виду, с откатом (см. [ARCHITECTURE](ARCHITECTURE.md#8-безопасность-операций)).
- Цвет домена — метка пользователя, не политика.

## 4. Главные сценарии

| Сценарий | Ценность |
|---|---|
| Файл/конфигурация: найти → открыть → diff → сохранить на сервере → проверить | работа с документами и настройками |
| Диагностика службы: Services → журнал → конфигурация → проверка → restart → проверка статуса | восстановить сервис |
| Smart Files: каталог → поиск → превью → безопасный перенос с подтверждением | работа с Linux-файлами как с локальными при сохранении удалённого источника |
| Logs: выбрать службу → читать события → сгруппировать → сводка с источниками | понять проблему без AI и неподтверждённых «корневых причин» |
| Почта: письмо → вложение → просмотр → в Files | деловая переписка через серверный клиент |
| Первое подключение: SSH → видимая подготовка сервера → понятное состояние → переход в Files/Services | первые минуты (цель исследования UX — 3 минуты, не обещание) |

Это цели, а не отчёт о приёмке. Нельзя ради скорости обходить проверки, отмену, второй вход или откат.

## 5. Необязательный AI-помощник

Команда `ai` над готовым **llama.cpp** на CPU Linux, запуск только по запросу; клиентская модель,
облачный API и демон не используются. Ставится только с согласия после проверки CPU/RAM; на слабых
VPS отключён. Возможен серверный кеш точных «вопрос + контекст + модель → ответ» с TTL и меткой
«из кеша»; чувствительные данные не сохраняются без согласия. AI объясняет и советует, ничего не
исполняет. Полный контракт и статус — [AI_CLI](AI_CLI.md). Не рекламировать как готовое.

## 6. Не цели

Собственный офисный пакет, полноценный видеоплеер, форматирование дисков, произвольные удалённые
GUI-программы, новые серверные API, командная работа и централизованный аудит (нужна отдельная
модель доступа). Containers, Jobs (cron/systemd timers) и Backup — кандидаты на поздний этап.

## 7. Коммерческая модель

Единая лицензия на все приложения, продаётся через Lemon Squeezy; покупатель выбирает срок.

| Тариф | Цена | Доступ |
|---|---|---|
| **Intro** | 2 € разово | 14 суток с подтверждённой оплаты, один раз на покупателя, без автопродления |
| **Pro** | 39,90 € в год | оплаченный год, продление до отмены; после отмены доступ до конца срока |

Intro не превращается в подписку Pro. Условие «один Intro на покупателя» требует отдельной проверки
механизма повторной покупки. Цены показываются окончательными с налогом (tax-inclusive). Промокоды —
только для Pro, как разовые акции Lemon Squeezy (по умолчанию скидка на первый платёж); Intro в
акциях не участвует; своего сервиса промокодов нет. Лицензирование доступно без SSH. Исходный код
покупателям не передаётся.

Ориентир первого выпуска: проверка покупок в тестовом режиме Lemon Squeezy, выдача и проверка
ключей, безопасное хранение, работающий пакет Windows, испытания подготовки сервера. Контракт —
[LICENSING](LICENSING.md), настройка — [LICENSING_SETUP](LICENSING_SETUP.md).
