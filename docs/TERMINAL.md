# Terminal — первый PTY-срез, 22.10.2026

Приоритет владельца: сейчас Terminal и единое поведение окон; затем Disks, MDok
(.md/PDF) и Mail. Последние три приложения этим срезом **не реализованы**.

## Реализовано

- «Terminal» автоматически открывает shell на выбранном подключённом сервере. Без SSH
  показана кнопка выбора сервера, как в Files; после подключения открытое окно запускает PTY.
  После ошибки/ручной остановки нет бесконечного auto-retry: новая сессия — кнопкой или
  повторным открытием окна. Уже работающий скрытый shell переиспользуется. Используется
  существующий login shell через SSH PTY, `TERM=xterm-256color`; без установки серверных программ.
- Отдельное соединение libssh2 проверяет закреплённый отпечаток **до** аутентификации.
  Данные доступа берутся из RAM RemoteController, не из QML/аргументов процесса.
  Текущий адаптер при открытии требует доступный SFTP, как остальные приложения FORTIQ.
- PTY сохраняет каталог/переменные; ввод, Ctrl+C/D, стрелки, F-клавиши и размер передаются
  серверу. Чтение неблокирующее, до 64 КиБ за цикл; канал принадлежит одному постоянному
  worker-потоку без event loop, не GUI. Очереди ввода ограничены.
- **libvterm 0.3.3 / MIT** разбирает VT/ANSI, UTF-8, цвета и альтернативный экран.
  Qt рисует сетку. Upstream закреплён в [README.fortiq](../third_party/libvterm/README.fortiq.md).
  Собственный ANSI-парсер не написан. Лицензия включена в ресурсы и Windows packaging.
- Экран и ввод только в RAM: нет перехвата/журнала ввода или автоматического повтора команд,
  выполнения ссылок или переноса OSC52 в локальный clipboard. Копирование экрана — явное
  действие; вставка подтверждается, поскольку переводы строк могут выполнять команды;
  одна вставка ограничена 16 КиБ.
- Закрытие окна скрывает shell; отдельная кнопка «Arrêter» убрана. Смена/отключение сервера
  закрывает PTY и очищает экран/историю. Поколение запроса отбрасывает старый вывод.
  Открытое окно запускает новую сессию после выбора подключённого сервера, без повтора ввода.
- Окно использует обычный sidebar/toolbar/status layout. Слева — компактный снимок сохранённых
  строк `~/.bash_history`, до 200 последних строк / 64 КиБ, новые сверху. Чтение выполняет
  существующий `tail` через SSH до открытия PTY. Временные метки Bash скрываются, управляющие
  символы удаляются; строки отображаются как PlainText, не исполняются кликом и не сохраняются
  локально. Клик вводит строку в текущую позицию без Enter и возвращает фокус терминалу;
  табуляции заменяются пробелами. Ввод из истории отклоняет управляющие символы и переводы строк.
  Активный курсор — мигающий заполненный блок, неактивный — контур; скрытие курсора
  сервером учитывается. Нижние кнопки Ctrl+C/D убраны; сочетания клавиатуры работают. Смена сервера очищает их. Отсутствие/права/лимит показаны как недоступность.
  На узком экране sidebar открывается кнопкой меню; ввод терминала не сужается постоянно.
  Это стандартный файл Bash, не живая история текущей сессии и не поддержка custom HISTFILE
  или других shell. Bash обычно сохраняет историю при выходе: [GNU manual](https://www.gnu.org/software/bash/manual/html_node/Bash-History-Facilities.html).
- WindowDragArea общий для Files, Logs, Browser и Terminal: одинаковые границы и быстрый
  press/release, фиксированные окна в adaptive-режиме. Пустой список Logs больше не
  забирает жест как scroll. Активация остаётся общей в DesktopShell.

## Буфер вывода

- До **1000 строк** основного экрана хранятся в RAM через scrollback callbacks libvterm;
  самые старые строки вытесняются. Это вывод текущего PTY, отдельно от истории Bash.
- Колесо/трекпад, Shift+PageUp/PageDown и вертикальная полоса прокрутки показывают предыдущие
  строки. Полоса имеет увеличенную ширину в adaptive-режиме. Shift+End возвращает вниз.
- Новый вывод сохраняет позицию чтения, пока строка не вытеснена лимитом. Ввод/вставка
  возвращают к текущему экрану. Курсор скрыт при просмотре прошлых строк; «Copier» копирует
  видимый фрагмент. Никакой записи на диск или повторной отправки вывода в shell.
- Альтернативный экран (например, TUI) не смешивается с буфером: локальная прокрутка там
  отключена, Shift+PageUp/PageDown передаются программе. Mouse reporting TUI пока не реализован.
- Resize использует push/pop callbacks libvterm. Строки сохраняют исходную ширину; отдельный
  reflow старых строк не реализован. Reset/смена сервера и серверный ESC[3J очищают буфер.

## Выделение и копирование

- Протягивание левой кнопкой выделяет ячейки видимого экрана в обоих направлениях,
  включая несколько строк и буфер прокрутки. Выделенный фрагмент подсвечен.
- «Copier» и Ctrl+Shift+C копируют выделение; без выделения — видимый экран. Обычный Ctrl+C
  остаётся прерыванием команды. Само выделение не отправляет байты серверу.
- Unicode/комбинируемые знаки и широкие символы копируются целиком; скрытые атрибутом
  VT conceal ячейки копируются пробелами. ANSI-коды в clipboard не попадают.
- Новый вывод, ввод, прокрутка, resize и reset снимают выделение. Это привязка к текущим
  видимым ячейкам, а не сохранённая цитата. Click без drag снимает выделение и даёт фокус.
- Переносы между визуальными строками сохраняются как newline: объединение soft-wrap,
  автопрокрутка за край, выбор слов двойным кликом и Android touch handles ещё не реализованы.

## Поиск по выводу

- Кнопка ⌕ или Ctrl+Shift+F открывает локальное поле поиска. Ctrl+F остаётся клавишей shell.
  Ввод запроса не отправляется по SSH. Enter/↓ — следующее совпадение, Shift+Enter/↑ — предыдущее;
  переход циклический, Esc/× закрывает поле и возвращает фокус терминалу.
- Поиск буквальный, без учёта регистра, по визуальным строкам текущего экрана и до 1000 строк
  RAM-буфера. Запрос до 256 символов, до 1000 совпадений; достижение лимита помечено «+».
  Межстрочный поиск, regex, объединение soft-wrap и нормализация Unicode не реализованы.
- Найденный фрагмент прокручивается в видимую область и выделяется для копирования.
  ANSI/VT conceal не ищутся как скрытый текст. В альтернативном экране ищется только его вывод.
- Новый вывод/resize сбрасывают результаты и предлагают повторить поиск. Автосканирования
  бесконечного потока нет; последующее нажатие стрелки/Enter ищет актуальное содержимое.
  Reset/смена сервера очищают запрос и результаты. Запросы не сохраняются на диск.

## Проверки и ограничения

Windows MSVC и Android arm64 debug собраны. Layout QtTest **37 passed**: Terminal на пяти
размерах, ANSI/альтернативный экран/Ctrl+C и общий drag Logs. Изолированный WSL Debian:
PTY, сохранение `/tmp` и Unicode-переменной, resize `120×35`, прерывание `sleep` через Ctrl+C,
код `exit 7`; тест контроллера проверяет вывод, закрытие/очистку при disconnect и отсутствие
отправки позднего ввода. **4 passed** с init/cleanup, без skipped. Отпечаток согласованного
ECDSA host key проверен непосредственно на стенде, проверка pin не отключалась.
Автозапуск после SSH, переиспользование/повторное открытие окна и подавление рестарта после
ручного stop проверены живым тестом. Снимок истории действительно прочитан на Bash-стенде.
Отдельный TerminalHistory QtTest: **4 passed** (с init/cleanup), timestamp/Unicode/PlainText,
управляющие символы и лимиты. UI проверяет кнопку подключения и адаптивный sidebar.
Общий CTest Windows: **8/8**; SSH integration и publication в общем запуске пропускают
живые сценарии без fixture-переменных. Приведённые выше PTY-проверки запущены отдельно с fixture.

Ещё не квалифицированы Android touch/IME и физический планшет, все полноэкранные TUI,
длительные потоки, touch-выделение, настройки шрифта и accessibility сетки.
Копируется выделенный фрагмент либо видимый экран. Это первый рабочий PTY, не полное соответствие xterm.
Команды вводит пользователь; AI не участвует.

  требуют отдельной реализации и проверки инструментов.
