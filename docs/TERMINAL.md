# Terminal — первый PTY-срез, 22.10.2026

Приоритет владельца: сейчас Terminal и единое поведение окон; затем Disks, MDok
(.md/PDF) и Mail. Последние три приложения этим срезом **не реализованы**.

## Реализовано

- «Terminal» на панели приложений → «Ouvrir» после подключения Linux. Используется
  существующий login shell через SSH PTY, `TERM=xterm-256color`; без установки серверных программ.
- Отдельное соединение libssh2 проверяет закреплённый отпечаток **до** аутентификации.
  Данные доступа берутся из RAM RemoteController, не из QML/аргументов процесса.
  Текущий адаптер при открытии требует доступный SFTP, как остальные приложения FORTIQ.
- PTY сохраняет каталог/переменные; ввод, Ctrl+C/D, стрелки, F-клавиши и размер передаются
  серверу. Чтение неблокирующее, до 64 КиБ за цикл; канал принадлежит одному постоянному
  worker-потоку без event loop, не GUI. Очереди ввода ограничены.
- **libvterm 0.3.3 / MIT** разбирает VT/ANSI, UTF-8, цвета и альтернативный экран.
  Qt рисует сетку. Upstream закреплён в [README.fortiq](../third_party/libvterm/README.fortiq.md).
  Собственный ANSI-парсер не написан. Лицензия включена в ресурсы и Windows packaging.
- Экран и ввод только в RAM: нет журнала команд, автоматического запуска/повтора,
  выполнения ссылок или переноса OSC52 в локальный clipboard. Копирование экрана — явное
  действие; вставка подтверждается, поскольку переводы строк могут выполнять команды;
  одна вставка ограничена 16 КиБ.
- Закрытие окна скрывает shell; «Arrêter» закрывает соединение. Смена/отключение сервера
  закрывает PTY и очищает экран. Поколение запроса отбрасывает старый вывод. Повторное
  открытие — явное действие, без автоматического восстановления/повтора ввода.
- WindowDragArea общий для Files, Logs, Browser и Terminal: одинаковые границы и быстрый
  press/release, фиксированные окна в adaptive-режиме. Пустой список Logs больше не
  забирает жест как scroll. Активация остаётся общей в DesktopShell.

## Проверки и ограничения

Windows MSVC и Android arm64 debug собраны. Layout QtTest **37 passed**: Terminal на пяти
размерах, ANSI/альтернативный экран/Ctrl+C и общий drag Logs. Изолированный WSL Debian:
PTY, сохранение `/tmp` и Unicode-переменной, resize `120×35`, прерывание `sleep` через Ctrl+C,
код `exit 7`; тест контроллера проверяет вывод, закрытие/очистку при disconnect и отсутствие
отправки позднего ввода. **4 passed** с init/cleanup, без skipped. Отпечаток согласованного
ECDSA host key проверен непосредственно на стенде, проверка pin не отключалась.
Общий CTest Windows: **7/7**; SSH integration и publication в общем запуске пропускают
живые сценарии без fixture-переменных. Приведённые выше PTY-проверки запущены отдельно с fixture.

Ещё не квалифицированы Android touch/IME и физический планшет, все полноэкранные TUI,
длительные потоки, поиск/выделение, scrollback, настройки шрифта и accessibility сетки.
Пока копируется только видимый экран. Это первый рабочий PTY, не полное соответствие xterm.
Команды вводит пользователь; AI не участвует.

## Следующие приложения

- Disks: проверить `lsblk`/`findmnt`/`df`, JSON/locale/права на Debian/Ubuntu; первый сценарий —
  обзор и свободное место. Деструктивные операции не подразумеваются.
- MDok: серверные `.md`, редактирование поверх Files; Markdown и PDF-просмотр/экспорт
  требуют отдельной реализации и проверки инструментов.
- Mail: проверить и выбрать существующий серверный mail CLI; аккаунты и IMAP/SMTP на Linux,
  FORTIQ работает только по SSH. Утилита пока не выбрана.
