# Réseau — первый срез (23.10.2026)

Приложение только для чтения: показывает сетевое состояние выбранного Linux-сервера и запускает три диагностики
**на сервере**. Ничего не меняет (ни интерфейсы, ни маршруты, ни файрвол).

## Что показывает

- **Interfaces:** имя, состояние, MTU, MAC, адреса IPv4/IPv6 с областью действия, счётчики RX/TX, ошибки и потерянные пакеты (`ip -j addr`, `ip -j -s link`).
- **Ports en écoute:** TCP/UDP, адрес, порт, процесс и pid (`ss -H -tulpn`). Для каждого порта указано, **кто может подключиться**:
  «toutes les interfaces» (`0.0.0.0`, `::`, `*`), «local seulement» (`127.x`, `::1`) или «une adresse». Число портов «на всех интерфейсах»
  выводится на пункте меню: быстрый взгляд на поверхность атаки.
- **Routes:** IPv4 и IPv6, маршрут по умолчанию выделен (`ip -j route`, `ip -6 -j route`).
- **DNS:** серверы и домены поиска из `/etc/resolv.conf`, примечание об источнике (WSL, systemd-resolved, NetworkManager), вывод `resolvectl status`, если есть.
- **Diagnostic:** «Résoudre (DNS)» (`getent ahosts`, `dig`, если установлен), «Ping ×4» (`ping -c 4 -W 2`), «Chemin» (`mtr -rwn`, иначе `tracepath`).
  Каждая диагностика — отменяемая задача общего [TaskManager](ARCHITECTURE.md) (`networkProbe`).

## Правила и ограничения

- Транспорт — SSH, скрипты POSIX `sh` на stdin (`sh -s`); существующие утилиты, никаких серверных агентов.
- Цель диагностики проверяется до отправки: имя хоста или IP-литерал (буквы, цифры, точки, дефисы, двоеточия для IPv6), без пробелов, без ведущего
  дефиса, без символов оболочки; иначе показывается объяснение и ничего не отправляется. Цель вставляется в скрипт как проверенные данные в кавычках.
- Имена процессов видны только для процессов вашего пользователя (или при root); окно это сообщает, а не прячет.
- `ip -j` требует iproute2 с JSON (4.14+); без него окно показывает явную ошибку, а не пустой список. `ss` отсутствует — примечание, остальное работает.
- Выход ограничен (снимок 1 Мио, диагностика 64 Кио), отдельная SSH-сессия для диагностики, привязка к поколению сессии: смена сервера очищает окно.
- Диагностика идёт **от сервера**: ping/DNS показывают его положение в сети, а не положение этого устройства.
- Нет: изменения сети, захвата пакетов, сканера портов (`nmap`), правил файрвола — это отдельные срезы после согласия владельца
  ([ARCHITECTURE](ARCHITECTURE.md) §8: изменения только с согласием и откатом).

## Реализация и проверки

`src/network/NetworkInfo` (скрипты и разбор), `src/network/NetworkController`, `qml/shell/NetworkWindow.qml`.

- `fortiq_network` (14 тестов): настоящие выводы тестового Debian (`tests/fixtures/network/`), особые строки `ss` (`127.0.0.53%lo`, `[::]`, `*`, несколько процессов,
  мусор), `resolv.conf`, разбор снимка и его отказы, скрипт без команд изменения, проверка целей диагностики (инъекции, `-oProxyCommand`, `fe80::1%eth0`, 300 символов).
- Живой тест `networkAppReadsTheServer` на тестовом Debian 13: интерфейсы, маршрут по умолчанию, порт sshd как «на всех интерфейсах», DNS, резолвинг, ping, отмена
  долгого ping по 203.0.113.1, задачи, очистка при смене сессии.
- Layout-тест с подставным контроллером: разделы, количество строк, запуск диагностики, вывод.

Не проверено: Android на устройстве, серверы со старым iproute2, IPv6-only серверы, интерфейсы с десятками адресов (контейнеры) под нагрузкой.
