# FORTIQ: архитектура и общие контракты

Статус: целевой технический контракт, 11 октября 2026 года. Имена ниже задают
обязанности и инварианты, а не объявляют готовые Dart-классы. Текущее состояние
описано в [README](../README.md) и §2 [матрицы](DEVELOPMENT_MATRIX.md).
Назначение компонентов — в [PRODUCT_SCOPE](PRODUCT_SCOPE.md).
**Приоритетный обязательный контракт: [SSH_FRONTEND_CONTRACT](SSH_FRONTEND_CONTRACT.md).**
Любая архитектурная интерпретация ниже допустима лишь в его пределах.

## 1. Текущая основа и направление изменений

Обязательный принцип: сначала использовать зрелые Linux-инструменты, затем
строить интерфейс и адаптеры FORTIQ. Не писать собственные серверные аналоги
готовых клиентов, утилит, агентов и демонов без предварительного обоснования.
Выбор инструмента подтверждается проверкой CLI, версии, выходных данных и ошибок.
Встроенные приложения обращаются к выбранному серверу по SSH; прямое внешнее
подключение клиента ограничено покупкой и лицензированием FORTIQ.
Почтовый аккаунт обслуживает существующий консольный клиент на сервере: IMAP/SMTP,
аутентификация и синхронизация выполняются там; GUI получает результат по SSH.

Сейчас `lib/main.dart` управляет подключением; `widgets/desktop_workspace.dart`
создаёт внутренние окна и зависит от `SshClientService`. SSH-сервис отвечает
за транспорт, проверку ключа сервера, reconnect, PTY и SOCKS, предоставляя
`RemoteShell` из `services/shell.dart`. Поверх него уже выделены `FileService`,
`TerminalService`, `SystemService`, `NetworkService`, `MailService`.
`ServerSetupService` выполняет подготовку и обновления; профили и host keys
сохраняются отдельно. `PrivateKeyStore` сохраняет импортированные ключи
без дополнительного шифрования и не заменяет целевой CredentialStore.

Развивать эту основу следует по конкретным сценариям. Не требуется переписывать
все виджеты, переименовывать классы или менять технологии хранения одновременно.

**Архитектура (обязательно):**

```text
FORTIQ Flutter UI (окна, App Registry, ActionRouter, TaskManager)
        │
        ├── SessionManager → SSH (exec / shell / PTY / SFTP / forwarding)
        │                            │
        │                     Linux CLI executor
        │                            ├─ standard commands / distro packages
        │                            └─ custom fortiq-* CLI tools (when needed)
        │                                  └─ Linux files, mail, services, network
        │
        └── UI-only local state (profiles, secure secrets, temporary drafts)
             + separate Lemon Squeezy license control plane (HTTPS)
```

**Без серверного CLI-исполнителя нет рабочей функции.** Всё, что читает,
изменяет, ищет, отправляет или скачивает рабочие данные, выполняется сервером.
Ни Flutter, ни виджеты не создают прямые соединения IMAP/SMTP/HTTP/FTP
для рабочих инструментов. Локальная оболочка может существовать без SSH
для выбора сервера и управления лицензией, но рабочие действия недоступны.
Разрыв одной SSH-сессии не отменяет другую SSH-сессию; каждое окно знает
свой serverId. Адаптеры не обращаются напрямую к чужим виджетам.

## 2. ResourceLocation и ResourceService

`ResourceLocation` **рабочего ресурса** содержит `serverId`, `sourceId`,
путь/идентификатор, тип содержимого, версию и допустимые действия.
`kind: server` — обычные ресурсы Linux; `kind: account` — объект,
которым управляет **CLI на этом же Linux-сервере** (дополнительно содержит
mailbox/account/folder/message ID). `kind: local` допустим **только**
для UI-состояния, SSH-профиля, временного черновика и лицензии, но не для
самостоятельного обработчика рабочих файлов или Mail.
Один путь или идентификатор письма не является глобальным ключом.

`ResourceService` направляет рабочие операции только в **SSH SessionManager
и серверный CLI-адаптер** выбранного host, включая server-bound accounts.
Каждая операция получает явный `serverId`, источник, версию ресурса,
определённую CLI-команду и обнаруженную capability. Прямой клиентский
сетевой адаптер запрещён. Ответ содержит данные либо типизированную ошибку: нет доступа, отсутствует,
источник недоступен, конфликт, операция не поддерживается. Ошибка не превращается
в пустой успешный результат. Возможности — read/write/list/transfer и другие
конкретные действия — определяются источником и актуальными правами.

При сохранении проверяется версия ресурса; конфликт требует выбора пользователя.
Атомарная запись используется при поддержке адаптера; иначе до записи видны риск
и способ восстановления. Передача связывает два ResourceLocation и имеет задачу;
нельзя подменить destination при смене активного сервера.

## 2a. Обязательный серверный CLI-контракт каждого приложения

Каждому APP соответствует конкретная Linux-команда (системная, пакетная или
разрабатываемая `fortiq-*`), список возможностей, необходимая версия,
права, способ установки и тест. Матрица всех APP-01…14 находится в
[SSH_FRONTEND_CONTRACT.md](SSH_FRONTEND_CONTRACT.md). `ResourceService`
вызывает через SSH только этот исполнитель. Формат ответа должен быть
стабилен; ошибки и exit code не маскируются успешными пустыми списками.

`ServerSetupService` проверяет `command -v`/версию утилиты и при
возможности устанавливает/обновляет требуемый CLI-пакет через SSH,
без принуждения пользователя к ручным командам. Собственный CLI
доставляется/обновляется по SSH с проверкой целостности. Никакой HTTP/REST
агент для него автоматически не вводится.

**Mail:** `MailService → SSH → mail/sendmail/fortiq-mail` на Linux.
MIME/синхронизация внешнего ящика, когда понадобятся, относятся к
серверной `fortiq-mail` или существующей Linux CLI-утилите.
Серверная программа вправе использовать протокол провайдера со стороны
Linux; Flutter никогда не открывает SMTP/IMAP. Без SSH Mail не
получает/отправляет данные, допускается только временный черновик.

**Browser:** WebView2 рисует страницу; интерактивный трафик проходит через
SSH forwarding на выбранном Linux (серверный `sshd`), CLI-запросы
выполняет `curl`/другая серверная команда. Прямой fallback запрещён,
включая DNS и WebRTC; принимается только после e2e проверки.

## 3. SessionManager

Для каждого сервера независимая сессия со стабильным ID, профилем, доверенным ключом,
состоянием и поколением соединения. Состояния: disconnected, connecting, connected,
reconnecting, blocked (например, изменившийся ключ). Повторный connect и Disconnect
инвалидируют предыдущее поколение; поздний клиент закрывается и не становится активным.

На одну сессию допускается одна попытка подключения/reconnect одновременно.
Таймер и «Retry now» не создают два клиента; Disconnect отменяет таймеры и дальнейшие
попытки. Отмена попытки освобождает её каналы и сокеты. Ключ хоста проверяется
для каждой новой транспортной сессии; автоматический reconnect не принимает
новый или изменившийся ключ. Неверная аутентификация останавливает повторы.

SFTP, терминалы и SOCKS принадлежат конкретной сессии. Переподключение создаёт
новые каналы, но не воспроизводит изменяющие сервер команды. Терминал повторно
присоединяется к своей tmux-сессии при поддержке сервера; без tmux нельзя обещать
сохранение запущенного процесса. Терминал имеет стабильный идентификатор сессии (`fortiq-1`).

## 4. TaskManager

Задача содержит ID, действие, источник/назначение, session ID и поколение,
прогресс (или признак неизвестного объёма), время, результат и безопасное описание
ошибки. Состояния: queued, running, cancelling, cancelled, succeeded, failed,
unknown. `unknown` означает, что сервер мог выполнить действие, но подтверждение
не получено; это не ошибка, допускающая слепой повтор.

Закрытие окна не уничтожает запись задачи. Отмена поддерживается только если
адаптер может её корректно выполнить; запрос отмены не равен остановке процесса
на сервере. Для apt не следует обещать немедленную отмену. Если результат неясен,
задача переходит в unknown и предлагает проверку состояния.

Повторяющиеся чтения могут возобновляться с ограничениями. Изменяющая операция
всегда имеет отдельную политику проверки результата; она не повторяется только
потому, что восстановился SSH. История задач не содержит секретов или произвольных
команд для автоматического воспроизведения.

## 5. AppDescriptor и ActionRouter

`AppDescriptor`: стабильный app ID, категория Workspace/System/Tools, название,
иконка, фабрика окна, поддерживаемые типы ресурсов и действий, требуемые возможности,
размеры по умолчанию и политика `multipleInstances`. Реестр обслуживает док,
«Открыть с помощью» и восстановление; все 12 текущих типов сохраняются.

`ActionRouter` принимает типизированное действие (open, edit, showLogs, restart,
reveal, attach и т. п.) с ResourceLocation и контекстом службы/процесса/задачи.
Проверяет источник, возможности и политику нескольких окон. Переход
Services → Logs → Editor → Restart → Verify сохраняет server ID и unit ID;
restart не выполняется после ошибки сохранения. Для PID учитывается повторное
использование идентификатора. Маршрутизация не подставляет активный сервер
вместо указанного в действии.

`NotificationService` связывает уведомление с задачей или ресурсом, показывает
результат и открывает правильный контекст через ActionRouter. Приложения не
реализуют собственные независимые очереди уведомлений.

## 6. CredentialStore и локальные данные

CredentialStore хранит ключи, токены, пароли по явной политике пользователя
и passphrase в системном защищённом хранилище там, где оно поддерживается.
По умолчанию passphrase и временные пароли существуют только в памяти;
постоянное хранение требует отдельного выбора. Профили содержат ссылки на секрет,
а не его значение. Доступ ограничен назначением и источником; удаление аккаунта
отзывает ссылки и удаляет сохранённые секреты по заданной политике.

Недоступность защищённого хранилища показывается явно; нельзя незаметно перейти
к открытому файлу. Миграция существующих импортированных ключей проверяет чтение
новой записи перед удалением старой и предусматривает восстановление при сбое.
Секреты не попадают в shared_preferences, черновики, историю, логи или экспорт.
Освобождение строки в Dart не гарантирует физического обнуления памяти.

Local Storage содержит **только UI-кеш** (с явной меткой устаревания),
защищённые временные черновики и состояние окон/профилей. Он никогда
не становится первичным хранилищем почты, документов или иных рабочих
данных. Editor и Docs могут сохранять локальную черновую копию для
защиты от потери, но записывают авторитетный результат на Linux через
SSH/CLI. Конкретная технология хранения выбирается после проверки миграции.

## 7. WorkspaceState и асинхронный жизненный цикл

WorkspaceState содержит стабильные ID окон, app ID, порядок, геометрию,
source ID, ResourceLocation и ссылки на локальные черновики. Не содержит секретов,
живых SSH-объектов или операций изменения для автоматического повтора.

Восстановление открывает UI-состояние и защищённые локальные черновики;
**все рабочие окна** показывают отсутствие доступа к источнику до восстановления
его SSH-сессии и серверного CLI. Отсутствующая серверная capability или
аккаунт серверной CLI-утилиты не ломает всю оболочку. Старое состояние мигрируется либо сохраняется
для восстановления с понятной ошибкой.

Каждый запрос привязан к окну, ресурсу и поколению. После закрытия, смены пути
или сервера поздний ответ не изменяет новый ресурс. Потоки и контроллеры
освобождаются владельцем; сворачивание окна не равно dispose. Общая задача
продолжает жить по политике TaskManager.

## Безопасность операций

Это правила R0. В коде им соответствует `ServerSetupService`. Проверено юнит- и
виджет-тестами с FakeShell и синтаксисом скриптов; на реальном сервере и disposable VM
не проверено.

1. При подключении Fortiq сам готовит сервер: проверка читает, а найденное
   выполняется по шагам (пакеты, обновления, защита), **на виду**: модальное окно
   показывает шаги и живой лог, цепочка останавливается на первой ошибке и по
   просьбе пользователя после текущего шага. Если делать нечего, окна нет.
2. Шаги, способные отрезать доступ (SSH, файрвол), подтверждаются **вторым входом**
   новым соединением, пока первая сессия ещё может отменить изменение; при неудаче
   изменение откатывается автоматически. Парольный вход не включает шаг SSH.
   Файрвол сохраняет открытыми SSH и порты, слушающие сейчас. Без root/sudo и на
   системах не Debian/Ubuntu ничего не меняется, причина показана.
3. Чтение и изменение системы — разные фазы с разными командами. Недоступные
   права отличаются от отсутствующего пакета. Текущий `sudo -n sh -c` не
   объявляется системой минимальных разрешений.
4. Операции сериализуются на конфликтующих ресурсах: один apt-процесс,
   одна запись определённой версии файла. UFW проверяет сохранение SSH-доступа;
   дисковые действия повторно идентифицируют устройство и запрещают работу
   с системными/занятыми устройствами без предусмотренной процедуры.
5. После обрыва потенциально изменяющая команда получает unknown до проверки
   фактического результата. Нельзя автоматически повторять restart, удаление,
   обновление, отправку письма или изменение разделов. Ошибка сохранения копии
   письма на сервере не разрешает отправить письмо ещё раз.
6. Shell-аргументы экранируются, действия проверяются по допустимому набору;
   вывод и код завершения проверяются. SOCKS не имеет скрытого прямого fallback;
   HTTP/DNS/WebRTC и отказ туннеля проверяются интеграционно.

## 9. Проверка контрактов

Unit-проверки покрывают парсеры и состояния задач/сессий; widget-проверки —
dirty, поздние ответы, закрытие и восстановление окон. Интеграционные проверки
используют реальный SSH/SFTP/SOCKS и **серверную Mail CLI** на тестовом Linux-хосте.
Прямые SMTP/IMAP-соединения из Flutter не тестируются, потому что запрещены.
Изменения служб,
UFW, пакетов и дисков проверяются на disposable Linux VM с восстановимым состоянием.
Наличие контракта или тестового файла не означает прохождение проверки;
свидетельства и этапы приёмки ведутся только в матрице.

## 10. Лицензирование и Lemon Squeezy (R0)

Для FORTIQ действуют две коммерческие опции: **Intro (2 € разово на 14 дней)**
и **Pro (39,90 € в год, ежегодное продление)**.
Обе предоставляют одинаковый полный набор возможностей. Подробные договорённости —
[LICENSING.md](LICENSING.md).

Для первого выпуска используем штатную систему лицензий Lemon Squeezy:

    FORTIQ Desktop
      ├── Hosted Checkout: Intro / Pro
      ├── LicenseClient ──HTTPS──> Lemon Squeezy License API
      │       ├── activate + проверка store/product/variant
      │       ├── validate license + instance
      │       └── deactivate instance
      ├── локальный защищённый ключ и ограниченный offline-cache
      └── Hosted Customer Portal: управление Pro

Lemon Squeezy формирует лицензионные ключи и доставляет их покупателю после
оплаты. Для Intro устанавливается срок ключа **14 дней с покупки**; для Pro срок
лицензии следует состоянию годовой подписки. Отмена подписки прекращает
будущие списания, но доступ продолжается до фактического окончания срока
её действия, согласно состоянию лицензии.

- Активация и восстановление покупки доступны без SSH и до запуска окон с
  удалёнными ресурсами.
- Пользователь вводит ключ из подтверждённой покупки. Клиент проверяет
  `store_id`, `product_id`/`variant_id`, `instance_id` и срок;
  переход со страницы оплаты не является подтверждением лицензии.
- Лицензионный ключ защищается при хранении локально; клиенту не передаются
  административные API-токены магазина или секреты подписей webhooks.
- Неоднозначный/недоступный ответ сервера не превращается в бесконечный доступ
  и не приводит к удалению локальных данных. Офлайн-период утверждается отдельно.
- **Один Intro на покупателя** — отдельное требование. Встроенный License API
  ограничивает активации конкретного ключа, но не предотвращает покупку
  второго ключа. Для строгой проверки повторных покупок потребуется
  минимальный серверный учёт и определённая политика идентификации. Не
  объявлять правило реализованным, пока не проверено фактическое ограничение.
- Если нужны webhooks или серверный компонент, проверять подпись событий,
  обрабатывать повторы идемпотентно и хранить только минимум необходимых данных.
  Не разрабатывать полноценный биллинг/личный кабинет: Lemon Squeezy уже
  предоставляет Customer Portal.

**Открытые решения:** допустимое число устройств, офлайн-период,
идентификация повторной Intro-покупки и политика восстановления доступа.

### Цена и промокоды

Публичная базовая цена Pro — **39,90 € в год**, Intro — **2 € за 14 дней**,
цены конечные с включением применимого TVA при корректной настройке
**tax-inclusive pricing** в Lemon Squeezy.

Промокоды — необязательный инструмент продвижения только **Pro**,
настраиваемый через штатные Discounts Lemon Squeezy. По умолчанию
скидка действует **только на первый годовой платёж**; продление
производится по полной цене 39,90 € в год, что должно быть прозрачно
показано перед покупкой. Промокоды Intro не применяются.
