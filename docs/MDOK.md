# MDok — premier Markdown, 23.10.2026

Premier éditeur de documents Markdown du serveur. **PDF pas encore implémenté**.

## Реализованный сценарий

- Отдельное окно MDok с общими Glass/WindowDragArea/активацией по клику. Открывается
  из панели, launcher, двойным кликом по обычному .md/.markdown в Files или по абсолютному пути.
  Files сохраняет собственный preview/editor: MDok не использует его буфер.
- Новый документ в памяти, plain-text редактор, предпросмотр рядом на desktop, переключение
  «редактор/просмотр» в adaptive-режиме, Ctrl+S. Sidebar становится drawer.
- Чтение/сохранение только через SFTP выбранного закреплённого SSH-источника, отдельный
  рабочий поток/соединение. Используются существующие SshSession.readFile/saveFile/saveCopy;
  новых серверных агентов/CLI или прямых внешних подключений нет.
- Обычный Save проверяет SHA-256 исходной версии, пишет временный файл рядом, сохраняет
  метаданные по контракту Files и публикует через posix-rename. Это оптимистическая проверка,
  не CAS относительно постороннего писателя. Конфликт сохраняет черновик; принудительной
  перезаписи в MDok нет. «Копия» пишет по пути сверху, выбирая свободное имя (n), если занято.
  Новый документ записывается этим же механизмом, а не перезаписывает существующий.
- До 256 КиБ, только полный UTF-8, с сохранением BOM и единых LF/CRLF. Truncated, binary/NUL,
  некорректный UTF-8, CR-only и смешанные окончания отвергаются, без незаметной конвертации.
- Source label/token закреплены за документом. Disconnect/смена поколения оставляют текст
  и черновик в RAM, отключают Save, отбрасывают поздний результат. Запись в процессе разрыва
  считается unknown, без автоматического повтора. Повторное подключение не перепривязывает
  черновик автоматически: текст можно явно скопировать, проверить сервер и открыть заново.
- Открытие другого документа/нового, закрытие окна и обычный выход из приложения требуют
  решения о несохранённом черновике. Во время операции закрытие блокируется. Force-kill/
  аварийный выход не защищены: постоянного локального кеша нет. Переключение приложений
  скрывает окно без удаления текста.

## Готовые инструменты и предпросмотр

Markdown разбирает **QTextDocument Qt 6.12**, не собственный parser. MarkdownDialectGitHub
с MarkdownNoHTML; SafeMarkdownDocument запрещает загрузку любых ресурсов: file/HTTP/data,
включая картинки. Ссылки в рисуемом preview не запускаются. Это форматирование уже полученного
через SSH текста, без запроса к внешним сайтам. Qt — существующая зависимость клиента.

Предпросмотр ограничен первыми 64 000 символами, ограничение подписано. Рисуется только viewport,
а не текстура полной высоты документа; прокрутка остаётся доступной. Предпросмотр обновляется
с задержкой 180 мс после ввода. Сохранение использует весь документ в пределах лимита 256 КиБ.
Нормализация Unicode не выполняется. WYSIWYG, поиск/replace, история документов, PDF и embedded
media не реализованы.

Перед срезом проверены локальные Qt-компоненты: Qt6Pdf отсутствует в Windows и Android SDK.
На тестовом Debian проверены command -v для pandoc/cmark/pdfinfo/pdftoppm: не установлены.
Поэтому PDF-просмотр/экспорт не объявлен работающим, программы не устанавливались. Для него
нужен отдельный проверенный серверный инструмент и сценарий, а не скрытый сетевой fallback.

## Проверки

Статус сборки/испытаний добавляется после выполнения. Физический Android и чистая Windows
по-прежнему не квалифицированы.
