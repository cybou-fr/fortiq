# MDok — premier Markdown, 23.10.2026

Premier éditeur de documents Markdown du serveur. **PDF pas encore implémenté**.

## Реализованный сценарий

- Отдельное окно MDok с общими Glass/WindowDragArea/активацией по клику. Открывается
  из панели, launcher, двойным кликом по обычному .md/.markdown в Files или по абсолютному пути.
  Files сохраняет собственный preview/editor: MDok не использует его буфер.
- Новый документ в памяти, plain-text редактор, предпросмотр рядом на desktop, переключение
  «редактор/просмотр» в adaptive-режиме, Ctrl+S. Sidebar становится drawer.
- Чтение/сохранение только через SFTP выбранного закреплённого SSH-источника, отдельный
  рабочий поток/соединение. Используются существующие SshSession.readFile/saveFile/saveCopy;
  новых серверных агентов/CLI или прямых внешних подключений нет.
- Обычный Save проверяет SHA-256 исходной версии, пишет временный файл рядом, сохраняет
  метаданные по контракту Files и публикует через posix-rename. Это оптимистическая проверка,
  не CAS относительно постороннего писателя. Конфликт сохраняет черновик; принудительной
  перезаписи в MDok нет. «Копия» пишет по пути сверху, выбирая свободное имя (n), если занято.
  Новый документ записывается этим же механизмом, а не перезаписывает существующий.
- До 256 КиБ, только полный UTF-8, с сохранением BOM и единых LF/CRLF. Truncated, binary/NUL,
  некорректный UTF-8, CR-only и смешанные окончания отвергаются, без незаметной конвертации.
- Source label/serverId/token закреплены за документом. Disconnect/смена поколения оставляют текст
  и черновик в RAM, отключают Save, отбрасывают поздний результат. Запись в процессе разрыва
  считается unknown, без автоматического повтора. Повторное подключение не перепривязывает
  черновик автоматически: текст можно явно скопировать, проверить сервер и открыть заново.
- Открытие другого документа/нового, закрытие окна и обычный выход из приложения требуют
  решения о несохранённом черновике. Во время операции закрытие MDok блокируется; завершение
  SSH-сессии отдельно подтверждает TaskManager. Force-kill/
  аварийный выход не защищены: постоянного локального кеша нет. Переключение приложений
  скрывает окно без удаления текста.

## Готовые инструменты и предпросмотр

Markdown разбирает **QTextDocument Qt 6.12**, не собственный parser. MarkdownDialectGitHub
с MarkdownNoHTML; SafeMarkdownDocument запрещает загрузку любых ресурсов: file/HTTP/data,
включая картинки. Ссылки в рисуемом preview не запускаются. Это форматирование уже полученного
через SSH текста, без запроса к внешним сайтам. Qt — существующая зависимость клиента.

Предпросмотр ограничен первыми 64 000 символами, ограничение подписано. Рисуется только viewport,
а не текстура полной высоты документа; прокрутка остаётся доступной. Предпросмотр обновляется
с задержкой 180 мс после ввода. Сохранение использует весь документ в пределах лимита 256 КиБ.
Нормализация Unicode не выполняется. WYSIWYG, история документов, PDF и embedded
media не реализованы.

Перед срезом проверены локальные Qt-компоненты: Qt6Pdf отсутствует в Windows и Android SDK.
На тестовом Debian проверены command -v для pandoc/cmark/pdfinfo/pdftoppm: не установлены.
Поэтому PDF-просмотр/экспорт не объявлен работающим, программы не устанавливались. Для него
нужен отдельный проверенный серверный инструмент и сценарий, а не скрытый сетевой fallback.

## Поиск и замена, подсветка, горячие клавиши (26.10.2026)

- **Поиск и замена** (Ctrl+F — поиск, Ctrl+H — с заменой, F3 / Shift+F3 — дальше/назад, Enter / Shift+Enter в поле поиска, Esc — закрыть): по обычному тексту, **без регулярных выражений** (запрос — всегда данные: `.*`, `$(…)` ищутся буквально), с переключателями «Aa» (регистр) и «Mot» (слово целиком; `_` считается буквой слова), счётчик результатов, обход по кругу. Замена вносится прямо в редактор (`remove`/`insert`), поэтому Undo работает; «Tout» заменяет всё одним действием, замена не ищется повторно, подстановка буквальная (без `$1`/`\0`). Поиск ограничен 20 000 совпадений. Логика — чистые функции [`src/documents/TextSearch.h`](../src/documents/TextSearch.h).
- **Подсветка Markdown** ([`MarkdownHighlighter`](../src/documents/MarkdownHighlighter.cpp), `QSyntaxHighlighter`): заголовки, **жирный**, *курсив*, `код`, ограждённые блоки, ссылки, цитаты, маркеры списков, разделители. Она только красит символы: текст не меняется, ничего не загружается, ссылки не открываются. Строка длиннее 4000 символов остаётся без подсветки (ни одно регулярное выражение не бежит по враждебному мегабайту). Состояние ограждённого блока переносится между строками; незакрытый блок остаётся кодом до конца документа.
- **Горячие клавиши:** Ctrl+B (`**…**`), Ctrl+I (`*…*`), Ctrl+K (`[выделение](https://)` с выделенным адресом); без выделения вставляются пара разделителей и курсор между ними.
- **Счётчик** слов, символов и строк внизу справа (обновляется вместе с предпросмотром, через 180 мс после ввода).
- **Проверено:** `fortiq_markdown_tests` (14: поиск с регистром, словами, Юникодом, буквальностью запроса, ограничением числа совпадений, замена и её буквальность, обход по кругу, счётчики), `fortiq_highlighter_tests` (6: каждая конструкция, ограждённый блок не принимается за заголовок, текст не меняется, враждебный ввод — строка из 200 000 звёздочек, 900 незакрытых `**`, 3500 обратных кавычек, 2000 строк разметки — обрабатывается быстрее 5 с), тест раскладки `fortiq_layout` (Ctrl+F открывает панель, счётчик «2 résultat(s)», «Tout» заменяет и в редакторе, и в модели, Esc закрывает, Ctrl+B оборачивает выделение) на шести размерах окна.
- **Не проверено / остаток:** внешний вид панели поиска и цвета подсветки визуально не приняты; Android (экранная клавиатура, сочетания клавиш недоступны, панель увеличена, но не проверялась); поиск не охватывает предпросмотр; замена «Tout» на очень большом числе совпадений создаёт столько же шагов Undo; регулярные выражения и «заменить в нескольких файлах» не планируются.

## Серверный черновик и экран конфликта (26.10.2026)

- **Черновик на сервере, не на клиенте.** Пока открытый документ изменён и есть связь, через 5 с после последнего ввода MDok пишет черновик на **тот же сервер** по тому же SSH: `${XDG_CACHE_HOME:-~/.cache}/fortiq-mdok/<sha256 пути>.md` и `.meta` (каталог 0700, файлы 0600, запись во временный файл и атомарное `mv`: сначала текст, потом метаданные). Имя файла — хэш пути, сам путь лежит в метаданных в base64. Постоянного локального кеша по-прежнему нет, новых сетевых путей нет. Отдельного сервисного процесса или CLI нет: используются `sh`, `base64`, `mv`. Текст идёт в скрипт только как base64 (никакой интерполяции).
- **Восстановление.** При открытии документа MDok читает черновик; если он отличается от файла, над редактором появляется строка «Найден несохранённый черновик от …» с кнопками **Восстановить / Plus tard / Удалить**. Если файл на сервере изменился с тех пор, как писался черновик, это сказано, а восстановленный текст сохраняется с прежней базовой версией — то есть следующее сохранение **обязательно** упрётся в проверку конфликта, а не перезапишет чужую правку.
- **Когда черновик удаляется:** успешное сохранение (файла и копии), явное «Отбросить черновик» в диалоге несохранённых изменений, кнопка «Удалить». **Не** удаляется при выходе, обрыве связи, конфликте и выборе «версия сервера» — там черновик и есть страховка.
- **Экран конфликта.** Если при сохранении выяснилось, что файл на сервере изменился, MDok сначала дописывает черновик на сервер, затем читает версию сервера и показывает построчное сравнение («−» только у вас, «+» только на сервере, дальние неизменные строки свёрнуты; для документов длиннее 3000 строк — только сводка). Три выхода: **сохранить мою версию как копию** (`имя (ma version).md` рядом, свободное имя выбирается как у обычной копии), **загрузить версию сервера** (мой текст остаётся в черновике и будет предложен при следующем открытии), **оставить мой текст и решить позже**. Принудительной перезаписи по-прежнему нет, слияния тоже нет.
- **Проверено:** юнит-тесты `fortiq_markdown_tests` (формат метаданных и их проверка, скрипты без сырого текста, порядок публикации, разбор ответа, построчный diff и его границы) и живой `mdokServerDraftAndConflict` на одноразовом Debian: черновик появляется с правами 600/700 и без имени документа в названии, переживает «аварию» (новый контроллер), восстанавливается, при изменении файла третьей стороной сохранение открывает сравнение и **не затирает** серверный файл, оба выхода (копия / версия сервера) работают, успешное сохранение убирает черновик. Тест раскладки `fortiq_layout` (47 проверок, включая окно MDok на шести размерах) проходит; один раз при подготовке упала проверка кнопки «запомнить» окна входа (щелчок мышью по первому окну), при повторе всё зелёное.
- **Не проверено / остаток:** внешний вид баннера и экрана конфликта визуально не принят (как и вся оболочка); Android и физическое устройство не проверялись; черновик новых (ещё не сохранённых) документов не пишется — у них нет серверного пути; задержка 5 с фиксирована; если связь потеряна, текст остаётся только в памяти клиента (это сказано в строке состояния).

## Повседневный сценарий Files ↔ MDok (27.10.2026)

Первый связанный сценарий остаётся **однодокументным Markdown-редактором**:
многодокументные вкладки, PDF и вложения почты этим срезом не добавлены.

- Повторное открытие того же пути на том же поколении SSH активирует уже
  открытый документ без перечитывания: текст, выделение и Undo сохраняются.
- При открытии другого документа, создании нового, закрытии MDok, выходе,
  отключении или смене сервера несохранённый текст требует решения.
  Основное действие при доступном источнике — **Enregistrer et continuer**;
  **Abandonner** и отмена доступны отдельно. Продолжение выполняется только
  после подтверждённого успешного сохранения. Ошибка оставляет текст и диалог;
  конфликт открывает существующий экран сравнения, без отложенного перехода.
- Escape закрывает поиск без второго действия закрытия документа на узком экране;
  Back сначала закрывает поиск.
- Подтверждение закреплено за `serverId` и поколением соединения: устаревший
  диалог не открывает другой документ и не отбрасывает текст на новом источнике.
  Недоступный источник явно отмечен; текст остаётся в RAM, запись отключена.
  Правило явного восстановления после переподключения из предыдущего раздела
  сохраняется — автоматической перепривязки черновика нет.
- У документа есть исходный `serverId`; удаление его серверного черновика
  разрешено только на исходном поколении SSH. Отказ от черновика A после
  перехода на B не удаляет независимый черновик B даже с тем же хэшем пути.
- Успешный Save обновляет Files, если его родительский каталог открыт и нет
  другой навигации. Кнопка **Afficher dans Fichiers** в sidebar/drawer открывает
  родительский каталог, снимает фильтр и выделяет файл, не закрывая MDok.
  Для скрытого имени включается показ скрытых файлов; подгружается имеющаяся
  серверная выдача до действующего лимита 50 000. Если файл не найден в
  загруженной выдаче, это сказано явно. Отложенное выделение отменяется при
  смене сервера или поколения соединения. Отказ открытия папки также снимает
  отложенное выделение: оно не срабатывает при последующей ручной навигации.

Проверки и итоговые ограничения этого среза фиксируются в
[PRODUCTION_READINESS](PRODUCTION_READINESS.md); визуальная приёмка владельцем
и физический Android остаются отдельными этапами.

## MD-01: защита от устаревшего autosave (28.10.2026)

Исправлена гонка в асинхронной записи серверного черновика: перед запуском SSH-записи
контроллер фиксирует точный снимок текста. После подтверждения, если пользователь
успел изменить документ и он всё ещё dirty, статус **не** заявляет, что актуальный
черновик сохранён, а показывает ожидание и назначает повторный autosave.
Проверка свежести выделена в `draftNeedsAnotherSave`; регрессионный unit-тест
`inFlightDraftMustNotMaskNewEdits` добавлен в `fortiq_markdown_tests`.

**Статус проверки:** код и тест закоммичены, но компиляция и исполнение тестов
в этой сессии не выполнялись. Это точечное исправление, **не закрытие всего MD-01**.
Остались открыты: черновики для новых документов до первого Save, защита при
обрыве SSH (текст только в RAM), полноценная матрица save/autosave/close/reconnect
и тесты реальных потерянных подтверждений.

### MD-01 continued: сериализация autosave-записей

Контроллер теперь допускает только **одну незавершённую серверную запись черновика**.
Пока она выполняется, срабатывание таймера не создаёт второй SSH upload: повторная
попытка назначается через 1 секунду. После ответа сбрасывается признак активной
записи; если текст уже изменился, существующая проверка снимка назначает новый
autosave. Это снижает вероятность перезаписи актуального черновика старым
снимком и ограничивает очередь SSH операций. При закрытии/смене сессии старый
ответ не сообщает о сохранённом тексте нового документа.

**Верификация:** изменения закоммичены; C++/Qt тесты и живой SSH не запускались
в этой сессии. Требуется отдельный integration-тест с задержанной записью,
повторными правками, Save, переключением документов и потерей SSH.

### MD-01: игнорирование запоздавших подтверждений SSH

Завершение фонового upload черновика теперь проверяется по идентичности сервера,
токену соединения, пути и **эпохе операции документа** (`m_seq`). Это
предотвращает ложный статус «сохранено» после Save, повторного открытия
или смены сервера; при потере связи также проверяется `linkLost()`.
Правило `draftCompletionBelongsToDocument` покрыто unit-тестами для
разных путей, серверов, токенов, эпох и отключения.

**Не завершено:** для надёжного MD-01 ещё нужны реальные асинхронные/live-тесты,
черновики новых безымянных документов и явная стратегия восстановления при
отсутствии SSH. Эти коммиты не подтверждены сборкой Qt/живым прогоном.

### MD-01: защита восстановления и честный статус новых правок (28.10.2026)

Асинхронное чтение серверного черновика (`checkDraft`) теперь использует ту же
проверку идентичности, что и upload: путь, идентификатор сервера, токен соединения,
эпоху операции документа и состояние связи. Это предотвращает появление чужого
или устаревшего окна восстановления при быстром повторном открытии документа
либо смене сервера. Unit regression: `delayedRecoveryCannotCrossDocumentEpoch`.

При каждом новом изменении текста прежний положительный статус autosave
заменяется на «изменения ещё не сохранены на сервере» до подтверждения
актуальной версии. Это **не** обещает сохранность нового документа до первого
Save и не решает отсутствие связи.

**Верификация:** исходники и unit-тест записаны в main; в текущей сессии
сборка Qt, запуск unit-тестов и живой SSH-прогон не выполнены. Для закрытия
MD-01 необходимы интеграционные тесты с задержанными ответами, отказами и
переключением сервера.

### MD-01: защита ручного Save при работающем autosave (28.10.2026)

Если фоновая SSH-запись черновика ещё не завершена, ручные Save/Save As
не начинают новую конкурирующую операцию. Вместо молчаливого отказа MDok
показывает сообщение о выполняющемся сохранении черновика и предлагает
повторить действие после завершения. Это временная консервативная политика:
дальше нужно реализовать очередь намерения пользователя без небезопасного
повторения записи со статусом `unknown`.

Unit-тест `manualSaveWaitsForDraftUpload` проверяет правило блокировки
пересекающихся операций. **Запуск тестов и сборка в этой сессии не проведены**;
полное MD-01 остаётся открытым до live fault-injection проверки.

### MD-01: live regression for rapid autosave edits (28.10.2026)

Добавлен живой тест `mdokBurstEditsConvergeBeforeManualSave` в
`tests/SshIntegrationTest.cpp`. Он подключается к одноразовому Debian SSH,
создаёт реальный Markdown файл, выполняет 12 быстрых правок с включённым
серверным autosave, дожидается записи **последней** версии в приватный
черновик, затем выполняет обычный Save и проверяет содержимое исходного файла
и удаление черновика. Все временные файлы удаляются через `qScopeGuard`.

Это проверка достижимости и согласованности при серии правок, **не**
детерминированная инъекция потери SSH, ACK или конкретного interleaving.
Код теста закоммичен; живой прогон и сборка не выполнялись в этой сессии.
Для закрытия MD-01 остаются управляемые задержки/отказы SSH и черновики
новых несохранённых документов.

### MD-01: пользовательский Save после фонового autosave (28.10.2026)

Предыдущее ограничение «повторите Save вручную» заменено одним отложенным
**явным пользовательским намерением**. Если Save/Save As запрошен во время
серверного upload черновика, сохраняются путь назначения, режим Save/Save As
и поколение документа. После **подтверждённого** успешного upload контроллер
один раз запускает запрос обычного Save. Ошибка, неизвестный исход, разрыв
соединения или смена документа не запускают отложенную запись. Новый явный
Save заменяет прежний ожидающий запрос. Auto-retry операций записи с исходом
`unknown` не производится.

Добавлен unit-тест `pendingSaveRequiresConfirmedDraftAndSameSource`.
**Проверка ограничена кодом и unit-контрактом:** реальный прогон Qt/SSH в
этой сессии не выполнялся. Обязателен интеграционный тест с задержанным
autosave и ручным Save, включая сбой upload.

Черновики ещё не названных документов требуют отдельного механизма обнаружения
после перезапуска и остаются **не реализованы**.

## MD-02 — работа с документом: навигация и форматирование (28.10.2026)

В `qml/shell/DocumentsWindow.qml` добавлены две пользовательские возможности:

- **План документа** в sidebar (на маленьком экране — в drawer): извлекаются заголовки Markdown H1–H6, до 200 элементов. Сканирование не считает заголовками строки внутри fenced code blocks; при выборе заголовка курсор переходит к его позиции. План обновляется вместе с предпросмотром после задержки 180 мс.
- **Панель форматирования** над редактором: H1, H2, жирный, курсив, маркированный и нумерованный список, цитата, inline code, ссылка и поиск. Панель доступна мышью/касанием, а существующие клавиатурные сочетания сохраняются.

Это первая реализация интерфейса, **не завершение всей работы с документами**: нет PDF, мультимедийных вложений, синхронной прокрутки, многодокументных вкладок или WYSIWYG. Текущие ограничения Markdown (256 КиБ, UTF-8, безопасный просмотр) сохраняются.

**Верификация:** исходники обновлены непосредственно в main; сборка Qt и визуальная приёмка на Windows/Debian/Android в этой сессии не проводились. Требуется проверить размещение панели на шести размерах окна и с экранной клавиатурой.

## MD-03 — PDF Viewer, первый функциональный срез (28.10.2026)

MDok теперь принимает абсолютный путь `.pdf` из строки пути и из Files.
Режим **только для чтения**: общее окно MDok показывает номер страницы,
кнопки предыдущая/следующая, масштаб 50–300% и прокручиваемую страницу.
Сохранение Markdown в PDF-режиме отключено.

На выбранном Linux-сервере через уже закреплённое SSH-соединение используются
существующие программы Poppler: `pdfinfo` для количества страниц и
`pdftoppm` для рендеринга **одной** страницы в PNG. В клиент попадает
только PNG по SSH (base64, без прямого HTTP или клиентского PDF-parser).
Рендеринг ограничен 1600 пикселями по большей стороне, 3 МБ PNG,
до 10 000 страниц в документе; на сервере временная директория создаётся
через `mktemp -d` с `umask 077` и удаляется по trap.
Запросы не стартуют при занятом контроллере; ответы старого сервера или
поколения операции не меняют текущую страницу.
При отсутствии `pdfinfo`/`pdftoppm` показывается ошибка, а не ложная
пустая страница. Для Debian-сервера пакеты предоставляет `poppler-utils`.

**Ограничения первого среза:** PDF с паролем, поиск по PDF, выделение и
копирование текста, аннотации, печать, экспорт Markdown→PDF, миниатюры
и непрерывная прокрутка страниц ещё не реализованы. Проверены только
исходные изменения; Qt-сборка и runtime-тесты по решению владельца отложены.

## MD-04 — экспорт Markdown → PDF на сервере (28.10.2026)

Добавлен `DocumentsController.exportPdf(destination)` и кнопка PDF в MDok.
Экспорт берёт **текущий снимок редактора** (включая ещё не сохранённые правки)
и выполняется исключительно на выбранном SSH-сервере, не создавая прямого
сетевого соединения у клиента. По умолчанию используется имя текущего
Markdown-файла с расширением `.pdf`.

Конвейер: `pandoc --from=gfm --standalone --pdf-engine=weasyprint`; на Debian
сервере необходимы `pandoc` и `weasyprint` (установка администратором,
FORTIQ их автоматически не устанавливает). Markdown передаётся в скрипт как
base64 через quoted heredoc; путь назначения shell-экранирован. Скрипт
выполняется с `umask 077`, создаёт временный каталог рядом с результатом,
удаляет его через trap и проверяет сигнатуру `%PDF-`. Публикация через
`ln` **не заменяет существующий PDF**; при занятом имени возвращается
ошибка. Источник Markdown остаётся неизменным. Операция отображается в
TaskManager; при неизвестном исходе автоматического повтора нет.

**Ограничения:** первый срез не загружает удалённые картинки и CSS,
не передаёт ресурсы пользовательской директории в pandoc, не поддерживает
настройку шаблона, параметры страницы или PDF/A. Экспорт может не отобразить
внешние изображения и богатое форматирование; наличие pandoc/weasyprint
и шрифтов проверяется на сервере. Пользователь должен доверять серверу и
установленным инструментам конвертации. Тесты и сборка Qt сознательно
отложены по решению владельца; функция ещё не квалифицирована для production.

## MD-05 — изображения в Markdown (первый срез)

Предпросмотр может отображать относительные ссылки `![alt](images/picture.png)`
из каталога текущего Markdown-документа. Ресурсы читаются отдельными
асинхронными запросами SFTP через выбранный закреплённый SSH-сервер,
передаются в память клиента и декодируются через Qt ImageReader.
`SafeMarkdownDocument` по-прежнему не загружает произвольные `file:`,
`http:`, `https:` или `data:` URL: он отдаёт только изображения,
явно помещённые контроллером в таблицу разрешённых ресурсов.

Границы первого среза: PNG/JPEG/WebP, до 2 МиБ на файл, размеры не больше
4096×4096 и 8 миллионов пикселей, не более 12 запросов за обновление
предпросмотра; не поддерживаются URL с параметрами, абсолютные пути,
`..`, SVG и внешние картинки. При смене документа кеш изображений
сбрасывается. Ответ прежнего документа, сервера или SSH-поколения
не должен попадать в новый предпросмотр.

**Известная граница безопасности:** SFTP может разыменовывать
символьные ссылки внутри разрешённого каталога. Проверки реального
пути/политики symlink ещё нет — для работы с недоверенными
Markdown-файлами и production функцию необходимо дополнительно
ограничить или отключить. Не реализованы добавление/загрузка нового
изображения из клиента, редактирование изображения и внешний fetch.
Тесты и сборка по решению владельца отложены.

### MD-05 продолжение — вставка изображения и проверка пути

В MDok добавлена кнопка **Image** с полем относительного пути к уже
существующему файлу на выбранном сервере. Она вставляет Markdown-ссылку
`![alt](images/figure.png)` в позицию курсора, используя выделенный текст
как подпись. Это **не загрузка файла с клиента**: изображение должно
уже находиться в каталоге документа или его вложенной папке.

Исправлено распознавание относительных ссылок в QML. Перед SFTP-чтением
добавлена серверная проверка компонентов пути на символьные ссылки
(`test ! -L`), без shell-интерполяции пользовательского пути. Проверка
**не атомарна** относительно последующего SFTP-read и не устраняет гонку
переименования на недоверенном многопользовательском сервере. Каталог
самого документа также требует отдельной политики. Для production
потребуется более строгая модель разрешённых ресурсов.

По решению владельца сборка и тесты пока отложены. CI не запускался
в рамках этой задачи.

## MD-06 — быстрый переход между документами (28.10.2026)

В sidebar MDok добавлен список **Documents récents** (до десяти путей за
текущую сессию). Он показывает Markdown/PDF-документы выбранного сервера,
позволяет вернуться к ранее открытому документу через существующий маршрут
`request("open")`, сохраняя проверку несохранённых изменений:
перед переходом требуется Save, явный отказ от изменений либо отмена.
Текущий документ выделяется. Список очищается при смене `serverId`,
не хранится на диске и не позволяет открывать путь от другого сервера.

**Граница:** это переключатель *недавних документов*, а не независимые
одновременные буферы/вкладки. Undo и несохранённые изменения не сохраняются
между такими переходами без обычного Save. Для полноценных вкладок потребуется
выделить состояние каждой вкладки в собственную документную сессию
(текст, base hash, token/serverId, recovery, timer, in-flight writes).
Не выдаём этот срез за готовую многодокументную архитектуру.

По решению владельца тесты и сборка отложены; отключённый GitHub Actions
workflow не восстанавливался.

### MD-06 continued — закреплённые вкладки навигации (28.10.2026)

Добавлена горизонтальная панель до восьми закреплённых документов с
индикацией активного файла и несохранённых правок, переключением по
нажатию и закрытием из панели. При переходе/закрытии активного файла
с несохранёнными правками используется существующая процедура
Save / Abandonner / Annuler; данные не отбрасываются молча. Вкладки
изолированы по текущему `serverId`, история живёт только в RAM.

**Важно:** это ещё **вкладки навигации**, не полноценные независимые
редактируемые буферы. Текущий `DocumentsController` остаётся
одно-документным. Переход к настоящим параллельным буферам требует
выделить отдельный контроллер и SSH-состояние на вкладку, а также
согласовать общесистемную защиту закрытия приложения со всеми
незавершёнными документами. Нельзя просто кешировать `text` и
`baseHash` в QML без безопасной изоляции операций записи.

Тесты и сборка по решению владельца не запускались; автоматический CI
удалён из GitHub в отдельном коммите.

### MD-07 — отдельные C++-сессии открытых документов (28.10.2026)

Начато реальное разделение буферов: корневой `DocumentsController`
может создавать `createTabSession()`; каждый объект содержит собственные
`text/base/hash`, SSH-эпоху, autosave, восстановление и состояние PDF.
QML сохраняет соответствие `serverId|path → DocumentsController` в
памяти текущей сессии и при выборе открытой вкладки переключает сам
контроллер, а не копирует только текст. Теперь можно оставить правки
в документе A и перейти к открытому B, не стирая A. Повторное открытие
этого пути возвращает прежний C++ объект.

Оболочка использует `hasDirtyTabs()/hasBusyTabs()` для учёта остальных
открытых сессий при запросах завершения/смены сервера. Закрытие вкладки
с несохранёнными правками или активной операцией пока не выполняется:
пользователь возвращается к этой вкладке. Важно: полная процедура
многодокументного Save / Discard / Cancel при **выходе из программы**,
корректная выгрузка чистых сессий и ограничение памяти ещё не закончены.
Следовательно, нельзя считать MD-07 завершённым или проверенным на
безопасность потери данных.

Тесты и сборка отложены по решению владельца, GitHub CI удалён.

### MD-07 — завершение работы с несколькими грязными вкладками (28.10.2026)

Добавлена `dirtyTabSessions()` в корневом DocumentsController:
оболочка может получить **все** несохранённые C++-сессии, а не
только текущую. `requestAllDocumentsReady()` последовательно переводит
пользователя на каждую несохранённую вкладку и предлагает существующие
Save / Abandonner / Annuler. Только когда список грязных вкладок пуст,
продолжается исходное действие выхода или отключения SSH. Отмена
прерывает последовательность; запись `unknown` не повторяется автоматически.
`releaseTabSession()` освобождает только чистую, незанятую дочернюю сессию.

Это **первый жизненный цикл**, не финальная сертификация: нужно
дополнительно проверить закрытие активной вкладки, изменение пути после
Save As, переключение сервера во время асинхронного сохранения и
интеграцию с глобальным guard выхода. CI удалён, тесты и сборка
отложены по решению владельца.

### MD-07 — закрытие вкладок и Save As (28.10.2026)

Исправлен жизненный цикл панели вкладок MDok. Закрытие активной чистой
вкладки теперь сначала переключает UI на другую сессию (или корневой
контроллер), а затем освобождает бывшую сессию, не оставляя QML
привязанным к объекту с отложенным удалением. Для грязной вкладки
вызывается существующее подтверждение Save / Abandonner / Annuler;
после подтверждения процедура закрытия повторяется с проверкой
текущего состояния. Выполняющаяся SSH-операция по-прежнему блокирует
закрытие.

После успешного Save As ключ `serverId|path` обновляется для текущей
C++-сессии: старое имя вкладки исключается из списка, новое
регистрируется и показывается. Дополнительно запрещён обход защиты
несохранённого **безымянного** документа при переходе на новую вкладку.

Незавершённые риски: полный многодокументный UX, конфликтующие попытки
открыть один и тот же путь через разные сессии, управление сервером
при смене поколения SSH и визуальная проверка. Сборка и тесты
отложены по решению владельца; GitHub CI не включался.

### MD-07 — повторное открытие и поколение SSH (28.10.2026)

В QML-карте открытых вкладок теперь учитывается не только `serverId`,
но и `connectionGeneration`: при смене SSH-поколения старые
привязки `path → DocumentsController` сбрасываются, и старый буфер
не выдаётся за актуальный документ повторного подключения.
Сами C++-сессии с несохранёнными изменениями сохраняются в памяти
под корневым контроллером и учитываются `hasDirtyTabs()` при выходе;
автоматической перепривязки к новой SSH-сессии нет.

Перед поиском уже открытого документа абсолютный путь приводится
к единому виду (повторные разделители, `.`, `..`) для предотвращения
нескольких вкладок одного пути. Ограничения: символические ссылки
внутри серверной файловой системы пока не объединяются в один
документ; открытие в другом SSH-поколении требует нового чтения.
Тесты/сборка отложены владельцем; CI не восстанавливался.

### MD-08 — доступ к черновикам после смены SSH-сессии (28.10.2026)

В sidebar MDok теперь показывается раздел **Brouillons en mémoire**:
в нём перечисляются все `dirtyTabSessions()` корневого C++-контроллера,
включая вкладки, исчезнувшие из обычной панели после смены поколения SSH.
Нажатие выбирает **исходный контроллер** и возвращает его текст в редактор;
не выполняется автоматическая перепривязка к новой сессии или запись на
удалённый сервер. Для недоступного источника показывается предупреждение.
Текст можно скопировать существующей командой копирования содержимого.

Раздел решает практическую проблему обнаружения несохранённого текста
после реконнекта, но **не** является безопасным `Save As` на новом
сервере: для этого необходима явная операция «создать копию» с
проверкой идентичности целевого SSH-сервера и политики конфликтов.
Хранение остаётся исключительно в RAM, поэтому аварийное завершение
клиента по-прежнему может привести к потере несохранённого текста.
CI отключён; Qt-сборка и тесты отложены по решению владельца.

### MD-08 — восстановить старый черновик как новый документ (28.10.2026)

Для черновика из недоступного SSH-поколения добавлено действие
**Récupérer comme nouveau…**. Корневой контроллер создаёт новую независимую
C++-сессию и вызывает `recoverAsNew(source)`: в неё копируется **снимок
текста**, без исходного base hash, пути, SSH-токена или обязательства записи.
Старый буфер остаётся без изменений и продолжает отображаться среди
черновиков в памяти. Новая сессия явно закрепляется за текущим SSH-сервером,
помечена как `isNew` и предлагает указать новый абсолютный путь Markdown;
обычный Save As публикует файл по существующей политике без молчаливой
перезаписи существующего имени.

Операция не работает при отсутствии соединения, активной SSH-записи
источника или превышении лимита Markdown. Ни один файл не создаётся в
момент копирования: до явного Save новая копия также хранится только
в RAM. Сборка и тесты сознательно отложены, GitHub CI отключён.

### MD-09 — независимые безымянные буферы (28.10.2026)

Команда **Nouveau** создаёт отдельную `DocumentsController`-сессию,
если уже открыт документ, вместо перезаписи текущего буфера. Незавершённые
безымянные документы остаются доступны в горизонтальной панели
`documentsUntitledTabs`, с индикатором правок и переключением по нажатию.
Длительное нажатие предлагает закрыть вкладку, используя существующее
подтверждение Save / Abandonner / Annuler для грязного буфера. После
успешного первого Save безымянная сессия переходит в обычные вкладки
по сохранённому пути. Восстановление старого черновика как нового
документа также регистрирует новую безымянную вкладку.

Это сохранение нескольких **RAM-буферов**, не гарантия пережить аварийное
завершение клиента. Новые безымянные документы не имеют серверного
autosave до первого Save. Важные незавершённые работы: проверка UI на
узких экранах, доступный способ закрывать вкладку без long-press,

### MD-09 — вкладки на узком экране (28.10.2026)

### MD-10 — панель форматирования для сенсорного экрана (28.10.2026)

Панель Markdown переработана из переносящего строки `Flow` в горизонтально прокручиваемый `Flickable` с фиксированной высотой. Кнопки имеют высоту 48 px в адаптивном режиме и 38 px на десктопе; это не заставляет область редактора прыгать при изменении ширины. Для адаптивного режима размер текста увеличен с 14 до 16 px. Действия форматирования (H1/H2, выделение, списки, цитата, код, ссылка, изображение, поиск) сохранены. Горизонтальная прокрутка оставляет доступными команды, не помещающиеся на планшете.

Это UI-изменение; работа с виртуальной клавиатурой и её реальными координатами на Android требует проверки на устройстве. По решению владельца сборка и тесты пока не запускались; CI остаётся отключённым.

### MD-11 — курсор и экранная клавиатура Android (28.10.2026)

MDok теперь централизованно поддерживает видимость курсора редактора с учётом смещения `TextEdit` внутри `Flickable` и отступов для сенсорного управления. Перепрокрутка выполняется при движении курсора, изменении высоты редактора, появлении/исчезновении экранной клавиатуры (`Qt.inputMethod.visibleChanged` и `keyboardRectangleChanged`). Переключение в режим предпросмотра на одном экране убирает фокус редактора и закрывает экранную клавиатуру; возврат в режим редактирования проверяет прокрутку.

Изменение не предполагает вручную вычитать высоту клавиатуры из окна: Android/Qt может самостоятельно корректировать доступную область, а принудительное вычитание ведёт к двойному уменьшению высоты. На реальном устройстве нужно проверить поведение с разными IME и режимом resize/pan. CI и тесты пока отложены по решению владельца.

### MD-12 — отделение предпросмотра от анализа текста (28.10.2026)

Ввод текста в MDok больше не запускает одним таймером все тяжёлые операции через 180 мс. Предпросмотр Markdown обновляется с debounce 420 мс **только когда панель предпросмотра видима**. Статистика, outline и поиск обновляются отдельно с debounce 650 мс. При переключении в предпросмотр выполняется принудительное планирование рендера актуального текста. Это уменьшает число полных Markdown-парсингов в режиме редактирования на узком экране. Операции остаются на UI thread, поэтому это не замена инкрементальному парсеру или асинхронному рендереру. Лимит превью 64 000 символов остаётся в C++.

Сборку, замеры и тесты по решению владельца пока не запускали; CI остаётся отключённым.

### MD-13 — пропуск повторного Markdown-парсинга за границей предпросмотра (28.10.2026)

В `MarkdownPreview::setSource()` сохраняется ограничение предпросмотра первыми 64 000 символами, но **полная реконструкция `QTextDocument` теперь пропускается**, если изменения затронули только текст после этой границы. Состояние `limited` обновляется отдельно при переходе через порог. Это уменьшает затраты на редактирование хвоста больших документов, не меняя фактическое содержимое редактора и серверное сохранение. При изменении отображаемых первых 64 000 символов Markdown по-прежнему парсится целиком.

Сборка, CI и тесты пока не выполнялись по решению владельца. Следующая оптимизация должна измеряться профилировщиком, прежде чем усложнять архитектуру инкрементальным рендерером.

### MD-14 — быстрые проверки перед regex-подсветкой (28.10.2026)

В `MarkdownSyntax::highlightBlock` добавлены дешёвые проверки наличия Markdown-разделителей до запуска четырёх циклов регулярных выражений для жирного/курсивного текста, ссылок и inline-code. Это локальная оптимизация; фактическое ускорение требует замеров на устройстве. CI отключён, сборка и тесты отложены по решению владельца.

### MD-15 — линейный scan структуры документа (28.10.2026)

Сохраняются точные смещения курсора, номера строк и UI-лимит в 200 заголовков. Разбор Markdown-текста по-прежнему линейный и выполняется после debounce; замеры и тесты пока не проводились. ### MD-16 — защита SSH-операций при завершении сессии (28.10.2026)
