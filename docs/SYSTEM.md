# Système — процессы, службы, обзор (первый срез, 23.10.2026)

Приложение только для чтения: показывает процессы, службы systemd и общую картину выбранного Linux-сервера. Ничего не запускает,
не останавливает и не «убивает».

## Что показывает

- **Processus:** имя (для интерпретаторов — имя скрипта, например `python3 fail2ban-server`), пользователь, PID/PPID, состояние (R, S, D, Z, T, I),
  CPU %, память %, RSS, число потоков, время работы, полная командная строка. Фильтр по имени, команде, пользователю или PID; сортировка по CPU, памяти,
  PID, имени; потоки ядра скрыты по умолчанию; «Auto 5 s» обновляет список. Выбранный процесс раскрывается с объяснением состояния.
  Источник: `ps -eo pid=,ppid=,user:32=,stat=,pcpu=,pmem=,rss=,etimes=,nlwp=,args= --sort=-pcpu` (первые 3000 строк).
- **Services:** все юниты `*.service` (`systemctl list-units --type=service --all`): состояние, подсостояние, описание; **юниты в состоянии failed — вверху** и счётчиком
  в меню; фильтры «Tous / Actifs / En échec / Inactifs» и текст. Без systemd окно честно говорит об этом.
- **Vue d'ensemble:** загрузка (1/5/15 мин) относительно числа ядер — сообщает, когда сервер насыщен; память и swap с полосой; аптайм; ОС и ядро;
  число процессов (в т. ч. zombie); состояние systemd и число служб в сбое (`/proc/loadavg`, `/proc/uptime`, `/proc/meminfo`, `nproc`, `os-release`).

## Правила

- Транспорт — SSH, POSIX `sh -s` на stdin; существующие утилиты; ни одна команда не меняет систему (тест проверяет отсутствие `kill`, `systemctl stop/start/restart/enable/disable/mask`,
  `renice`, `shutdown`, `reboot`, `sudo`, `rm`).
- Выход ограничен (4 Мио; процессов — 3000, служб — 2000); при усечении окно сообщает об этом.
- Одна постоянная SSH-сессия на все обновления; привязка к поколению сессии: смена сервера очищает окно.
- Окно не пишет задач в TaskManager (чтение, быстро); изменение процессов и служб будет задачами с подтверждением.
- Не вводится никакой эскалации: ничего не делается через `sudo`; процессы других пользователей видны как есть, права не повышаются.

## Реализация и проверки

`src/system/SystemInfo` (скрипт и разбор), `src/system/SystemController`, `qml/shell/SystemWindow.qml`.

- `fortiq_system` (12 тестов): настоящие выводы тестового Debian (`tests/fixtures/system/`), особые строки (поток ядра, zombie, командная строка с пробелами и юникодом, `-bash`,
  интерпретаторы, неполные строки), службы (маркер ●, описание с пробелами, `not-found`, мусор), разделы обзора, сборка снимка, отказ без `ps`, усечение 3000, форматы, скрипт без команд изменения.
- Живой тест `systemAppReadsTheServer` на Debian 13: обзор (ядра, доля памяти, аптайм), `init` и `sshd` в списке, порядок по CPU, systemd и `ssh.service`, повторное обновление по той же
  сессии, отсутствие задач, очистка при смене сессии.
- Layout-тест с подставным контроллером: скрытие потоков ядра, сортировка по PID, фильтр, раскрытие процесса, службы (failed вверху, фильтры), автообновление.

## Не сделано

Остановка/перезапуск служб, сигналы процессам, дерево процессов, графики во времени, службы пользователя (`systemctl --user`), потребление по сетевым соединениям, диски (есть в Disques).
Все изменения — отдельными срезами и только с подтверждением, проверкой прав (`sudo -n`) и записью в TaskManager. Android на устройстве не запускался.
