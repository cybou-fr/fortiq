# Готовность к выпуску: гейты, свидетельства, препятствия

Статус на 26.10.2026 (Production Sprint 1). Это рабочий документ, а **не подтверждение** прохождения проверок: гейт закрыт только если в колонке «Свидетельство» стоит воспроизводимый результат запуска именно на том коммите, который выпускается. Состав функций — [RELEASE_SCOPE_1_0](RELEASE_SCOPE_1_0.md). Подпись, установщик, обновления — [RELEASE](RELEASE.md). Лицензии — [THIRD_PARTY_LICENSES](THIRD_PARTY_LICENSES.md).

Принципы: недоступная или пропущенная обязательная проверка **блокирует** гейт, пока не выполнена либо не получила письменное исключение с причиной (`tool/gate_waivers.json`, видимо в отчёте); Windows может выйти отдельно, пока Android G5 не закрыт.

## Автоматические гейты (что исполняют скрипты)

| Команда | Что доказывает | Что делает с пропуском |
|---|---|---|
| `python tool/ci_check.py --qt-prefix … --toolchain …` | **офлайн-гейт**: документы, самотесты инструментов (`check_third_party`, `check_pins`, `check_test_results`, `make_sbom`), компиляция скриптов, закреплённые libssh2/OpenSSL в дереве vcpkg, сборка, `ctest`, затем `check_test_results.py` | пропуск без исключения, сбой, программа без итоговой строки (аварийное завершение) или меньше 10 файлов результатов = **провал**, хотя `ctest` назвал бы такой тест «Passed» |
| `python tool/prepare_live_fixture.py` (поднимает одноразовый Debian в WSL и запускает `run_live_tests.py`) | **живой гейт**: все наборы, требующие сервер | пропуск без исключения, действующего в области `live`, = **код возврата 1**; исключение печатается рядом с пропуском |
| `python tool/check_third_party.py --stage … / --apk …` | лицензии пакета: допустимые модули Qt, отладочные плагины, неизвестные DLL, тексты лицензий (в т. ч. `FORTIQ-LICENSE.txt`) | любое нарушение = код возврата 1; `package_windows.py` не создаёт пакет |
| `python tool/check_pins.py --vcpkg-root …` | в сборке именно закреплённые overlay-порты libssh2 `6e7b207` и OpenSSL 3.6.5#2 | другая версия или отсутствие порта = провал |

Исключения (`tool/gate_waivers.json`) имеют области `offline` / `live` / `release`. Тесты, которым нужен Linux-сервер, исключены только из офлайн-гейта; `twoHostsNeverMix` (второй одноразовый хост, WSL-дистрибутив `fortiq-test-b`) выполняется живым прогоном (`prepare_live_fixture.py` сам поднимает хост B); пропуск в живом прогоне теперь провал.

## Измеренные препятствия (от чего зависит следующий спринт)

Отсортировано по влиянию на выпуск; всё из таблицы выше, ничего не придумано заново.

1. **CI не доказан**: запустить на GitHub и получить зелёный прогон (G3). Требует push — решение владельца.
2. Повтор набора безопасности на **упакованных** бинарниках (G2); второй хост для `twoHostsNeverMix` уже подключён.
3. **Чистая Windows-машина и подпись** (G4): проверка — владельцем; сертификат — покупка владельца.
4. **Аудит репозитория перед публикацией** (G7): сканирование истории и тегов на секреты, права на ресурсы, документы сообщества.
5. **Визуальная приёмка и недостающие замеры** (G6).
6. **Android**: физическое устройство, подпись release (G5).

## Что сделано в Production Sprint 1

- Заявленный в стороннем разборе «синтаксический дефект» `tool/check_third_party.py` в этом дереве **не воспроизводится** (файл компилировался и до правок); реальная проблема другая: инструмент и документы считали FORTIQ закрытым продуктом под LGPL, а лицензия проекта — GPLv3. Инструмент переписан под политику `gpl3`/`lgpl` и отладочные плагины, проверяется самотестом на синтетическом наборе Qt (без установленного Qt).
- Windows CI больше не использует стандартный порт libssh2; закрепление версий проверяется скриптом и самотестом.
- `ctest` больше не скрывает пропуски и аварии: `check_test_results.py` читает файлы результатов QtTest; живой запуск возвращает 1 при пропуске без исключения.
- Документы: [RELEASE_SCOPE_1_0](RELEASE_SCOPE_1_0.md), этот файл; [THIRD_PARTY_LICENSES](THIRD_PARTY_LICENSES.md) и [RELEASE](RELEASE.md) приведены к GPL-3.0; `package_windows.py` кладёт `FORTIQ-LICENSE.txt` и предложение исходного кода в уведомления.
- **Не делалось**: Windows/Android квалификация, запуск CI на GitHub, смена видимости репозитория, подпись, новые функции.

## Локальная стабилизация 27.10.2026

Минимум Qt в CMake поднят до 6.9: оболочка использует `RectangularShadow`;
целевой kit остаётся 6.12. CTest ограничивает каждый офлайн-набор 120 секундами,
SSH/publication/gateway-live/engine-live — 600 секундами. Превышение — ошибка,
а не пропуск. Тестовые клиенты GatewayTest при отказе loopback записывают
явный FAIL с ошибкой сокета и сохраняют объект клиента, чтобы последующие
проверки не разыменовывали nullptr. Это исправление диагностики теста,
не свидетельство дефекта рабочего SSH-шлюза.

Предварительный прогон существующих Windows-бинарников в ограниченной среде
не прошёл: недоступны clipboard, Credential Manager и loopback, engine-live
завершился с 0xc0000135; layout-прогон прерван. Это не чистая сборка,
не квалификация Windows и не закрытие G2/G3/G4/G6.

Linux sanitizer CI переведён с системного Qt Ubuntu на kit 6.12,
без WebEngine; запуск на GitHub в этом срезе не выполнялся.

Проверка этого среза: отдельная чистая MSVC/Qt 6.12 сборка `GatewayTest.cpp`
с рабочими `HttpWire`/`ProxyGateway`/`UrlPolicy` — **110 passed, 0 failed,
0 skipped**. В ограниченной среде `missingOrWrongAuthIsRefused` завершился
обычным FAIL с `Cannot connect to the loopback test gateway: Socket operation
timed out`, без аварии. Документы (`check_docs_consistency.py`) и
`git diff --check` проходят. Полная сборка приложения не завершена:
регенерация старого `build-msvc` застряла в `qmlimportscanner` с сообщениями
об отсутствующих файлах `QtQuick/NativeStyle`; запуск остановлен. Таймауты
CTest и обновлённый workflow пока не проверены полным прогоном/на GitHub.
