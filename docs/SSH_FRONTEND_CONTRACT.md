# FORTIQ — обязательный архитектурный контракт

**Решение владельца продукта, 11 октября 2026 года. Нормативный документ.**
Любая противоречащая этому контракту реализация, постановка задачи или маркетинговое обещание подлежит исправлению. Этот документ описывает архитектурное направление, а не утверждает, что весь текущий код уже соответствует ему. Активный клиент — C++20/Qt 6/QML (прототип Flutter в теге `flutter-final`); фактические возможности и риски — в [QT_MIGRATION](QT_MIGRATION.md).

## 1. Одна архитектура, без альтернатив

**FORTIQ = только GUI / слой визуализации и управления.**
**Linux-сервер = backend, единственный источник рабочих данных, настроек и вычислитель.**

```text
                FORTIQ GUI (C++/Qt)
       отображение / ввод / команды пользователя
                         │
                         │ SSH
                         ▼
            Выбранный Linux-сервер
       существующие проверенные CLI-инструменты
       вычисления, рабочие данные, конфигурация
                         │
            файлы / демоны / почта / сеть
```

- **Вся предметная логика, обработка, поиск, индексация, преобразование, синхронизация и хранение рабочих данных — на Linux.** Клиент получает результат и отображает его; необходимые декодирование ответа и графический рендеринг относятся исключительно к представлению.
- **FORTIQ не является вычислительным backend, локальным файловым менеджером, почтовым движком, планировщиком задач, базой рабочих документов или копией серверного ПО.** Ни одна функция не получает альтернативный клиентский обработчик при недоступности сервера.
- **Все серверные настройки и действия настройки/развёртывания/обновления выполняются на Linux через SSH.** Сервер — источник истины для системной конфигурации, пользовательских рабочих данных, серверных настроек инструментов, сохранённых рабочих пространств и постоянных рабочих черновиков.
- **SSH — единственный рабочий транспорт сейчас.** SSH exec/shell/PTY для команд, SFTP как подсистема SSH для передачи файлов, SSH forwarding/SOCKS для сетевых представлений. Запрещены прямые клиентские SMTP/IMAP/POP3, API/REST, FTP/WebDAV, сокеты к рабочим системам и любой прямой fallback.
- В будущем другой транспорт допустим **только при реальной технической необходимости и отдельном решении**. Миграция с SSH, новый протокол и собственный сетевой стек не являются пунктами текущей дорожной карты.
- **Приоритет — уже существующие, зрелые, проверенные Linux-утилиты.** Мы проектируем удобный frontend поверх них, а не переписываем аналоги на C++ или изобретаем собственный серверный движок. Если утилита отсутствует, сначала обнаружить это, затем **предложить пользователю отдельно подтвердить установку** существующего пакета на Linux через SSH и проверить результат. Если нужной функции нет в зрелых CLI, решение откладывается до отдельного согласования; собственная CLI-обвязка возможна как исключение, но не как стандартная задача. Постоянно работающий агент и HTTP/RPC-сервер FORTIQ не нужны.
- **Экономика разработки:** повторно используем зрелые инструменты Linux, минимизируем код предметной логики, поверхность атаки и сопровождение. Готовая утилита не считается автоматически безопасной — версии, параметры, права, ввод и результат требуют проверки.

## 2. Минимально необходимое клиентское состояние

Разрешено в FORTIQ исключительно то, без чего графический клиент не может работать:
- UI/окна, пользовательский ввод, представление результатов в памяти, графический рендеринг (включая WebView), навигация, прогресс;
- необходимое для установления SSH соединения: адрес/профиль хоста, проверенные host keys, защищённые SSH credentials (минимальный bootstrap);
- покупка/лицензия Lemon Squeezy, защищённый ключ лицензии, необходимые для запуска клиента настройки и обновление **самого GUI**;
- кратковременный буфер редактирования **в оперативной памяти** для несохранённого пользовательского ввода. Никаких автоматических локальных копий рабочих данных на диск как основного сценария.

**Не переносить на клиент** постоянные рабочие конфигурации, почтовые ящики, документы, индекс поиска, историю задач, серверный scheduler, сохранённые рабочие пространства и серверные черновики. Их первичное и постоянное хранение — Linux, доступ по SSH. Любое локальное хранилище, которое появится в клиенте, не основание расширять клиентские данные сверх этого списка. Минимальный локальный bootstrap и лицензионные данные остаются исключением.

**Если SSH отсутствует:** можно открыть GUI подключения/лицензию, отобразить статус отключения и несохранённый ввод из оперативной памяти. Нельзя читать/синхронизировать/сохранять на диск рабочие файлы, выполнять почту, вычисления, поиск и операции с сервером. Не создавать скрытую локальную ветку исполнения.

## 3. Обязательный CLI-контракт каждого инструмента

Для каждой APP-функции обязательны: Linux-пакет и точная исполняемая команда; версия/feature discovery (`command -v`, flags, права); SSH-способ запуска; формат stdout/stderr и exit status; безопасные аргументы; таймаут, отмена и состояние `unknown` после обрыва; тест на Linux. Без проверенного серверного исполнителя функция не объявляется готовой.

Процесс: **выбрать проверенный CLI → проверить наличие/версию → отдельно запросить согласие перед установкой/обновлением → выполнить через SSH при подтверждённых правах → проверить CLI на Linux → написать тонкий GUI → интеграционный SSH-тест.**

Автоподготовка Linux принадлежит `ServerSetupService`: `apt`/`dpkg` и системные команды выполняются на сервере через SSH. Никаких клиентских установок, конфигурации серверных пакетов в обход SSH или прямых дополнительных API.

Эта таблица содержит **предпочтительные проверяемые исполнители**, а не обещание, что все пакеты доступны в любом дистрибутиве. Если зрелого инструмента не хватает, не писать отдельный backend автоматически; сначала выбирать проверенное Linux-решение или уточнять требования.

### Browser: исключение формы представления, не транспорта

Первый срез (решение владельца 23.10.2026) — GUI к `curl`, исполняемому на сервере: см. [BROWSER](BROWSER.md). Для будущего полноценного движка: локальный WebView рендерит веб-страницу, но соединения с сайтами должны идти **через SSH SOCKS** выбранного Linux-сервера, а не напрямую с клиентского устройства. Серверный `sshd` исполняет сетевой маршрут. Серверные автоматизированные запросы/вычисления делает Linux CLI (`curl` и др.). DNS, WebRTC, loopback, отказы и отсутствие fallback требуют e2e-проверки.

### Mail: жёсткий запрет прямых протоколов

**Клиент не открывает SMTP/IMAP/POP3 ни при каких обстоятельствах.**
`Mailbox UI → почтовый адаптер → SSH → Linux CLI (mail/sendmail/notmuch/mu/mbsync)`.
Выбранная Linux-программа вправе обращаться к внешнему почтовому серверу, исполняя протокол на Linux; это **не прямой клиентский сетевой адаптер FORTIQ**.

Для полноценной почты сначала исследовать возможности существующих CLI, затем интегрировать их через SSH. Собственная серверная почтовая программа не является обязательным архитектурным этапом. Если подходящей CLI нет, функция остаётся незавершённой до отдельного решения. Отправка **не записывает письмо в mbox вместо отправки**: сообщение передаётся по SSH stdin настоящему Linux `mail`/`sendmail`, отсутствие MTA означает ошибку. Нулевой exit code подтверждает только **приём команды**, не доставку адресату. Неизвестный результат после обрыва SSH нельзя превращать в успех или автоматически повторять.

### Опциональная Linux AI CLI: `ai` / llama.cpp (R2, P2)

**Отдельно согласованный, не реализованный сценарий:** на Linux
пользователь вызывает короткую команду `ai`, которая запускает **готовый
llama.cpp** (`llama-cli` либо проверенный эквивалент `llama cli`) с
компактной GGUF-моделью **на CPU**. FORTIQ исключительно отображает
контекст/совет и общается с `ai` только через **SSH**.

**Никакого постоянно работающего AI-демона, API/HTTP-порта или клиентского
inference.** Запуск только по запросу и после проверки ресурсов VPS.
AI устанавливается лишь при отдельном согласии пользователя; если VPS
слабый, AI отключён и остальные инструменты работают как обычно.
Модель ещё не выбрана до CPU-only бенчмарков.

**Кеш повторных советов:** на Linux внутри `ai` допускается ограниченный
кеш «точный вопрос + точный контекст + модель/параметры → ответ».
При совпадении и актуальном TTL ответ возвращается **без запуска llama.cpp**.
Кеш принадлежит выбранному серверу и Linux-пользователю, имеет границы по
объёму и сроку жизни; для чувствительных логов/конфигураций нужно отдельное
согласие. Возвращённый из кеша совет не заменяет актуальную системную
проверку. Безопасное локальное хранение и будущее шифрование at rest —
отдельная область требований.

AI только советует: никаких команд, перезапусков служб и изменений Linux,
выполняемых моделью автоматически. `ai` — разрешённая маленькая CLI-обвязка
над существующим runtime, не собственный inference engine. Полный контракт:
[AI_CLI](AI_CLI.md).

## 4. Будущее: надёжное шифрование данных на сервере в покое

**Целевая возможность, не текущий приоритет и не готовая функция.** В будущем рабочие данные и сохраняемые серверные настройки должны быть надёжно защищены **шифрованием at rest на Linux-сервере**.

Когда будет принято решение о реализации, отдельно спроектировать Linux-native механизм, управление ключами, восстановление, права доступа, резервные копии, ротацию и испытания угроз. Не обещать, что шифрование сейчас уже включено, не придумывать ключевую инфраструктуру и не блокировать текущий SSH/CLI frontend этапом шифрования. SSH уже шифрует **передачу**, но сам по себе **не шифрует данные на диске**.

## 5. Блокирующие правила code review и roadmap

1. Любой новый инструмент обязан ссылаться на конкретный готовый Linux CLI и SSH-интеграционные тесты.
2. Никаких новых предметных `HttpClient`/`Socket`, SMTP/IMAP/REST SDK, локальных почтовых клиентов и клиентских вычислительных движков. Lemon Squeezy HTTPS — отдельный **license control plane**, а не исключение для рабочих данных.
3. Нет client-side бизнес-кеша, локальной базы рабочих документов, локальной обработки и сохранения рабочих настроек в обход Linux.
4. Изменение/развёртывание на Linux только через SSH CLI и `ServerSetupService`, минимальные необходимые права, проверка результата и статус `unknown` вместо опасного повтора.
5. Без SSH рабочий GUI остаётся только представлением недоступного ресурса, не переключается на локальный backend.
6. Собственные серверные CLI/агенты, новый транспорт и инфраструктура шифрования **не планируются по умолчанию**. Требуют отдельного решения и доказанной необходимости.
7. Нельзя представлять проверенные Linux CLI как гарантию безопасности без тестирования версий, разрешений и сценариев отказа.
8. `docs/SSH_FRONTEND_CONTRACT.md` обязателен для всех документов и функций FORTIQ. Нарушение блокирует приемку.
