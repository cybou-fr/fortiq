# FORTIQ AI — концепция консольной команды `ai` (НЕ реализовано)

**Статус:** согласовано использовать **существующий Ollama на Linux** как единственный runtime первого эксперимента, с короткой пользовательской командой **`ai`**. Это план и проект CLI-контракта: ни Ollama, ни модель, ни `ai` пока не реализованы и не проверены в FORTIQ. AI необязателен и не блокирует R0/R1.

## 1. Единственная архитектура

```text
FORTIQ GUI (Explain / Diagnose / Suggest; только отображение)
                 │ SSH exec + stdin/stdout
                 ▼
 Linux: команда ai (тонкая CLI-обёртка)
                 │ локальный вызов Ollama CLI / loopback API
                 ▼
  Ollama service (127.0.0.1:11434) + CPU-модель
```

- **Имя команды — ровно `ai`**, не `fortiq-ai`. Ею можно пользоваться также через обычный SSH/терминал без FORTIQ.
- `ai` — тонкая CLI-обёртка над уже существующим **`ollama`**, а не собственный inference engine, модель, агент или платформа. Ollama обеспечивает загрузку/запуск модели и штатный Linux **systemd service**. 
- Для простых запросов обёртка может вызывать `ollama run`; для версионированного JSON и настроек inference допускается обращение **только с Linux-сервера** к штатному Ollama API на `127.0.0.1:11434`, например серверной CLI-командой `curl`. FORTIQ **никогда не обращается к порту 11434 напрямую**, даже через отдельный клиентский SDK.
- Модель, её файлы, временные рабочие файлы, настройки runtime и вычисления принадлежат **Linux-серверу**. Flutter не запускает модель, не обрабатывает логи моделью локально, не хранит AI-профили или копии документов и не обходит SSH.
- AI **только объясняет и советует**. Никакого выполнения предложенной команды, скрытого `sudo`, записи файла, изменения службы или запуска shell из вывода модели. Linux-действия остаются за обычными FORTIQ-сервисами и явным пользователем.
- **Ollama имеет собственный локальный HTTP listener и фоновый сервис**; это инфраструктура **самого Linux**, не API FORTIQ и не отдельный клиентский транспорт. Он обязан слушать **только 127.0.0.1:11434**, не `0.0.0.0`, не внешний адрес. Порт не публикуется в UFW/облачном firewall; необходимо проверить фактический bind и запретить чужим пользователям/процессам с недоверенным локальным доступом использовать сервис на общей машине. Никаких открытых внешних AI-портов, Flutter SDK к Ollama, Windows-модели или облачного API на первом этапе.
- При локальном использовании Ollama отключаем cloud-функции (`OLLAMA_NO_CLOUD=1`), чтобы модель не переключалась на удалённый inference. Скачивание модели разрешено **только после явного подтверждения установки**, штатным `ollama pull` на Linux.
- При отсутствии CLI/модели, отключённой функции, слабом CPU или нехватке памяти **FORTIQ работает как прежде**. AI не является зависимостью SSH, Files, Services, Logs, Editor, Mail и Server Setup.

Это узкое, **явно согласованное исключение** из общего предпочтения «не писать собственные Linux CLI»: добавляем только удобную команду `ai` над **готовым Ollama**. Никакого нового собственного серверного движка или API FORTIQ.

## 2. Контракт команды (проект интерфейса, требует интеграционных тестов)

| Команда | Семантика | Влияние на сервер |
|---|---|---|
| `command -v ai` | Обнаружение CLI без запуска inference | Только чтение |
| `ai status --json` | Состояние доступности, версия CLI/runtime/model, CPU/RAM, причина disabled/unavailable | Только чтение, без загрузки модели |
| `ai setup --check --json` | Проверка ресурсов, среды, источника модели и возможность установки | Только чтение |
| `ai setup` | После подтверждения ставит проверенную версию Ollama и модель через Linux/SSH, настраивает ограниченный loopback-only systemd service | Контролируемая серверная установка |
| `ai benchmark --json` | Ограниченный CPU-прогон через установленный Ollama; измерить ответ и влияние на сервисы | Временная CPU-нагрузка; Ollama service остаётся установлен |
| `ai ask --stdin --json` | Объяснение/совет по данным из stdin | Только чтение; ответ в stdout |
| `ai explain --stdin --json` | Объяснение **выбранного** фрагмента журнала/конфигурации, не произвольное чтение сервера | Только чтение; ответ в stdout |

Приведённые subcommands — **контракт нашей обёртки `ai`**, а не встроенные подкоманды Ollama: штатные CLI — `ollama --version`, `ollama list`, `ollama ps`, `ollama pull`, `ollama run`, `ollama stop`; формат и параметры перепроверить на закреплённой версии. Пользовательская интерактивная форма `ai ask "вопрос"` возможна в терминале, но **FORTIQ всегда передаёт рабочие данные через stdin**, не через argv, историю shell, временный файл или лог.

Пример желаемого `ai status --json`:

```json
{
  "schema": "fortiq-ai-status/v1",
  "available": false,
  "reason": "insufficient_resources",
  "runtime": null,
  "model": null
}
```

Пример `ai ask --stdin --json`:

```json
{
  "schema": "fortiq-ai-advice/v1",
  "status": "ok",
  "advice": "Проверить конфигурацию службы",
  "caution": "Это гипотеза, не результат системной проверки"
}
```

Формат ответа версионируется, ошибка/нехватка ресурсов идут через явный код завершения и структуру ошибки; stderr — для диагностики без секретов. Долгий запуск должен поддерживать отмену, жёсткие лимиты времени и вывода; обрыв SSH не приводит к автоматическому повтору или фоновой генерации. Запрещено интерпретировать ответ модели как shell-скрипт.

## 3. CPU-only и политика доступности

**Не рекомендуем слабые VPS специально ради AI.** Обычные функции FORTIQ не требуют LLM; отсутствие AI не делает VPS «несовместимым с FORTIQ».

- Серверный GPU не требуется и **не предполагается**. Выбор происходит по фактическим параметрам **CPU-only**: архитектура и инструкции процессора, доступное RAM (`MemAvailable`), **cgroup/VM memory limit**, свободный диск и фоновая нагрузка; не только по общему объёму RAM.
- VPS с **1–2 ГБ RAM** по умолчанию **без AI**. От **4 ГБ** можно лишь рассматривать компактную модель после проверки **реально свободной** памяти и CPU; **8 ГБ+ не гарантия** полезной скорости. Это предварительная политика включения, а не обещание работоспособности.
- Ollama — выбранный runtime, но **модель ещё не выбрана**. Перед рекомендацией подтвердить конкретный Ollama tag и квантование, лицензию распространения, пик RAM (включая контекст/KV cache), CPU-потребление, задержку ответа, tokens/s и влияние на работающие сервисы на **реальных CPU-only VPS**.
- Первый пилот проверяет **малую CPU-ориентированную модель**, но **не фиксирует** ни Qwen, ни какой-либо размер параметров без бенчмарка. При неприемлемой скорости/памяти `ai status` возвращает `available: false` с ясной причиной.
- Inference **только on demand**: без периодической генерации, автоскачивания и фоновой модели. Сервис Ollama может работать постоянно, но **модель должна выгружаться сразу или быстро после запроса**, например через `OLLAMA_KEEP_ALIVE=0`; ограничиваем `OLLAMA_NUM_PARALLEL=1`, максимум загруженных моделей, CPU/RAM, контекст, время выполнения и конкурирующую нагрузку. Проверить, что настройка действительно действует на выбранной версии и `ollama ps` не показывает оставшуюся модель. При недостатке ресурсов — выключить AI, GUI не блокировать.

### Ollama: минимальная конфигурация (целевые требования, не готовый installer)

- Дистрибутив Debian/Ubuntu, пакет и сервис Ollama устанавливаются **на Linux** только после отдельного согласия пользователя. Не трогать уже установленную Ollama без проверки версии/существующих моделей и настроек.
- Проверить `command -v ollama`, `ollama --version`, `ollama list`, `ollama ps`, `systemctl status ollama` и `ss -ltn` для bind; запретить доступ к API извне VPS. Служба Ollama по умолчанию использует loopback 127.0.0.1:11434; после установки проверить реально, не предполагать.
- Ограничить Ollama сервис параметрами `OLLAMA_HOST=127.0.0.1:11434`, `OLLAMA_NO_CLOUD=1`, `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_KEEP_ALIVE=0`; для других параметров и systemd лимитов — отдельный тест под VPS. Не включать cloud-режим и remote models автоматически.
- **Кандидаты только для замеров:** `qwen2.5:0.5b` (файл ~398 МБ), `qwen2.5:1.5b` (~986 МБ); **файловый размер ≠ runtime RAM и ≠ полезная скорость**. На 4 ГБ нельзя гарантировать даже 1.5B до CPU/памяти теста. 0.5B может быть недостаточно качественной для диагностики. Ни один кандидат не фиксируется как рекомендуемая модель до испытаний.
- `ai` работает как небольшая CLI-обвязка к `ollama run` либо локальному Ollama API **с Linux**, а машинный JSON в требуемом формате нормализует эта обвязка. Ollama сам по себе **не предоставляет** команды `ai status` или `ai explain`.

Источник для последующей реализации: [Linux install](https://docs.ollama.com/linux), [CLI](https://docs.ollama.com/cli), [Ollama FAQ](https://docs.ollama.com/faq), [qwen2.5:0.5b](https://ollama.com/library/qwen2.5:0.5b), [qwen2.5:1.5b](https://ollama.com/library/qwen2.5:1.5b).

## 4. Первые сценарии GUI

**Первый эксперимент:** контекстная кнопка «Explain with AI» в существующих **Logs** и **Services**. Flutter через SSH получает данные обычными Linux CLI, показывает выбранный фрагмент, затем по явному нажатию отправляет только **этот фрагмент** в `ai explain --stdin --json`. Ответ показывает объяснение, возможную причину и шаги **для ручной проверки**.

Позже, только при успешном пилоте: Editor («объясни выбранный конфиг») и Terminal («предложи команду, но не выполняй»). Новое обязательное отдельное AI-приложение в dock не требуется; нет автоматического обхода файловой системы и массовой индексации для AI.

Истиной остаются `systemctl`, `journalctl`, `nginx -t` и другие системные CLI, **не** ответ LLM. Недоверенные тексты логов/файлов нельзя трактовать как инструкции; ограничить объём контекста, санитизировать отображение, не допускать вывода секретов и опасных рекомендаций без предупреждений.

## 5. Установка, приватность и деньги

- `ai`, Ollama, модель и серверные настройки устанавливаются **на Linux через SSH** в существующем согласованном процессе `ServerSetupService` **только после явного выбора пользователем**. Обычный Server Setup и новые версии FORTIQ не включают AI автоматически.
- `ai` отдельно версионируется; перед установкой проверить занятость имени `ai` в PATH и **не перезаписывать чужую команду**. При установке Ollama не запускать скачанный shell-скрипт вслепую: предварительно выбрать проверенный официальный пакет/версию, проверить происхождение и обновление. Модель устанавливается штатным `ollama pull` только с разрешения пользователя; закрепить точный tag и проверять лицензию.
- Содержимое серверных файлов/логов не передаётся внешним AI-провайдерам. Модель работает на том же Linux-хосте. Не сохранять prompts/responses по умолчанию. Будущее подключение внешнего API требует отдельного решения о ключах, consent, приватности и расходах, и выполняется **со стороны Linux**, не клиентским SDK.
- **Intro и Pro сохраняют одинаковые доступные возможности**; AI доступен в обоих при достаточных ресурсах и если пользователь сам включил его. Тарифы **2 € / 14 дней** и **39,90 € / год** не меняются; стоимость inference на CPU пользователя — не облачный расход FORTIQ.

## 6. Приёмка эксперимента и запреты

AI-проба принята только если:

1. CPU-only VM/VPS: документированный измеренный memory peak и скорость на конкретных конфигурациях; слабые VPS получают корректный `disabled`, без OOM и торможения основных инструментов.
2. `ai status` ничего не скачивает/меняет; `ai setup` требует отдельного подтверждения; установка проверена на disposable Linux.
3. CLI корректно принимает stdin, возвращает машинно-читаемый ответ/ошибку, выдерживает отказ, таймаут и обрыв SSH; **Ollama service работает на Linux только на `127.0.0.1:11434`**, внешний порт закрыт, клиент FORTIQ подключается **только по SSH**. Нет автоматической отправки наружу.
4. Logs/Services остаются полностью рабочими, когда AI выключен; AI не выполняет никакие команды по своим советам.
5. Качество: ответы на наборе реальных, обезличенных ошибок Linux помогают понять проблему; ответы не принимаются за проверки и должны ясно обозначать неопределённость.

**Приоритет:** R2 / исследовательский P2, **не блокирует R0/R1, коммерческий релиз и обычный Server Setup**. Runtime — **Ollama**, но модель/CPU-порог утверждаются только после испытаний; до тех пор в документации и на сайте не обещать «AI included» как готовую функцию.
