# FORTIQ AI — концепция консольной команды `ai` (НЕ реализовано)

**Статус:** согласованное направление документации, опциональный эксперимент после основных R0/R1. Не входит в обязательный функционал первого коммерческого выпуска. Никакая модель, CPU-runtime, команда `ai` или автоматическая установка пока не выбраны как готовая реализация.

## 1. Единственная архитектура

```text
FORTIQ GUI (Explain / Diagnose / Suggest; только отображение)
                 │ SSH exec + stdin/stdout
                 ▼
      Linux: команда ai
                 │ локальный CPU inference
                 ▼
   существующий поддерживаемый runtime + компактная модель
```

- **Имя команды — ровно `ai`**, не `fortiq-ai`. Ею можно пользоваться также через обычный SSH/терминал без FORTIQ.
- `ai` — минимальная **CLI-обвязка/адаптер**, а не наш собственный inference engine, сетевой AI-сервер, агент или постоянный демон. Использует проверяемый готовый CPU-runtime, который ещё предстоит выбрать по тестам.
- Модель, её файлы, временные рабочие файлы, настройки runtime и вычисления принадлежат **Linux-серверу**. Flutter не запускает модель, не обрабатывает логи моделью локально, не хранит AI-профили или копии документов и не обходит SSH.
- AI **только объясняет и советует**. Никакого выполнения предложенной команды, скрытого `sudo`, записи файла, изменения службы или запуска shell из вывода модели. Linux-действия остаются за обычными FORTIQ-сервисами и явным пользователем.
- Никаких открытых TCP-портов, REST/HTTP endpoint, фонового inference, локальной Windows-модели или облачного AI в первой реализации. Новый транспорт и внешний AI API — отдельные будущие решения, не создающие исключения для прямых рабочих сетевых соединений из Flutter.
- При отсутствии CLI/модели, отключённой функции, слабом CPU или нехватке памяти **FORTIQ работает как прежде**. AI не является зависимостью SSH, Files, Services, Logs, Editor, Mail и Server Setup.

Это узкое, **явно согласованное исключение** из общего предпочтения «не писать собственные Linux CLI»: добавляется только общая простая команда `ai`, не собственная LLM, не отдельный backend FORTIQ.

## 2. Контракт команды (проект интерфейса, требует интеграционных тестов)

| Команда | Семантика | Влияние на сервер |
|---|---|---|
| `command -v ai` | Обнаружение CLI без запуска inference | Только чтение |
| `ai status --json` | Состояние доступности, версия CLI/runtime/model, CPU/RAM, причина disabled/unavailable | Только чтение, без загрузки модели |
| `ai setup --check --json` | Проверка ресурсов, среды, источника модели и возможность установки | Только чтение |
| `ai setup` | Установка проверенного runtime/модели **по отдельному явному подтверждению**; не при обычном SSH-входе | Контролируемая серверная установка |
| `ai benchmark --json` | Небольшой ограниченный CPU-прогон после установки; решение о доступности/скорости | Временная нагрузка, без постоянной службы |
| `ai ask --stdin --json` | Объяснение/совет по данным из stdin | Только чтение; ответ в stdout |
| `ai explain --stdin --json` | Объяснение **выбранного** фрагмента журнала/конфигурации, не произвольное чтение сервера | Только чтение; ответ в stdout |

Приведённые subcommands — **целевой контракт**, не подтверждение совместимости с конкретной моделью. Пользовательская интерактивная форма `ai ask "вопрос"` возможна в терминале, но **FORTIQ всегда передаёт рабочие данные через stdin**, не через argv, историю shell, временный файл или лог.

Пример желаемого `ai status --json`:

```json
{
  "schema": "fortiq-ai-status/v1",
  "available": false,
  "reason": "insufficient_resources",
  "runtime": null,
  "model": null
}
```

Пример `ai ask --stdin --json`:

```json
{
  "schema": "fortiq-ai-advice/v1",
  "status": "ok",
  "advice": "Проверить конфигурацию службы",
  "caution": "Это гипотеза, не результат системной проверки"
}
```

Формат ответа версионируется, ошибка/нехватка ресурсов идут через явный код завершения и структуру ошибки; stderr — для диагностики без секретов. Долгий запуск должен поддерживать отмену, жёсткие лимиты времени и вывода; обрыв SSH не приводит к автоматическому повтору или фоновой генерации. Запрещено интерпретировать ответ модели как shell-скрипт.

## 3. CPU-only и политика доступности

**Не рекомендуем слабые VPS специально ради AI.** Обычные функции FORTIQ не требуют LLM; отсутствие AI не делает VPS «несовместимым с FORTIQ».

- Серверный GPU не требуется и **не предполагается**. Выбор происходит по фактическим параметрам **CPU-only**: архитектура и инструкции процессора, доступное RAM (`MemAvailable`), **cgroup/VM memory limit**, свободный диск и фоновая нагрузка; не только по общему объёму RAM.
- VPS с **1–2 ГБ RAM** по умолчанию **без AI**. От **4 ГБ** можно лишь рассматривать компактную модель после проверки **реально свободной** памяти и CPU; **8 ГБ+ не гарантия** полезной скорости. Это предварительная политика включения, а не обещание работоспособности.
- Прежде чем рекомендовать конкретную модель, подтвердить CPU-runtime, точный файл/квантование, лицензию распространения, пик RAM (включая контекст/KV cache), CPU-потребление, задержку первого ответа, tokens/s и влияние на уже работающие сервисы на **реальных CPU-only VPS**.
- Первый пилот проверяет **малую CPU-ориентированную модель**, но **не фиксирует** ни Qwen, ни какой-либо размер параметров без бенчмарка. При неприемлемой скорости/памяти `ai status` возвращает `available: false` с ясной причиной.
- Работа модели **on demand**: никаких запусков при открытии окна, периодического inference, автоскачивания и автопереключения на чужой API. Ограничить число CPU threads, память, контекст, время и параллельность; избегать swap-thrashing/OOM. При недоступности — выключить AI, не блокировать сервер и GUI.

## 4. Первые сценарии GUI

**Первый эксперимент:** контекстная кнопка «Explain with AI» в существующих **Logs** и **Services**. Flutter через SSH получает данные обычными Linux CLI, показывает выбранный фрагмент, затем по явному нажатию отправляет только **этот фрагмент** в `ai explain --stdin --json`. Ответ показывает объяснение, возможную причину и шаги **для ручной проверки**.

Позже, только при успешном пилоте: Editor («объясни выбранный конфиг») и Terminal («предложи команду, но не выполняй»). Новое обязательное отдельное AI-приложение в dock не требуется; нет автоматического обхода файловой системы и массовой индексации для AI.

Истиной остаются `systemctl`, `journalctl`, `nginx -t` и другие системные CLI, **не** ответ LLM. Недоверенные тексты логов/файлов нельзя трактовать как инструкции; ограничить объём контекста, санитизировать отображение, не допускать вывода секретов и опасных рекомендаций без предупреждений.

## 5. Установка, приватность и деньги

- `ai`, runtime, модель и серверные настройки устанавливаются **на Linux через SSH**, в существующем согласованном процессе `ServerSetupService` **только после явного выбора пользователем**. Обычный Server Setup и новые версии FORTIQ не включают AI автоматически.
- `ai` должен быть отдельно версионированным; перед установкой проверять занятость имени `ai` в PATH и **не перезаписывать чужую команду**. Путь/дистрибуция и политика обновлений — отдельная задача перед реализацией; загрузка модели только из проверенного источника с контрольной суммой и лицензионной проверкой.
- Содержимое серверных файлов/логов не передаётся внешним AI-провайдерам. Модель работает на том же Linux-хосте. Не сохранять prompts/responses по умолчанию. Будущее подключение внешнего API требует отдельного решения о ключах, consent, приватности и расходах, и выполняется **со стороны Linux**, не клиентским SDK.
- **Intro и Pro сохраняют одинаковые доступные возможности**; AI доступен в обоих при достаточных ресурсах и если пользователь сам включил его. Тарифы **2 € / 14 дней** и **39,90 € / год** не меняются; стоимость inference на CPU пользователя — не облачный расход FORTIQ.

## 6. Приёмка эксперимента и запреты

AI-проба принята только если:

1. CPU-only VM/VPS: документированный измеренный memory peak и скорость на конкретных конфигурациях; слабые VPS получают корректный `disabled`, без OOM и торможения основных инструментов.
2. `ai status` ничего не скачивает/меняет; `ai setup` требует отдельного подтверждения; установка проверена на disposable Linux.
3. CLI корректно принимает stdin, возвращает машинно-читаемый ответ/ошибку, выдерживает отказ, таймаут и обрыв SSH; нет daemon/порта/API и автоматической отправки наружу.
4. Logs/Services остаются полностью рабочими, когда AI выключен; AI не выполняет никакие команды по своим советам.
5. Качество: ответы на наборе реальных, обезличенных ошибок Linux помогают понять проблему; ответы не принимаются за проверки и должны ясно обозначать неопределённость.

**Приоритет:** R2 / исследовательский P2, **не блокирует R0/R1, коммерческий релиз и обычный Server Setup**. Кандидат-модель и runtime утверждаются только после сравнительных тестов CPU-only; до тех пор в документации и на сайте не обещать «AI included» как готовую функцию.
