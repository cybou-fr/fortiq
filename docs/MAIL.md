# Courrier — чтение и теги поверх notmuch (первый срез, 23.10.2026)

Приложение — графический интерфейс к существующему `notmuch` на выбранном Linux-сервере (требование проекта: почтовые аккаунты, IMAP/SMTP и синхронизация живут на сервере, клиент
FORTIQ к почтовым серверам не подключается). Письма на сервер доставляет собственный инструмент пользователя (например `mbsync`) и индексирует `notmuch new`; **этот срез их не
запускает и не настраивает**. Исследование: [APPS_RESEARCH](APPS_RESEARCH.md), композиция `mbsync` + `notmuch` + `msmtp` остаётся целевой.

## Что умеет

- **Папки** (по тегам): Boîte de réception (`tag:inbox`), Non lus, Suivis (`flagged`), Envoyés, Corbeille (`deleted`), Tous; счётчики сообщений (`notmuch count`).
- **Список бесед** (`notmuch search --format=json`, новые сверху, страницы по 100 + «Plus de conversations»), поиск на языке notmuch (`from:`, `subject:`, `tag:`…) внутри выбранной папки.
- **Чтение беседы** (`notmuch show --format=json --include-html --entire-thread`): заголовки уже декодированы (RFC 2047, кодировки вроде ISO-8859-1), ответы с отступом, письма вне запроса приглушены,
  `text/plain` показан как текст; если есть только HTML (или нажата «Afficher la version HTML») — **безопасный HTML** тем же `HtmlSanitizer`, что в Navigateur: без скриптов, стилей, форм
  и удалённых изображений (картинка заменяется её alt-текстом), только ссылки http(s), которые **не открываются** (адрес виден при наведении) — прямого выхода клиента в сеть нет.
  Вложения перечислены по имени; **скачивание вложений в этом срезе не реализовано**.
- **Теги — единственные изменения:** прочитано/не прочитано, «suivi», архив (убрать `inbox`), корзина (`deleted` — только метка, письма не удаляются). Беседа, открытая из списка, помечается прочитанной
  (настройка `mail/markReadOnOpen`). Менять можно только эти четыре тега; другие значения и неверные идентификаторы до сервера не доходят.
  `notmuch tag` переименовывает файлы Maildir (флаги `:2,S`/`F`) — штатное поведение notmuch (`maildir.synchronize_flags`).

## Правила

- Транспорт — SSH, POSIX `sh -s` на stdin; запрос, идентификатор беседы и теги — данные: одинарные кавычки и `--` перед запросом (проверено живым тестом: запрос с `$(…)`, обратными кавычками и `;` ничего не исполняет).
  Идентификатор беседы — только hex; тег — `[A-Za-z0-9][A-Za-z0-9_.-]*`; запрос ≤ 500 символов без управляющих.
- Не запускаются `notmuch new`, `mbsync`, `msmtp`, `rm`, `sudo` (тест просматривает скрипты).
- Одна постоянная SSH-сессия; задания идут по очереди (новый поиск/беседа вытесняет устаревшие в очереди); смена сервера очищает окно.
- Нестандартная конфигурация: `NOTMUCH_CONFIG` (свойство `configPath`, настройка `mail/notmuchConfig`; окна для неё пока нет).
- Если `notmuch` не установлен или не настроен — явное сообщение («notmuch setup», «notmuch new»), без угадываний.
- Окно не пишет задач в TaskManager (быстрые чтения и единичные теги); отправка и синхронизация будут задачами.

## Реализация и проверки

`src/mail/MailInfo` (скрипты, проверка, разбор JSON, безопасный HTML), `src/mail/MailController`, `qml/shell/MailWindow.qml`, фикстура `tool/make_mail_fixture.sh` → `tests/fixtures/mail/` (настоящие выводы notmuch 0.39).

- `fortiq_mail` (14 тестов): проверка запросов/тегов/id, скрипты (кавычки, `--`, нет опасных команд), список бесед, беседа с ответом и HTML, вложения и quoted-printable, письмо только с HTML (скрипты, обработчики,
  `javascript:`, удалённые картинки удалены, https-ссылка сохранена), ISO-8859-1, без темы, мусорный JSON, глубокая вложенность, обзор и ошибки, даты.
- Живой тест `mailAppReadsAndTags` (нужны `FORTIQ_IT_MAIL=1` и `notmuch` на сервере): база строится скриптом фикстуры; счётчики папок, поиск, инъекция в запрос, чтение беседы, пометка «прочитано» при открытии,
  вложения, HTML-письмо, теги (suivi, архив) с проверкой на сервере, запрещённые теги/идентификаторы, неверный путь конфигурации, очистка при отключении.
- Layout-тест с подставным контроллером: список, поиск, чтение, кнопки тегов, папки.

## Не сделано

Отправка (`msmtp`), ответ/пересылка/черновики, мастер аккаунта (`~/.mbsyncrc`, `~/.msmtprc`) и запуск синхронизации из приложения, скачивание вложений в Files, открытие ссылок через Navigateur, подписи/шифрование (PGP),
настоящее удаление, окно для `NOTMUCH_CONFIG`, TaskManager. Решение владельца ещё нужно: где хранить пароли IMAP/SMTP на сервере (файл 0600 или менеджер). Android на устройстве не проверялся.
