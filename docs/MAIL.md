# Courrier — чтение, теги, отправка, мастер аккаунта и вложения (срезы 1–3, 23.10.2026)

Приложение — графический интерфейс к существующим `notmuch`, `msmtp` и `mbsync` на выбранном Linux-сервере (требование проекта: почтовые аккаунты, IMAP/SMTP и синхронизация живут на сервере,
клиент FORTIQ к почтовым серверам не подключается). Собственных серверных агентов нет. Исследование: [APPS_RESEARCH](APPS_RESEARCH.md); композиция `mbsync` (получение) + `notmuch` (индекс, чтение, теги) +
`msmtp` (отправка).

## Срез 1 — чтение и теги

- **Папки** (по тегам): Boîte de réception (`tag:inbox`), Non lus, Suivis (`flagged`), Envoyés, Corbeille (`deleted`), Tous; счётчики сообщений (`notmuch count`).
- **Список бесед** (`notmuch search --format=json`, новые сверху, страницы по 100 + «Plus de conversations»), поиск на языке notmuch (`from:`, `subject:`, `tag:`…) внутри выбранной папки.
- **Чтение беседы** (`notmuch show --format=json --include-html --entire-thread`): заголовки декодированы (RFC 2047, кодировки вроде ISO-8859-1), ответы с отступом, письма вне запроса приглушены,
  `text/plain` показан как текст; если есть только HTML (или нажата «Afficher la version HTML») — **безопасный HTML** тем же `HtmlSanitizer`, что в Navigateur: без скриптов, стилей, форм
  и удалённых изображений (картинка заменяется alt-текстом), только ссылки http(s), которые **не открываются** (адрес виден при наведении) — прямого выхода клиента в сеть нет.
  Вложения перечислены по имени (срез 3 — как их сохранить, см. ниже).
- **Теги:** прочитано/не прочитано, «suivi», архив (убрать `inbox`), корзина (`deleted` — только метка, письма не удаляются). Беседа, открытая из списка, помечается прочитанной
  (настройка `mail/markReadOnOpen`). Менять можно только эти четыре тега; `notmuch tag` переименовывает файлы Maildir (флаги `:2,S`/`F`) — штатное поведение notmuch.

## Срез 2 — отправка

- **Новое сообщение / Répondre** (кнопки ✎ и «Répondre»): поля От (аккаунт msmtp), À, Cc, Cci, Объект, текст. Ответ подставляет получателя, «Re: …», цитату и `In-Reply-To`/`References`.
- **Сообщение строится на клиенте** (`MailSend`): заголовки (RFC 2047 для не-ASCII имён и темы), `Date`, `Message-ID`, UTF-8 в base64; Cci — только в конверте. Адреса — ASCII `имя@домен`
  (проверка, любые управляющие символы и переводы строк отклоняются — защита от инъекции заголовков); ≤ 50 получателей, тело ≤ 1 Мио.
- **Отправка** — `msmtp -a <аккаунт> -- <получатели>`: сообщение идёт на stdin **внутри скрипта** (heredoc со случайным разделителем, временный файл 0600), получатели — в одинарных кавычках, никаких данных
  в командной строке. Аккаунты берутся из `~/.msmtprc` (только строки `account`/`from`; пароль не читается). После успеха — копия `notmuch insert --folder=Sent +sent -unread` и тег `replied` у исходного письма.
- **Исходы честные:** `0` отправлено и скопировано; `11` отправлено, но копия не сохранена (предупреждение); `10` не отправлено (понятная причина: аутентификация, соединение, TLS, адресат отклонён);
  `12` тайм-аут — **«неизвестно»**, письмо не считается ни отправленным, ни нет, автоповтора нет. Обрыв SSH во время отправки — тоже «неизвестно» (задача `mailSend` в TaskManager, не отменяема).

## Срез 2 — мастер аккаунта (запись конфигурации на сервер)

Пароли IMAP/SMTP — **в файлах на сервере, режим 0600** (решение владельца 23.10.2026). Запись только с согласия:

1. Форма: имя аккаунта, имя и адрес, IMAP (сервер, порт, SSL/TLS | STARTTLS | без шифрования только для localhost), SMTP (то же), пользователь, пароль (SMTP-пароль отдельно по желанию).
2. **«Aperçu des fichiers»** строит **точный текст** файлов и ничего не пишет: `~/.mbsyncrc` (получение, **Sync Pull**, `Expunge None`: сервер почты не изменяется), `~/.msmtprc` (отправка), и
   `~/.notmuch-config` — только если его нет. Пароль в предпросмотре замаскирован; флажок «Révéler» показывает точный текст.
3. По каждому файлу — свой флажок, затем **отдельное подтверждение** («J'ai relu le contenu exact…») и кнопка «Écrire sur le serveur». Пока подтверждения нет, кнопка неактивна.
4. Существующие файлы **не заменяются целиком**: FORTIQ ведёт только свой блок между строками `# >>> FORTIQ account <имя>` / `# <<< …`; остальное содержимое сохраняется, перед записью — копия
   `<файл>.fortiq-bak-<время>`, запись через временный файл и `mv`, режим 0600 (в т. ч. исправляет 0644). `~/.notmuch-config` никогда не перезаписывается.
5. После записи пароль удаляется из памяти клиента (предпросмотр очищается), поля пароля стираются; смена или отключение сервера тоже очищают предпросмотр.

Особенности, проверенные на живых инструментах: msmtp читает ` #` как комментарий, поэтому пароль записывается в кавычках без экранирования (внутри `"…"` он берётся до последней кавычки строки);
mbsync требует экранирования `\` и `"`. Не поддерживаются пароли с переводом строки/управляющими символами, с пробелом в начале/конце и начинающиеся с `"` — об этом сообщается до предпросмотра.
Без TLS msmtp отказывается от `auth on`: для localhost без шифрования записывается `auth cram-md5` (остальным нужен TLS).

- **«Tester SMTP»** (`msmtp --serverinfo`: соединение, TLS, поддерживаемые методы), **«Tester IMAP»** (`mbsync -l`: вход и список ящиков), **«Relever maintenant»** (`mbsync <аккаунт>`, затем `notmuch new`; задачи, отмена).

## Срез 3 — вложения (они остаются на сервере)

Письма и вложения лежат на сервере, клиент к почте не подключается. Поэтому у каждого вложения две кнопки:

- **«Sur le serveur»** — декодированная часть (`notmuch show --format=raw --part=N`) записывается в `~/Downloads` на сервере (режим 0644). Существующие файлы не перезаписываются: `имя (1).ext`, `имя (2).ext`…
  Результат — полный путь на сервере (дальше его можно открыть в Files).
- **«Sur ce poste…»** — выбор места на этом компьютере (диалог «Сохранить как»). Часть сначала извлекается во **временную копию на сервере** (`~/.cache/fortiq-mail/att.XXXXXX`, режим 0600), затем идёт
  **обычная задача скачивания Files** (SFTP: прогресс, отмена, запрос при конфликте имён — существующий файл не перезаписывается), и **после завершения задачи (любой исход) временная копия удаляется**;
  забытые копии старше суток удаляются при следующем извлечении. Удаляется только каталог `…/.cache/fortiq-mail/att.XXXXXX` (проверка и на клиенте, и в скрипте).
- **Имя файла** очищается на клиенте: без `/ \ : * ? " < > |`, управляющих символов, ведущих точек (`../../etc/x` → `_.._etc_x`), ≤ 120 символов (расширение сохраняется), имя — в одинарных кавычках скрипта.
- Пустая или отсутствующая часть, неизвестное письмо → явное сообщение, ничего не создаётся. Нулевой по размеру файл сохранить нельзя (notmuch не отличает его от ошибки).
- Одно действие на сервере за раз: пока идёт отправка, релев или другое извлечение, вторая команда отклоняется сообщением.

## Правила

- Транспорт — SSH, POSIX `sh -s` на stdin; запрос, идентификатор, теги, адреса, имя аккаунта — данные (одинарные кавычки, `--`); пароли и SQL-подобные тексты никогда не в аргументах.
  Идентификатор беседы — hex, тег `[A-Za-z0-9][A-Za-z0-9_.-]*`, имя аккаунта `[A-Za-z0-9][A-Za-z0-9_.-]{0,30}`.
- Скрипты чтения не содержат `notmuch new`, `mbsync`, `msmtp`, `rm`, `sudo`; запись и отправка — только в перечисленных выше действиях (тесты просматривают скрипты).
- Две постоянные SSH-сессии: чтение/теги и «длинные» действия (отправка, запись, тесты, релев); задания чтения идут по очереди; смена сервера очищает окно.
- Нестандартная конфигурация notmuch: `NOTMUCH_CONFIG` (свойство `configPath`, настройка `mail/notmuchConfig`; окна для неё пока нет). Имя отправителя — настройка `mail/displayName`.
- Нет `notmuch`/`msmtp`/`mbsync` — явное сообщение с командой установки.

## Реализация и проверки

`src/mail/MailInfo` (чтение), `MailSend` (адреса, сообщение, скрипт отправки, аккаунты), `MailAccount` (мастер, скрипты записи/проб/тестов/релева), `MailController`, `qml/shell/MailWindow.qml`;
фикстуры `tool/make_mail_fixture.sh` → `tests/fixtures/mail/` (настоящие выводы notmuch 0.39), `tests/fixtures/mail/smtp_sink.py` (одноразовый приёмник SMTP, CRAM-MD5), `tool/setup_mail_live_fixture.sh`.

- `fortiq_mail` (14 тестов): чтение (включая номер части вложения). `fortiq_mailsend` (19 тестов, из них 2 — вложения: очистка имён, скрипты, разбор, защита очистки): адреса (кавычки, запятые в имени, инъекция, не-ASCII), RFC 2047 (границы UTF-8), сборка сообщения (Cci, даты, base64, ответ), отказы,
  скрипт отправки (кавычки, разделитель, нет пароля), аккаунты, исходы, ответ, пароли (спецсимволы, отказы), форма, содержимое трёх файлов (экранирование, маска), скрипт записи (бэкап, awk-блок, 0600, пароль только в heredoc),
  проба, скрипты тестов.
- Живой тест `mailSendAndWizard` (нужны `FORTIQ_IT_MAILSEND=1` и `tool/setup_mail_live_fixture.sh` от root **на одноразовом Debian**: dovecot на 127.0.0.1:1143, SMTP-приёмник на 127.0.0.1:2525; тест удаляет
  `~/.mbsyncrc`, `~/.msmtprc`, `~/.notmuch-config`, `~/Mail`, `~/sinkout` тестового пользователя): проба; предпросмотр ничего не пишет; запись двух из трёх файлов; существующий `~/.msmtprc` с чужим аккаунтом
  сохранён, права исправлены, бэкап есть; повторный запуск идемпотентен; `notmuch-config` не перезаписан; тесты SMTP/IMAP; релев через настоящий IMAP с паролем «с кавычкой, пробелом, #, \, $ и ;»; ответ; отправка
  с Cci/Cc/UTF-8 на приёмник (конверт, заголовки, нет Cci в письме), копия в Sent и тег `replied`; неверный пароль → «Authentification», задача `failed`, копии нет; очистка при отключении.
- Живой тест `mailAttachmentsStayOnTheServer` (`FORTIQ_IT_MAIL=1`): содержимое декодировано (base64 → `%PDF-1.4`), режим 644, повтор даёт `(1)`, враждебное имя остаётся в `~/Downloads`, неверная часть и
  неизвестное письмо ничего не создают, нет временных остатков; скачивание на «этот компьютер» — настоящая задача `download` (содержимое совпадает), временная копия на сервере удалена; конфликт с существующим
  файлом не перезаписывает его и копия всё равно удаляется; очистка при отключении.
- Layout-тест с подставным контроллером: список, поиск, чтение, теги, ответ → форма → отправка, мастер (маска, «Révéler», подтверждение, запись, тесты).

## Не сделано

Вложения при отправке (прикрепление файла к письму), открытие вложения «на месте», ответить всем/переслать/черновики, открытие ссылок через Navigateur, PGP, настоящее удаление, окно для `NOTMUCH_CONFIG`, автоматический периодический релев,
OAuth2-аккаунты (Gmail/Outlook требуют пароль приложения), IDN-адреса, проверка сертификатов с пиннингом, шифрование паролей на сервере (по решению владельца — файлы 0600). Android на устройстве не проверялся.
