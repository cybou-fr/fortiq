# Лицензии FORTIQ и сторонних компонентов

**Решение владельца, 26.10.2026:** собственный код FORTIQ распространяется на условиях **GNU GPL version 3 only (GPL-3.0-only)**. Полный текст — [LICENSE](../LICENSE). Проект будет бесплатным, исходники планируется открыть на GitHub; репозиторий пока приватный. GPL не запрещает коммерческое использование, но при распространении соответствующего GPL-кода налагает обязанности предоставить исходники.

## Текущая политика открытого проекта

- Qt 6.12 используется под доступными GPLv3/LGPLv3 условиями. Для GPLv3-приложения наличие Qt-модуля **только под GPLv3 само по себе не является нарушением**. Коммерческая лицензия Qt исключительно ради закрытия исходников больше не нужна.
- libssh2 (BSD-3-Clause), OpenSSL 3 (Apache-2.0), libvterm (MIT), zlib и прочие зависимости **сохраняют свои собственные лицензии**; тексты и copyright notices не удалять.
- Сохранить source offer/source delivery, GPLv3 и notices с каждым распространяемым бинарником. Для Android отдельно проверить применимые требования GPLv3 к Installation Information, возможность установки изменённой сборки и правила канала распространения. Собственные signing keys публиковать не требуется автоматически.
- Проверить авторские права на assets (обои, иконки, шрифты), вклады третьих лиц и историю Git до открытия приватного репозитория. Открытие исходников не дает права публиковать чужие закрытые данные.
- **Технический долг:** существующий `tool/check_third_party.py` всё ещё реализует старую **консервативную LGPL-only политику** и может отказать в пакете с GPL-only Qt, хотя GPLv3 FORTIQ это допускает. До отдельной корректировки с тестами сохранён его более строгий режим; он не определяет юридическую лицензию проекта. Проверки неизвестных DLL, лицензий и отладочных компонентов не ослаблять.
- IFW 4.11, Mesa/LLVM notices, Android Gradle dependencies и правила упаковки по-прежнему требуют проверки до публичного бинарного релиза.

## Что нашла проверка и что исправлено

FORTIQ — закрытый продукт, динамически скомпонованный с Qt по **LGPLv3**. Часть модулей Qt доступна **только по GPLv3 или за коммерческую лицензию**: распространять их в закрытом приложении без коммерческой лицензии Qt нельзя.
Автоматическая проверка (`tool/check_third_party.py`) читает `SPDX-License-Identifier` всех публичных заголовков установленного Qt 6.12.0: модуль, у которого хотя бы один заголовок не допускает LGPL, считается не-LGPL
(в этой сборке: QtVirtualKeyboard, QtQuickTimeline, QtCharts, QtGraphs, QtDataVisualization, QtQuick3D (часть), QtGrpc, QtHttpServer, QtNetworkAuth, QtDesigner, QtAxContainer/AxServer, QtCanvasPainter и др.).

**Найдено:** и пакет Windows (установщик и ZIP от 23.10.2026), и отладочный APK содержали `Qt6VirtualKeyboard` (GPL-3.0 или коммерческая) вместе с плагином `qtvirtualkeyboardplugin`; в APK ещё `Qt6QuickTimeline`.
FORTIQ их не использует: `windeployqt` и `androiddeployqt` подтягивают их как зависимости плагина ввода и плагина Lottie. **Ранее собранные установщик и ZIP не распространять.**

**Исправлено:**
- Windows: `windeployqt --no-virtualkeyboard --skip-plugin-types qmltooling,platforminputcontexts,vectorimageformats`, пустые каталоги модулей удаляются; в пакете 36 библиотек Qt вместо 41, без VirtualKeyboard, Lottie и QuickTimeline.
- Android: `qt_import_plugins(fortiq EXCLUDE_BY_TYPE platforminputcontexts EXCLUDE_BY_TYPE vectorimageformats)` в CMake; `tool/build_android.py` перед упаковкой удаляет `android-build/libs` (androiddeployqt только добавляет файлы и оставлял устаревшие GPL-библиотеки);
  в APK 35 библиотек Qt, QuickTimeline и VirtualKeyboard исчезли. Приложение запускается на эмуляторе, интерфейс и ввод не затронуты.
- QML: везде `import QtQuick.Controls.Fusion` вместо `QtQuick.Controls` (приложение и так использует только стиль Fusion).
- Проверка встроена: `package_windows.py` завершается ошибкой, если в пакете есть не-LGPL модуль Qt, неизвестная сторонняя DLL или нет текстов лицензий; `build_android.py --package` проверяет APK (в отладочной сборке плагины QML-отладки `qmltooling` только упоминаются:
  такой APK распространять нельзя; релизная сборка их не содержит); `tool/ci_check.py` запускает самотест проверки (`--self-test`: запрещённые модули, плагины, QML-модули, неизвестные библиотеки и отсутствующие лицензии отвергаются, чистый пакет проходит).

Ограничение проверки: сопоставление файлов с лицензиями идёт по именам и заголовкам; плагин или QML-модуль, чьё имя не содержит названия модуля, она не свяжет с его лицензией. Это дополнение к чтению уведомлений, а не замена.

## Что обязывает LGPLv3 при динамической компоновке

1. Текст лицензий и уведомления в составе продукта: есть (`licenses/Qt-COPYING.txt`, `Qt-LICENSE`, `Qt-Copyright.txt`, `THIRD_PARTY_NOTICES.txt`).
2. Qt остаётся отдельными заменяемыми файлами (`Qt6*.dll`, плагины, `qml/`): пользователь может подставить собственную сборку той же версии. Приложение **не** должно проверять подпись/хеш Qt-файлов и отказываться запускаться с изменёнными.
   Установка в `%LOCALAPPDATA%\\Programs\\FORTIQ` доступна пользователю на запись.
3. Исходный код **использованной** версии Qt: уведомление ссылается на `https://download.qt.io/official_releases/qt/6.12/6.12.0/` и обещает выдать по запросу у издателя (адрес для запроса задаётся переменной `FORTIQ_NOTICE_CONTACT` при упаковке; **по умолчанию текст говорит «через сайт продукта»: владелец должен указать настоящий адрес**).
   Qt используется без изменений; если когда-либо будут правки Qt — их исходники придётся предоставлять самим.
4. Запрет «ограничивать обратную разработку для отладки модификаций» не должен попадать в условия использования FORTIQ.
5. **Android:** библиотеки Qt лежат в APK как отдельные `.so` (динамическая компоновка), приложение подписывается ключом издателя. Пользователь, заменивший библиотеку, получает неподписанный/переподписанный пакет; требуется ли по LGPLv3 §4 предоставить «Installation Information»
   для потребительских устройств — **вопрос к юристу** (при коммерческой лицензии Qt вопроса нет).

## Установщик (Qt Installer Framework)

Установщик собран IFW 4.11. По данным проекта IFW распространяется по GPLv3 **с исключением** (`LICENSE.GPL3-EXCEPT`) либо по коммерческой лицензии; исключение позволяет распространять упаковываемое содержимое на своих условиях.
В локальной установке IFW нет текста этой лицензии, поэтому: **владелец должен прочитать исключение в репозитории IFW (code.qt.io, installer-framework, `LICENSE.GPL3-EXCEPT`) и подтвердить, что оно покрывает такой установщик**;
в `THIRD_PARTY_NOTICES.txt` установщик упомянут. Запасные варианты, если нет: коммерческая лицензия Qt (включает IFW) или другой упаковщик (Inno Setup, WiX/MSI, MSIX).

## Решение, которое остаётся за владельцем

| | LGPLv3 (сейчас) | Коммерческая лицензия Qt |
|---|---|---|
| Стоимость | 0 | подписка; для нескольких разработчиков/платформ значительная |
| Закрытый код | допустимо при динамической компоновке и выполнении пунктов выше | без ограничений |
| Модули только GPL (Virtual Keyboard, Charts, Graphs, Quick3D, Timeline…) | нельзя | можно |
| Android | вопрос про «Installation Information» | без вопроса |
| Установщик IFW | зависит от исключения GPL3-EXCEPT | входит |
| Риск | ошибка при обновлении Qt/зависимостей вернёт GPL-модуль в пакет — ловится проверкой | — |

Рекомендация проекта: оставаться на LGPLv3, пока продукту не нужны GPL-модули и юрист подтвердил Android и IFW; проверка (`check_third_party.py`) делает регрессию заметной до выпуска.
