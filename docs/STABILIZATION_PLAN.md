### Результат S-3 (24.10.2026)

- **S-3a (P1, исправлено):** `safeChildPath`/`parentPath` использовали `QDir::cleanPath`, который на **Windows** превращает обратную косую черту в разделитель. Имя Linux-файла `a` адресовалось как `a/b` — **другой** путь (при существующем каталоге `a` операция попала бы в чужой файл; без него — ошибка «permission»). Исправлено собственной нормализацией (`cleanAbsolutePath`), юнит-тесты `RemotePathTest` (5 проходят) и живой тест.
- **Поведение по контракту (не дефект):** `makeDirectory`/`renameEntry` обрезают пробелы по краям нового имени, а поиск обрезает запрос; имя с краевым пробелом можно создать только копированием/загрузкой. Зафиксировано в тесте.
- Ни одно имя не исполнилось (маркер не появился ни в арене, ни в домашнем каталоге, ни в `/tmp`), лишних записей (`-rf`, `--`, `-`) не создано.
- Проверено: `fortiq_ssh_it` — 12 тестов Files (передачи, Trash, safeSave, поиск, операции) и `fortiq_publication` 28/28 после правки. Не проверено: Logs/Disks/Network/Mail с враждебными именами (в этих адаптерах имена приходят от сервера, отдельный корпус — в бэклоге), Android.

## 4. Baseline производительности (к измерению; чисел пока нет)

Бюджеты — цели: действие UI p95 ≤ 100 мс, смена вкладки ≤ 150 мс, GUI не блокируется долгими операциями, часовой тест без устойчивого роста памяти, таблицы с виртуализацией, потоковые логи с ограничением хранения и backpressure, ограниченный пул SSH.

Что измерять первым (инструмент → метрика): Shell/QML (Qt Quick Profiler, число элементов сцены, пересоздание делегатов), SSH (число одновременных каналов, время открытия), Files (каталог из 50 000 записей), Logs (поток 10 000 строк/с), Terminal (`yes` / `cat` большого файла), память за час (Windows: Process Working Set; Android: `dumpsys meminfo`). Результаты записывать в `docs/PERFORMANCE_BASELINE.md` **с версией коммита и машиной**; до этого файла утверждений о скорости не делать.
