### Результат S-3 (24.10.2026)

- **S-3a (P1, исправлено):** `safeChildPath`/`parentPath` использовали `QDir::cleanPath`, который на **Windows** превращает обратную косую черту в разделитель. Имя Linux-файла `a` адресовалось как `a/b` — **другой** путь (при существующем каталоге `a` операция попала бы в чужой файл; без него — ошибка «permission»). Исправлено собственной нормализацией (`cleanAbsolutePath`), юнит-тесты `RemotePathTest` (5 проходят) и живой тест.
- **Поведение по контракту (не дефект):** `makeDirectory`/`renameEntry` обрезают пробелы по краям нового имени, а поиск обрезает запрос; имя с краевым пробелом можно создать только копированием/загрузкой. Зафиксировано в тесте.
- Ни одно имя не исполнилось (маркер не появился ни в арене, ни в домашнем каталоге, ни в `/tmp`), лишних записей (`-rf`, `--`, `-`) не создано.
- Проверено: `fortiq_ssh_it` — 12 тестов Files (передачи, Trash, safeSave, поиск, операции) и `fortiq_publication` 28/28 после правки. Не проверено: Logs/Disks/Network/Mail с враждебными именами (в этих адаптерах имена приходят от сервера, отдельный корпус — в бэклоге), Android.

### Результат S-4 (24.10.2026): операция → поведение при отказе

Три отказа, которые клиент не отличает от успеха: **1** сервер отказал (ошибка протокола, ничего не сделано), **2** запрос потерян (ничего не сделано, обрыв), **3** подтверждение потеряно (сервер **выполнил**, клиент видит обрыв). Правила: отказ — обычная ошибка, сессия жива; обрыв — код `unknown`, сессия закрыта, **операция не повторяется** (одна попытка).

| Операция | 1 отказ | 2 запрос потерян | 3 ACK потерян |
|---|---|---|---|
| `makeDirectory` | ошибка, папки нет | `unknown`, папки нет | `unknown`, **папка создана** |
| `renameEntry` | ошибка, имя прежнее | `unknown`, имя прежнее | `unknown`, **имя новое** |
| `saveCopy` | `conflict`, копии нет, временный файл убран | `unknown`, копии нет | `unknown`, **копия опубликована с содержимым** |
| `moveToTrash` | ошибка, элемент на месте, `.trashinfo` убран | `unknown`, элемент на месте | `unknown`, **элемент в корзине** |
| `restoreFromTrash` | ошибка, элемент в корзине | `unknown`, элемент в корзине | `unknown`, **восстановлен** |
| `deleteFromTrash` | ошибка | `unknown`, ничего не удалено | `unknown`, **удалён первый файл** (частичное удаление) |
| `emptyTrash` | пропускает элемент, продолжает, ошибка «N не удалено» | `unknown`, остановка | `unknown`, остановка |
| `upload`/`saveFile` (публикация) | ошибка, оригинал цел | `unknown` | `unknown`, **новое содержимое** (`publicationFailure`, 8 строк, было до S-4) |

Найдено и исправлено по этой таблице (тест падал до правки):
- **S-4a (P0):** `saveCopy` при обрыве во время публикации (`rename`) отвечал `conflict` и «nothing was written», хотя копия могла быть опубликована; теперь `unknown` и закрытие сессии.
- **S-4b (P1):** `emptyTrash` при обрыве связи считал элементы «не удалёнными (права?)» и продолжал; теперь первый обрыв даёт `unknown` и остановку.

Как проверено: в тестовой сборке мутации SFTP идут через `sftpMutation` (хук `publication_test::fault`), реальная операция либо не выполняется, либо выполняется и затем подменяется ошибкой; состояние сервера проверяет вторая сессия. `fortiq_publication` теперь 49 (28 + 21), `fortiq_ssh_it` Files-тесты проходят. **Не покрыто:** загрузка (`download`) — локальная запись, отдельная семантика; `upload` нового имени без замены (общий путь с публикацией); реальный обрыв TCP посреди операции (инъекция подменяет результат, а не рвёт сокет); побочные остатки при `unknown` (осиротевший `.trashinfo` после потерянного запроса `moveToTrash` допустим — спецификация корзины его терпит).

## 4. Baseline производительности (к измерению; чисел пока нет)

Бюджеты — цели: действие UI p95 ≤ 100 мс, смена вкладки ≤ 150 мс, GUI не блокируется долгими операциями, часовой тест без устойчивого роста памяти, таблицы с виртуализацией, потоковые логи с ограничением хранения и backpressure, ограниченный пул SSH.

Что измерять первым (инструмент → метрика): Shell/QML (Qt Quick Profiler, число элементов сцены, пересоздание делегатов), SSH (число одновременных каналов, время открытия), Files (каталог из 50 000 записей), Logs (поток 10 000 строк/с), Terminal (`yes` / `cat` большого файла), память за час (Windows: Process Working Set; Android: `dumpsys meminfo`).
