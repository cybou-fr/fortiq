Дата снимка: 11 октября 2026 года. Базовый коммит: `f0ca0954`.
Исходное состояние сверено с текущим кодом; локальные изменения описаны только

## 1. Назначение и принципы

FORTIQ — Distributed Desktop Software: **только GUI frontend над серверными
консольными Linux-утилитами**, вызванными по SSH. Все 12 инструментов
сохраняются. **Каждая функция APP имеет существующий/собственный CLI на
сервере и работает только при наличии соответствующей SSH-сессии.**
Локальны лишь окна, настройки, безопасные временные черновики и отдельный
контур лицензирования Lemon Squeezy.
Полная формулировка продукта и правила набора — в PRODUCT_SCOPE.

- Развитие идёт параллельно по рабочим приложениям, данным и управлению системой,
  когда готовы общие зависимости. Состав этапа определяется законченными сценариями.
- R0 готовит платный выпуск Windows с Lemon Squeezy и устраняет риски операций/соединений; R1 доводит Linux-инструменты;
  R2 добавляет полноценную почту и повседневные документы. Почта не блокирует R1.
- «Реализовано в коде» не означает «проверено» или «доступно в выпуске».
- Ресурсы, задачи, черновики и действия общие; переключение сервера не переносит операции.
- Все предметные операции проходят SSH exec/shell/PTY/SFTP/forwarding к серверным CLI.
  **Прямые SMTP/IMAP/HTTP/FTP подключения рабочих приложений Flutter запрещены.**
  Browser использует SSH SOCKS forwarding (`sshd` на сервере), без direct fallback.
- Встроенные приложения, порталы в браузере и удалённые GUI — разные возможности.
- Windows — основная платформа; наличие Android/iOS-папки не подтверждает поддержку.

## 3. Общие задачи и зависимости

Все изменения ниже запланированы, если отдельное свидетельство реализации не
указано в §2. P0 — блокирует безопасную основу; P1 — необходим для сценария этапа;
P2 — расширяет подтверждённую основу. R0/R2 означает ранний контракт и позднюю
полную интеграцию, а не два разных CORE.

| ID | Приоритет / этап | Изменение | Зависимости | Критерий проверки |
|---|---|---|---|---|
| CORE-01 | P1, R0 → R2 | Отделить UI/активацию от SSH-сессии | CORE-03/11 | Старт настроек/лицензии без SSH; все рабочие окна показывают disconnected, не выполняют операции |
| CORE-02 | P1, R0 → R1 | App Registry и AppDescriptor | CORE-01/03 | 12 типов доступны из одного реестра; multipleInstances и фабрики согласованы |
| CORE-03 | P0, R0 | SSH-bound ResourceLocation и CLI ResourceService | SSH_FRONTEND_CONTRACT | Каждая рабочая операция имеет serverId + CLI; account — контекст CLI на сервере; local только UI-кеш; чужой source ID отвергается |
| CORE-04 | P0, R0 → R1 | TaskManager, прогресс, отмена, ошибки и unknown | CORE-03/08 | Закрытие окна не скрывает результат; обрыв изменения даёт unknown; отмена не выдаётся за успех |
| CORE-05 | P1, R1 → R2 | Только UI-кеш, временные черновики и CredentialStore | CORE-03 | Черновик восстанавливается, но серверный файл/mail — source of truth; без SSH нет действий; секретов и plaintext fallback нет |
| CORE-06 | P1, R1 → R3 | ActionRouter и общие уведомления | CORE-02/03/04 | R1: служба → логи → конфиг с правильным сервером; R2: вложения; R3: уведомление открывает ресурс |
| CORE-07 | P0, R0 | Capability discovery, установка/обновление CLI на Linux через SSH, права | SSH_FRONTEND_CONTRACT | У каждого APP есть command/package или свой fortiq-* CLI; отсутствующее ставится через SSH, ошибки прав/версий видны, fallback на Flutter отсутствует |
| CORE-08 | P0, R0 | Асинхронный жизненный цикл | Контракт ARCHITECTURE | Поздний ответ после смены ресурса/закрытия не меняет другое окно; каналы освобождаются |
| CORE-09 | P1, R2 | WorkspaceState | CORE-01/02/03/05 | Восстанавливаются окна, геометрия и источники; нет секретов и автоматического повтора команд |
| CORE-10 | P0, R0 | Operation Safety | CORE-04/07/08 | Подготовка при подключении видна (окно с шагами и логом); SSH/файрвол проверяются вторым входом и откатываются; неизвестный результат проверяется, изменение не повторяется автоматически |
| CORE-11 | P0, R0 → R3 | Session Lifecycle / SessionManager | CORE-07/08 | R0: один reconnect на сессию, Disconnect отменяет повторы и поздние клиенты; R3: независимые серверы и каналы |
| CORE-12 | P0, R0 → R4 | Verification & CI | Контракты и сценарии соответствующего этапа | CI запускает analyze/test; unit/widget/протокольные проверки с отчётами; изменения системы только на disposable VM |

Новые модули App Registry, SSH-bound ResourceService, TaskManager, CredentialStore,
WorkspaceState и ActionRouter — целевые, не существующие файлы. Их контракты
определены в ARCHITECTURE; конкретные Dart-пути выбираются при реализации.
`SshClientService` остаётся транспортом; существующие сервисы развиваются через
RemoteShell и будущие адаптеры. CORE-10/11 закрепляют требования поверх уже
имеющихся механизмов, не объявляя каждый дефект новой самостоятельной задачей.

**Неопределённые коммерческие параметры:** необходимость контроля повторной покупки Intro, идентификация покупателя,
допустимое количество устройств, офлайн-период, политика отзыва, способ распространения.
До реализации они должны быть утверждены, а не назначены автоматически.

**Промокоды:** встроенные Discounts Lemon Squeezy — только необязательные
маркетинговые акции **Pro**, не третий тариф и не отдельный модуль.
По умолчанию скидка на первый годовой платёж, продление по 39,90 €;
лимит активаций кода, срок кампании и ограничение по продукту задаются
в Lemon Squeezy. На Intro скидки не действуют. Дополнительная разработка
механизма промокодов в R0 не требуется; перед акцией протестировать
покупку и стоимость будущего продления.

## 4. Матрица приложений

**Правило приёмки:** любая APP-функция имеет серверный console executable,
проверяемый `command -v`/версией, доставляемый/обновляемый при необходимости
через SSH. Источником действий служит Linux, а не Flutter.
Проверенная таблица 14 APP и конкретных CLI:
[SSH_FRONTEND_CONTRACT.md](SSH_FRONTEND_CONTRACT.md).
Без SSH допустимы только оболочка/настройки/покупка/лицензия/временные
черновики; не рабочие действия. Mail всегда серверный CLI, прямой SMTP запрещён.


### APP-01 — Файлы

- **Основная очередь:** R1 — SFTP, передачи, прогресс и безопасное сохранение.
- **Статус:** существующая основа реализована в коде; перечисленные изменения запланированы, приёмка не зафиксирована.

- **Код:** `lib/widgets/file_explorer.dart`; listDirectory/createDirectory/remove/readFile в `lib/services/file_service.dart`.
- **Сейчас:** каталоги, навигация, создание папки, удаление, открытие файла. Имена и метаданные разбираются из вывода ls.
- **Подтверждённые ограничения:** разделение по пробелам и склейка имени искажают повторяющиеся пробелы; имя ссылки включает отображение её цели. SFTP и центра передач нет; ошибки чтения могут выглядеть как пустые данные; корзина запланирована позже.
- **Ближайший шаг:** SFTP-список каталога, загрузка/скачивание, переименование, копирование пути. Добавить защиту от устаревшего ответа при быстрой навигации.
- **Бизнес:** избранные каталоги, недавние документы, пересылка файла как вложения, выбор места сохранения.
- **Администрирование:** права/владелец, ссылки, операции между каталогами, открытие терминала в выбранной папке.
- **Зависимости:** CORE-03/04/08/10/11; SFTP в существующем SSH-клиенте.
- **Готовность:** корректны имена с пробелами, кавычками и Unicode; передача большого файла показывает прогресс и ошибку; действие невозможно перенаправить на другой сервер.

### APP-02 — Текстовый редактор

- **Основная очередь:** R1 — черновики, diff, поиск и защита от внешнего изменения.
- **Статус:** существующая основа реализована в коде; перечисленные изменения запланированы, приёмка не зафиксирована.

- **Код:** `lib/widgets/file_editor.dart`; writeFile в `lib/services/file_service.dart`.
- **Сейчас:** текст, номера строк, Ctrl+S, dirty, проверка Reload, сравнение текста с отправленным снимком.
- **Ограничения:** нет проверки внешнего изменения файла; ветка прямой записи остаётся неатомарной; замена файла не сохраняет все атрибуты.
- **Ближайший шаг:** локальный черновик, поиск/замена, переход к строке, проверка версии файла перед сохранением и выбор при конфликте.
- **Бизнес:** восстановление документов, удобная работа с несколькими файлами и кодировками.
- **Администрирование:** подсветка конфигов, diff перед записью, резервная копия и связанное действие «перезапустить службу».
- **Зависимости:** CORE-03/05/08/10; файловый сервис.
- **Готовность:** правки переживают перезапуск клиента; изменение на сервере не перезаписывается молча; набор текста во время сохранения остаётся dirty.

### APP-03 — Документы и Markdown Studio

- **Основная очередь:** R2 — общий движок документов, шаблоны и восстановление.
- **Статус:** существующая основа реализована в коде; перечисленные изменения запланированы, приёмка не зафиксирована.

- **Код:** `lib/widgets/markdown_studio.dart`; общий `lib/services/file_service.dart`.
- **Сейчас:** Markdown, предпросмотр, путь на сервере, сохранение и dirty. Начальный путь заметки — /root/notes.md.
- **Ограничения:** нет постоянного локального черновика и версий; путь по умолчанию неудобен непривилегированному пользователю. Интерфейс загрузки требует проверки защиты несохранённого текста.
- **Ближайший шаг:** выбор расположения, черновики, поиск, шаблоны заметки/инструкции/отчёта. Приложение сохраняется отдельно от редактора.
- **Бизнес:** структурированные заметки, протоколы встреч, экспорт и просмотр документов.
- **Администрирование:** runbook, инструкции восстановления, ссылки на файлы, службы и сохранённые фильтры логов.
- **Зависимости:** CORE-03/05/06; общий механизм черновиков с редактором.
- **Готовность:** загрузка другой заметки не уничтожает правки без выбора; заметка восстанавливается после перезапуска и открывает ссылки на ресурсы.

### APP-04 — Почта

- **Основная очередь:** R2 — полноценная почта/MIME/вложения через **серверную консольную утилиту** по SSH. Поддержка нескольких аккаунтов — позже, только внутри серверного CLI.
- **Статус:** текущая основа реализована, новый серверный исполнитель и расширения ещё не реализованы.
- **Код:** `lib/widgets/mailbox_viewer.dart` и `lib/services/mail_service.dart`, использующий `RemoteShell.execute`.
- **Сейчас:** mbox на Linux, чтение серверного spool, вызов `mail` или `sendmail` **на Linux через SSH**. Fallback добавляет сообщение в mbox, но не является отправкой и должен показываться как недоставленное.
- **Запрет:** **никакого прямого SMTP, IMAP, POP3 из Flutter**. Никакого независимого client-side Mail Account adapter или почты, синхронизирующейся без SSH.
- **CLI-исполнитель:** использовать надёжный имеющийся инструмент (`mail`/`sendmail`, для внешних ящиков `mbsync`/`notmuch`/`mu` по подходящим возможностям) либо создать и доставить по SSH **`fortiq-mail`** с командами `list/read/send/reply/attachment/save-draft/status`. Для внешнего провайдера сама **серверная утилита** управляет соединениями на Linux.
- **R2:** capability discovery, установка/обновление CLI, стабильный stdout формат, mailbox/folder/message IDs, MIME/вложения, серверные черновики, подтверждённая доставка/очередь, корректные ошибки. Случайно пересланное письмо исключать через проверку результата после SSH-обрыва.
- **Готовность:** Mail получает/отправляет **только через SSH exec/stream на выбранном сервере**, при отключённом SSH не выполняет никаких почтовых действий, временный локальный черновик можно сохранить для восстановления. Нет прямых сокетов из Mail к почтовому провайдеру.
- **Проверки:** SSH integration + disposable Linux VM, наличие/отсутствие CLI и привилегий, MIME/UTF-8, вложения, неизвестный результат отправки, запрет повтора без проверки и отсутствие прямого SMTP/IMAP из клиента.

### APP-05 — Браузер

- **Основная очередь:** R0 — подготовка и защита сервера при подключении, видимая пользователю, с откатом при потере доступа.

- **Готовность:** подготовка видна в окне с логом; после потери входа SSH/файрвол возвращаются в прежнее состояние (на VM); занятый apt не вызывает дублирующую операцию (Dpkg::Lock::Timeout); смена сервера не переносит задачу; не-Debian система и пользователь без прав получают понятный статус, ничего не меняется; вход по паролю не включает шаг SSH.

- Окончательные цены **2 € и 39,90 €** проверены в checkout с **tax-inclusive pricing**; необязательный промокод Pro по умолчанию меняет только первый платёж, а стандартную цену продления покупатель видит заранее.
- Подписка Pro отменяется без сокращения оплаченного срока; Intro не продлевается и не превращается в Pro автоматически; восстановление ключа не теряет данные. Однократность Intro проверяется отдельно, так как повторную покупку другого ключа лицензия сама не запрещает.
- Протестированы активация, проверка и деактивация лицензионных ключей Lemon Squeezy, права при отмене подписки, офлайн-политика и отсутствие административных секретов в клиенте; webhooks проверяются, только если внедрён серверный компонент.
- Импортированный приватный SSH-ключ защищён OS-хранилищем/эквивалентным решением на Windows с тестом миграции сохранённых ключей.
- Подготовка при подключении видна (окно с шагами и логом); шаги SSH и файрвола
  проверяются вторым входом и откатываются, шаг SSH недоступен при входе по паролю;
  всё это проверено на disposable VM, включая обрыв посреди шага.

  одной сессии; поздний клиент освобождается, изменившийся ключ останавливает повторы.

  проводится проверка, автоматического повтора нет.
- Согласованы ResourceLocation/AppDescriptor/TaskManager; существующие окна доступны.
- Для **каждого** APP-01…14 зафиксированы исполняемая команда/пакет/fortiq-* и SSH capability; проверено отсутствие direct protocol adapters в клиентских рабочих сервисах.
- SOCKS проверен для HTTP/DNS/внутренних адресов/WebRTC и отказа без прямого fallback.
- Статический анализ и автоматические тесты проходят в CI с доступным отчётом.

### R1 — критерии приёмки

- Каждый рабочий ресурс и account привязаны к `serverId`, SSH-сессии и CLI; переключение не переносит действия. Local допустим только для UI/защиты черновика.
- SFTP-передача показывает прогресс, отмену по возможностям, ошибку и целевой источник;
  имена с пробелами, кавычками и Unicode не искажаются.
- Терминал присоединяется к своей tmux-сессии после reconnect; без tmux отсутствие
  сохранения объясняется, терминал открывается в выбранном каталоге.
- Конфигурация не перезаписывается молча при конфликте; черновик Editor восстанавливается,
  редактирование во время save остаётся dirty.
- Services → Logs → Editor → Restart → Verify выполняется на правильном сервере;
  неудачная запись блокирует restart, результат проверяется.
- Процессы, TCP/UDP и журнал дают корректный контекст, SIGTERM отделён от SIGKILL.
- Диски доступны для просмотра; частичный анализ и недостаточные права отмечены;
  UFW проверяется на VM с сохранением SSH-доступа. Операций с разделами в R1 нет.

### R2 — критерии приёмки

- Документ и черновик восстанавливаются после перезапуска.
- Серверный Mail CLI читает/отправляет через SSH на выбранном Linux; никаких прямых SMTP/IMAP из Flutter. Без SSH нет синхронизации и отправки; временный локальный черновик остаётся только UI-данными.
- MIME-вложения открываются в Viewer (включая PDF), сохраняются в выбранный ресурс;
  письмо не отправляется повторно из-за ошибки сохранения отправленной копии.
- Общий поиск выполняется серверным `find`/`grep`/`rg`/`fortiq-search` по SSH, возвращает serverId и правильную строку.
- Workspace восстанавливает окна, источники и контекст без секретов и повторения команд;
  недоступный сервер не мешает экрану подключения/лицензирования и просмотру
  временного черновика, но **ни одна рабочая операция не выполняется без SSH**.

### R3 — критерии приёмки

- Два сервера имеют независимые сессии, задачи, терминалы и контексты; переключение
  не меняет источник уже запущенного действия.
- Уведомления и история открывают правильные ресурсы и не содержат секретов.
- Выбранная конфигурация копируется, восстанавливается и проверяется на VM;
  неизвестный результат восстановления не приводит к автоматическому повтору.
- Решение по Containers/Jobs оформлено проверенным сценарием либо отложено явно.
  Несколько почтовых аккаунтов/OAuth, корзина и монтирование принимаются отдельно,
  если включены в конкретную поставку; не подменяют обязательные результаты.

### R4 — критерии приёмки

- Дисковые изменения проверены на образах/disposable VM: устройство повторно
  идентифицируется, системные и занятые устройства защищены, план и журнал видны.
- После разрыва результат разметки/форматирования проверяется без слепого повтора.
- Расширенные медиа проверяют большой файл, поток, буфер и ошибку; состав форматов
  и платформ подтверждён реальными испытаниями, а не наличием пакета.
- Дополнительная платформа получает свой отчёт о сценариях и ограничениях;
  не наследует статус Windows.

## 7. Качество, границы и первые задачи

| Тип проверки | Обязательная область | Свидетельство |
|---|---|---|
| Unit | Парсеры ls/ps/systemctl/ss/netstat/UFW/journal, аргументы shell, версии ресурсов, состояния задач/сессий | Входные fixtures, ошибочные/усечённые ответы, результат прогона |
| Widget | Dirty, закрытие/сворачивание, поздние ответы, источник окна, восстановление | Тесты смены ресурса/сервера и сохранения состояния |

## 8. Как поддерживать матрицу

Разделение ответственности: README — текущее поведение/запуск; PRODUCT_SCOPE —
что и зачем; ARCHITECTURE — как взаимодействовать; матрица — что, когда и как проверить.
Краткая дорожная карта README следует §5, не ведёт независимый подробный план.

После изменения обновлять исходное состояние и оставшиеся ограничения APP/CORE.
Использовать статусы «запланировано», «в работе», «реализовано в коде», «проверено»,
«доступно в выпуске». Для повышения статуса указывать коммит, окружение, дату,
сценарий и результат. Ссылка на метод или наличие кнопки недостаточны.

Приёмка фиксируется по FLOW и критериям этапа: пройдено / не пройдено / не проверено
с доказательством. Сейчас критерии §5 — предложения для реализации, не галочки
готовности. После выпуска обновлять README только подтверждёнными возможностями.
Если документы копируются в `www/assets`, обновлять эти снимки отдельно при
обновлении сайта; они не становятся самостоятельным источником плана.
