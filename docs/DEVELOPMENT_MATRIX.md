## 4. Правила приёмки

1. Функция «готова», только если есть тест на настоящем Debian-стенде (одноразовый WSL-дистрибутив
   `fortiq-test` или виртуальная машина), включая отказы: нет прав, нет пакета, имена с пробелами и
   Unicode, обрыв SSH, чужой сервер.
2. Подставной сервер допускается для разбора вывода и логики, но не подтверждает готовность.
3. Для каждого окна: ошибка показывается ошибкой, а не пустым списком.
4. Не описывать цель как реализованное в README, на сайте и в справке.

## Уроки прототипа

Что показали испытания Flutter-прототипа на настоящем сервере. Это требования к новой реализации.

**SSH и сеть**
- Отказ в доверии ключу хоста — отдельная ошибка, а не «неверный пароль»; приватный ключ
  разбирается **до** открытия сокета, иначе утекает соединение.
- SOCKS-перенаправление библиотеки терялось на хвосте ответа; помогает собственный SOCKS5 с
  half-close и сбросом буфера перед закрытием. Проверять на трафике настоящего браузера.
- Переподключение: одна попытка за раз, поколение сессии, поздний клиент закрывается; проверка
  живости каждые 10 с; ключ хоста не принимается автоматически.
- «Второй вход» для проверки SSH и файрвола — новое соединение с теми же данными при живой первой
  сессии.
- Стенд в WSL иногда сбрасывает соединение сразу после обрыва: повторять подключение стенда, не
  ослаблять проверки.

**Команды и разбор вывода**
- Имена файлов: `find -printf` с NUL-разделителем; любые символы (пробелы, кавычки, `\n`,
  Unicode); ссылки на каталоги открываются как каталоги.
- Процессы: полный список (`ps -eo pid,user:32,…`), не усечённые имена пользователей.
- Службы: объединять `systemctl list-units` и `list-unit-files` (остановленные и выключенные тоже).
- Журнал: обычный пользователь видит чужое только через `sudo -n`; ошибка чтения — ошибка.
- Порты: `ss`, запасной `netstat`, отсутствие обоих — явная ошибка; TCP и UDP; IPv6.
- Окна сети и журналов в прототипе глотали ошибки и показывали пустой список; а вкладка файрвола
  падала на приведении типов, когда UFW не установлен.

**Подготовка сервера**
- `systemctl enable --now fail2ban` возвращается раньше, чем готов сокет сервера: перед
  `fail2ban-client reload` ждать `fail2ban-client ping`.
- На свежем сервере без `iproute2` проверка не видит слушающих портов; список портов для файрвола
  читать заново **после** установки пакетов, иначе файрвол отрежет работающие сервисы.
- Откат SSH и файрвола при неудачном втором входе проверялся только на настоящем сервере.
- Шаг SSH недоступен при входе по паролю; без `sudo -n` ничего не меняется.

**Файлы и передача**
- Запись: временный файл, проверка размера, замена с сохранением прав; новые файлы пишутся на месте.
- Передача: временное имя, сверка байтов принятых и записанных, публикация жёсткой ссылкой (`ln`)
  без перезаписи; отмена не должна превращаться в ошибку закрытия файла; чужие временные файлы не
  удаляются; остаток не затирается молча.
- Испытания: обрыв SSH посреди передачи, отмена, конфликт имён, две одновременные загрузки одного
  имени, смена сессии — итоговый файл не появляется, чужой файл не меняется.
- Автоматическая докачка (Resume) не добавлять, пока остаток нельзя отличить от чужого файла по
  контрольной сумме или размеру на обеих сторонах.

**Терминал и tmux**
- Параметры tmux задавать для своей сессии, не глобально; имена сессий экранировать; без tmux —
  явная ошибка, а не зависание; код выхода отличает «оболочка завершилась» от «связь потеряна».

**Почта**
- Нельзя подменять отправку записью в mbox. Нулевой код выхода `sendmail`/`mail` означает «команда
  приняла», не «доставлено». Получатель не может начинаться с дефиса; перевод строки в теме и
  адресе запрещён (инъекция заголовков). Неизвестный итог после обрыва не повторять.

**Сборка**
- Библиотека защищённого хранилища, требующая компонент Visual Studio (ATL), ломала простую сборку
  под Windows: проверять зависимости сборки заранее.
