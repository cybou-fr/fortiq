# Правила разработки FORTIQ

## Git workflow: только main

- **Единственная рабочая ветка — `main`.** Все изменения кода, тестов и документации
  коммитить непосредственно в `main`, без создания feature-, fix- или иных веток.
- Не создавать pull requests для обычной разработки и не предлагать PR как
  способ передачи результата; фиксировать изменения обычными коммитами в `main`.
- Перед записью читать актуальную версию файла в `main`; при конфликте
  перечитать её и согласовать изменения, не перезаписывая чужую работу.
- Каждый законченный срез сопровождать тестами и документацией; если проверка
  невозможна, честно указывать это, не выдавая код за проверенный.
- Исключения из этого правила — только после отдельного прямого указания владельца.

## Стек и состояние проекта

- Клиент разрабатывается на **C++20 с Qt 6.12** (CMake). Прежняя реализация на Flutter/Dart
  удалена 18.10.2026; её последнее состояние — git-тег `flutter-final`. Flutter и Dart больше не
  используются, новый код на них не пишется.
- Текущее состояние — инженерный прототип **R0.1** (21.10.2026): QML-интерфейс, закрепление
  отпечатка ключа хоста (libssh2), вход по паролю, просмотр каталогов по SFTP только для чтения,
  тесты удалённых путей. Сборки для Windows/Android и проверки на устройствах ещё не выполнялись.
  Фактический статус — [QT_MIGRATION](docs/QT_MIGRATION.md) и [README](README.md); остальное в
  документации — цели и контракты, а не готовые функции.
- Платформы в приоритете: Windows и Android arm64. Следующие шаги: проверенные сборки, вход по
  ключу и защита учётных данных, постоянная сессия, затем Files/Editor от начала до конца.
- Открытые технические решения перечислены в `docs/ARCHITECTURE.md`.

## Product direction: универсальный desktop

- FORTIQ — универсальный удалённый Linux desktop, а не DevOps dashboard
  и не продукт исключительно для разработчиков.
- Приоритеты: Desktop UX → Files/Transfers → Documents → Mail →
  Browser/Media → опциональная AI-интеграция. Системные инструменты сохранять.
- Новые Docker/Podman/DevOps-модули не считать обязательным следующим этапом.
- Каждый повседневный инструмент обязан работать без AI. AI только помогает
  на основе явно выбранного контекста; не исполняет команды самостоятельно.
- Источник продуктовых приоритетов: `docs/PRODUCT_SCOPE.md`.

## Существующие инструменты прежде собственной реализации

- FORTIQ — графический интерфейс к существующим Linux-инструментам.
  Сначала изучить зрелые утилиты, их CLI, форматы вывода, лицензии и доступность
  на Debian/Ubuntu. Выбирать инструмент под законченный пользовательский сценарий.
- Писать адаптер, интерфейс и обработку результата, а не собственный аналог
  почтового клиента, дисковой утилиты или другой уже решённой серверной задачи.
- Не создавать собственные серверные агенты, демоны или CLI вроде `fortiq-mail`,
  если задача решается существующим инструментом. Если подходящего инструмента
  нет, сначала представить ограничения и обоснование владельцу проекта.
- Не объявлять конкретную утилиту выбранной до проверки её возможностей.

## Сетевой маршрут

- Встроенные приложения управляют инструментами на выбранном Linux-сервере
  через SSH. Клиент FORTIQ не подключается напрямую к IMAP/SMTP, почтовым API
  или другим внешним сервисам приложений. Браузер использует серверный SSH-прокси.
- Единственное согласованное прямое внешнее подключение клиента — покупка,
  активация и проверка лицензии FORTIQ, управление подпиской.
- Для почты использовать существующий консольный клиент на сервере. Его
  аккаунты, аутентификация, IMAP/SMTP и почтовая синхронизация находятся на сервере;
  FORTIQ предоставляет GUI и выполняет его команды по SSH.
- Локальные черновики/кеш не дают права вводить прямой сетевой fallback.
  При разрыве SSH показать недоступность источника и сохранить изменения.
- Системную почту и остальные существующие приложения сохранять.

## AI: согласованное исключение только для Linux

- Разрешён **опциональный** CLI **`ai`** над готовым **llama.cpp**
  (`llama-cli` / проверенный `llama cli`), с GGUF на CPU Linux.
  Собственный inference engine, отдельный AI-сервер, порт и daemon
  не разрабатывать. FORTIQ использует только SSH.
- Модель запускается по запросу и завершается; до включения проверить
  доступную RAM, CPU и реальную скорость. На слабых VPS AI выключен,
  остальные APP не зависят от него. Модель ещё не выбрана.
- **Серверный cache-first:** кешировать только подходящий точный
  вопрос + контекст + модель/параметры; ответ вернуть без загрузки GGUF.
  TTL, quota, изоляция Linux-пользователя, атомарная запись, clear.
  Кешированные ответы явно помечать и не принимать за живые проверки.
  Чувствительный контент не сохранять без явного согласия.
- AI объясняет и советует, ничего не меняет и не выполняет предложенные
  команды. Установка через SSH с согласия; никаких внешних AI API
  и скрытой отправки логов.
- Источник требований: `docs/AI_CLI.md`, статус R2/P2, не реализовано.
  Не рекламировать готовый AI.

## Проверка и документация

- Проверять версию и контракт CLI, ошибки, права, имена с Unicode/пробелами,
  обрыв SSH и привязку результата к правильному серверу.
- Секреты не передавать через аргументы команд и не выводить в логи.
- Согласовывать изменения с README, PRODUCT_SCOPE, ARCHITECTURE и
  DEVELOPMENT_MATRIX. Целевые возможности не описывать как реализованные.
- Приватный репозиторий и исходники не предлагать покупателям; пользователь
  получает готовое приложение, без самостоятельной сборки.
